## Что сделать

Playwright-спека `e2e/operator-next/walk.spec.ts` (+ свой конфиг `playwright.opnext.config.ts`, baseURL `http://localhost:3200`, viewport 375×812, touch). Один полный цикл смены машиниста на `/operator/next`:
допуск → приёмка установки → предсменный осмотр → начало смены → работа (сваи; паспорт с тремя залогами) → простой → завершение работы → осмотр после смены → закрытие смены.
На каждом шаге — скриншот в `docs/operator-next/browser/NN-шаг.png` и проверки:

1. **Размеры:** у каждой кнопки и поля видимого экрана `getBoundingClientRect` ≥ 44×44 px (список нарушителей с селектором и размером); нет горизонтальной прокрутки (`scrollWidth <= clientWidth`).
2. **Шрифт:** вычисленный `font-size` основного текста и подписей полей ≥ 16 px (список нарушителей).
3. **Черновики:** посреди паспорта (3 залога введены) — `page.reload()`; значения на месте.
4. **Нет связи:** `context.setOffline(true)` → записать сваи → запись в очереди, видна отметка «не отправлено» → `setOffline(false)` → ушла, **ровно одна** запись на сервере (сверь SELECT-ом — только чтение: `docker exec pilingtrack-postgres psql -U postgres -d pilingtrack_test -Atc "SELECT ..."`).
5. **Двойное нажатие** главной кнопки шага — одна команда (по сети или по базе).
6. **Сервер** (то, что в §9.4 проверено «только по контракту»): повтор команды с тем же `clientCommandId` не создаёт вторую запись; ночная смена (`NIGHT`) принимается; чек-лист `EO_AFTER` реально приходит в конце смены.
7. **Консоль браузера:** ни одной ошибки (`page.on('console')`/`pageerror` — список).

Если шаг невозможен (нет назначения на установку, чек-листа, прав) — пометь ЗАБЛОКИРОВАНО с точной причиной и иди дальше. ЗАБЛОКИРОВАНО ≠ пройдено.
