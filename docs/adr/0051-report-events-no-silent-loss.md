# ADR-0051: События отчёта не теряются молча (J1, J2, J4, J5, J6)

- Status: Принят (Hermes, 07.10.2026), проверен Claude
- Date: 2026-10-07
- Decision owners: серверный контур отчётов и аналитики
- Связано: ADR-0002 (outbox), ADR-0006 (консолидация шины событий), ADR-0043 (audit hash chain); отчёты W5, W3, W12, W35, W49
- Коммиты: `d1c52f06` (J1/J2), `5d4a1b20` (J4), `5b661046` (J6), `dc764bc2` (J5), `da068fdd` (W45)

## Контекст

События отчёта могли исчезнуть тихо — без ретрая, без dead-letter и без сигнала на экранах.

- W5: обработчик проекции при неразрешённых `siteId/userId/tenantId` писал `logger.warn` и делал `return`. Выход из обработчика — «успех» для outbox: строка клеймилась `published=true` (dispatch-then-claim), попытки не росли, DLQ пустела. Событие не обрабатывалось уже никогда.
- W5: гонка на старте воркера. Событие, попавшее в окно до `registerAllEventHandlers()`, не находило подписчиков, но всё равно клеймилось доставленным.
- W5: `ReportAnalytics.status` обновляли только `ReportCreated` (→`draft`) и `ReportSubmitted` (→`submitted`). Потерянный `ReportSubmitted` оставлял строку в `draft` навсегда — живой пример `RM-3190cede-2026-09-28` (`Report=submitted`, аналитика `draft`).
- W12: строки аналитики, оставшиеся без отчёта («сироты», 5 шт.), и отчёты без строки аналитики; `ensureReport` заводит отчёт вообще без события outbox.
- W35 и W3: читатели брали итог из проекции, а фолбэк на источник включали только при «строки нет», не при «строка устарела/занулена». Карточка установки показывала «0 свай» при живых `PileWork` (симптом D5).

Класс один: витрина молча расходится с источником, а расхождение ничем не видно.

## Решение

1. Событие без нужных данных — ошибка, а не пропуск (J1). `handleReportForAnalytics` бросает `Error` с типом события, `aggregateId` и перечнем недостающего (`siteId/userId/tenantId`). Outbox повторяет, после исчерпания попыток (`MAX_RETRIES=5`) отправляет событие в dead-letter.
2. Событие отчёта без подписчика — ошибка (J2). `emitDomainEvent` бросает, если реестр пуст. Событие, пришедшее до регистрации обработчиков, уходит на повтор, а не помечается доставленным.
3. Статус проекции берётся из источника (J4). Обработчик аналитики читает `Report.status` напрямую (источник истины, как в `rebuild.ts`) и пишет его в `ReportAnalytics.status`; на `ReportUpdated` добавлена подписка. Данные события для статуса не используются. Заодно закрыт прежний фолбэк недостающих id.
4. Карточка считает из источника (J6). `totalsForReport` берёт итоги из строк `PileWork/ReportDowntime` (`sourceTotals`), если у отчёта есть хотя бы одна строка источника; проекция используется только при полном отсутствии строк источника.
5. Расхождение становится видно (J5). `countReportAnalyticsStatusMismatch(tenantId)` одним `$queryRaw` считает расхождения статусов и отчёты без строки аналитики; метрики `report_analytics_status_mismatch_total` и `report_analytics_missing_total` собираются по организациям через `forEachTenant` (RLS fail-closed), сбой сверки гасится локально.
6. Удалённый отчёт не плодит сироту (W45). `ReportUpdated` для отсутствующего в `Report` отчёта не пишет строку аналитики и не бросает (удаление — нормальный конец; бросок увёл бы событие в DLQ без шанса на успех), только `logger.info`.

### Типы событий без подписчиков ПО ЗАМЫСЛУ (5 типов)

Набор `EVENT_TYPES_WITHOUT_SUBSCRIBERS` в `domain-events.ts`:

- `PileWorkAdded`, `PileWorkRemoved`, `DrillingAdded`, `DrillingRemoved`, `DowntimeRemoved`.

Почему: это события уровня строки отчёта. `SiteDailySummary` пересобирается из строки `Report` на `ReportSubmitted`/`ReportUpdated`, а CQRS-проекции читают те же события отдельным потребителем outbox (`projectOutboxEvents` → projection-worker). Подписчика на шине у них нет намеренно — событие не теряется, у него другой маршрут. Для этих типов поведение прежнее (`warn` и выход). События не отчётов (crew/site/equipment/readiness/…) не затрагиваются: `normalizeReportDomainEventType` для них даёт `null`, и шина отчётов их не обслуживает.

## Последствия

- Больше событий в dead-letter при ошибках данных: событие без подписчика или с неразрешимыми id теперь доходит до DLQ, а не исчезает. Повтор такого события, если причина не исчезла, снова упадёт — помогает только «Отбросить» (см. W49).
- Старые события не переотправляются. Правки действуют только на новые обработки outbox; уже помеченные `published=true` события не переобрабатываются.
- Перестройка проекций не требуется. Статус и итоги после правок читаются из источника, старые строки проекции догоняются обычной перестройкой при необходимости; отдельной миграции данных нет.

## Что НЕ решено

- J3 — экран машиниста: `ensureReport` (`operator-mobile/**`) заводит отчёт без события outbox. Отдано Codex.
- J8 — индекс `PileWork`.
- J9 — пометка «устарело» у деактивированных установок.
