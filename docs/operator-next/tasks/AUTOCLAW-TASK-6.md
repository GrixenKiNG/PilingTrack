## A. Черновики — одна простая модель (закрывает Д1–Д5 и пункт 2)

1. **Источник правды — память оболочки**, для всех форм, включая **паспорт сваи со всеми залогами**: паспорт хранится в состоянии оболочки как объект (номер, марка, все строки залогов, отказ, отметки), `PilePassportForm` получает его значениями и отдаёт изменения обратно. **Удали `passport-persist.tsx` и восстановление через DOM/клики** целиком. Если общий `PilePassportForm` (вне твоей зоны, менять нельзя) не умеет принимать начальное значение — сделай свою обёртку-форму паспорта в `operator-next/` с теми же полями и той же командой `PILE_PASSPORT`, не трогая общий компонент.
2. **Принадлежность черновика — пара `{userId, shiftId}`** во всём: отображение, асинхронные обновления, сохранение. Смена пользователя в уже открытой оболочке (без перезагрузки) — черновики прежнего пользователя не показываются, не сохраняются под новым и не отправляются. Пока пользователь неизвестен — пользовательские черновики не читаются и не пишутся (никакого общего `anon`).
3. **localStorage — только копия памяти**: запись после изменения, чтение при старте смены. Каждая операция возвращает результат; **ошибка чтения ≠ «пусто»** — при ошибке чтения ничего не записывать поверх. Любой отказ записи или очистки → статус «Черновик не сохраняется при перезагрузке» на экране той формы, где человек работает (включая паспорт). Очистка подтверждённого черновика, которая не удалась, — тоже видимая ошибка, а не молчание.

Тесты (каждый должен падать без исправления, откат — в журнал): смена пользователя А→Б без размонтирования; отказ записи после успешного старта; отказ чтения при существующем документе — документ не изменился; паспорт с тремя залогами переживает обходной экран и при отключённом localStorage; отправленный паспорт после восстановления содержит все три залога.

## B. Доказать единый цикл (пп. 3–5 ревью)

4. Для происшествия, поправки и записи в очередь — **второе нажатие во время отправки** не шлёт вторую команду. Сценарий «`reload` завершился сразу/с ошибкой → человек ввёл новое → позднее продолжение прежней отправки не стёрло новое» — для выработки и паспорта.
5. Закрытие смены: заметку **меняют во время задержанного `flush`** — уходит новая; считать число вызовов `flush` при двух нажатиях — один.
6. Гонка установок: вызвать обработчик выбора напрямую (или оба выбора до блокировки), зафиксировать исходное число запросов, два новых запроса с раздельно управляемыми ответами в обратном порядке; удаление `requestSeq` должно ломать итог.
