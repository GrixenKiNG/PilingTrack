# Задание для AutoClaw №2: доработка `/operator/next` по независимому ревью

Рабочая папка и все запреты — те же, что в `AUTOCLAW-TASK.md` раздел 0 (ветка `autoclaw/operator-next`, писать только в `src/components/piling/operator-next/**`, `src/app/operator/next/**`, `docs/operator-next/**`; ничего не пушить и не сливать). Проверь ветку перед началом.

Твою работу (этапы 1–7) проверил независимый ревьюер (GPT-6/Codex) — полный текст: `docs/operator-next/input/codex-review-1.md`. Вердикт «доработать». Три находки уже подтверждены вручную по коду (№2, №5, №6). Исправь ВСЕ девять, каждую — тестом, который без исправления падает.

1. **[критично]** Ошибка перечитывания (`reload` из `useOfflineQueue`) заменяет рабочий экран полноэкранной ошибкой и уничтожает открытую форму. Полноэкранная ошибка — только при ПЕРВОЙ загрузке; дальше — полоса ошибки поверх рабочего экрана, форма живёт.
2. **[критично]** Черновики теряются при переходах: вкладка «Техника» и обратно, «Назад к смене» → снова «Записать сваи» (`open()` вызывает `clear()`), уход в чек-лист ТБ, заметка закрытия при смене вкладок. Храни черновики выше сменяемых экранов (по смене и виду формы), очищай только после подтверждённой записи или явного «Очистить» человеком.
3. **[важно]** Успех отправки стирает то, что человек успел изменить после нажатия. Блокируй поля отправляемой формы до ответа (или очищай только если черновик не менялся).
4. **[важно]** Гонка загрузок при смене установки: применяй только ответ последнего запроса; кнопка «Принять установку» доступна, только когда загружена именно выбранная установка; `equipmentId` в команде = показанной установке.
5. **[важно]** `checklist-run.tsx`: «Отменить» после «Весь раздел — норма» снова ставит OK — сделай настоящую отмену (вернуть прежние ответы). Массовая «норма» не должна перезаписывать уже выбранные FAULT/REMARK — только неотмеченные пункты.
6. **[важно]** `work.tsx`: комментарий к бурению не передаётся в `DRILLING`. Посмотри тип `ProductionEntryInput` в `operator-mobile/api.ts`: если `comment` у DRILLING допустим — передавай; если нет — убери поле из формы бурения.
7. **[важно]** Ошибка `acknowledge-briefing` не видна на экране инструктажа — покажи её там же с кнопкой «Повторить».
8. **[важно]** Тупик: фаза CLOSING, а чек-листа `EO_AFTER` нет — кнопка осмотра ничего не открывает. Нужны объяснение, рабочая кнопка «Обновить» и путь назад.
9. **[важно]** `operator-next.css`: кнопки ответов осмотра 48px → минимум 56px; шрифт 0.9375rem (15px) → не меньше 18px. Проверь и остальные размеры по правилу 11.

Плюс «неподтверждённые гарантии» из конца ревью — закрой тестами, где это возможно на клиенте:
- двойное нажатие любой кнопки команды шлёт ОДНУ команду (синхронная блокировка повторного входа в `run`);
- ключ команды обновляется только у той команды, которая прошла, а не у всех;
- «принято, но перечитывание упало» — на экране «Записано…», а не «Нет связи», и форма очищена ровно один раз;
- закрытие смены перечитывает очередь непосредственно перед `close-shift`.
