# `/operator/next` — проектирование шестой версии экрана машиниста

Дата: 2026-09-27. Ветка: `autoclaw/operator-next`. Рабочая папка: `D:\PillingR\wt-autoclaw`.

Документ отвечает на три вопроса: как устроен поток смены от входа до «Смена закрыта»,
что именно взято из каждой из пяти действующих версий и почему, и какие находки
аудитов (`docs/operator-next/input/40-operator-novice.md`,
`docs/operator-next/input/43-offline-queue-edges.md`) эта версия закрывает.

---

## 1. Поток экранов смены

Фазу смены считает сервер (`OperatorMobileState.phase`) и отдаёт телефону готовой.
Телефон не выводит фазу сам: закрыл приложение на осмотре — вернулся на осмотр.
Экран лишь показывает то, что уже записано, и предлагает следующий шаг.

```
Вход /operator/next
  │
  ├─ нет ответа сервера ─────────► «Нет связи» + «Повторить» + плашка очереди
  ├─ 403 (не машинист) ──────────► «Рабочее место машиниста» (роль)
  ├─ нет данных ─────────────────► «Загрузка смены»
  │
  ▼
IDENTITY  «Допуск к смене»
  карточка «Следующее действие» + список шагов допуска:
  1. СИЗ                    → обходной экран PPE
  2. Ознакомление с инструкцией → обходной экран BRIEFING
  3. Проверка знаний по ОТ  → обходной экран KNOWLEDGE
  4. Подпись (ставится вместе с ознакомлением)
  5. Допуск к смене (решение сервера)
  │  шаг 4–5 закрывает сервер, экран только показывает факт
  ▼
ADMISSION «Принять установку»
  • выбор установки (только выбор; приёмки по тапу нет)
  • ТИП СМЕНЫ: «Дневная 07:00–19:00» / «Ночная 19:00–07:00» — явно, до приёмки
  • погода и условия площадки, сводка по объекту
  • ЯВНАЯ кнопка «Принять установку» (команда accept-equipment с выбранным shiftType)
  ▼
PRESHIFT_INSPECTION → STARTUP(EO_BEFORE) → SITE_READY
  чек-лист с крупным счётчиком «Осталось отметить: N»
  ответы: Норма / Замечание / Неисправность
  ▼
WORK «Работа»
  карточка «Следующее действие»
  быстрая запись свай: крупные кнопки марки, количество, метраж считается сам
  бурение, простой, паспорт сваи, поправки, журнал записей смены
  происшествие и неисправность — отдельными действиями
  • каждая запись уходит через общий контур api.ts: сервер принял ИЛИ запись в очереди
  ▼
CLOSING «Отчёт и отправка»
  • осмотр и обслуживание после работы (ЕО_AFTER) — условие закрытия
  • итоги смены
  • НЕОТПРАВЛЕННЫЕ ЗАПИСИ: число и кнопка «Отправить записи с телефона»
  • пока очередь не пуста — «Закрыть смену и отправить отчёт» заблокирована
    с видимой причиной
  ▼
CLOSED «Смена закрыта»
  номер отчёта, время принятия, итоги; вкладки остаются доступными
```

Передачи смены сменщику в потоке нет и не будет: у «Ориона» сменщиков нет,
установку принимает тот же машинист, а `close-shift` сразу отправляет отчёт диспетчеру.

## 2. Что взято из какой версии и почему

| Источник | Что берём | Почему именно это |
|---|---|---|
| `/operator` (основа) | поток фаз и порядок шагов, `api.ts` (`fetchState`/`sendCommand`/`newCommandId`), очередь `useOfflineQueue` + `OfflineQueueBanner`, экраны допуска (СИЗ, инструктаж, знания), чек-листы, журнал с поправками, происшествия со снимками, экран «Смена закрыта» с номером отчёта | Единственная версия без P0-находок; полный цикл смены уже собран и включён на бой 12.09.2026 |
| v7 | явная приёмка установки отдельной кнопкой, видимый выбор дня/ночи, название текущего этапа в шапке, **крупные кнопки марки** | Приёмка явной кнопкой и видимый день/ночь — прямые находки P0 у v2. **Автовыбор первой марки из v7 НЕ берём** (находка №39) |
| v10 | карточка «Следующее действие», отдельный экран «Отчёт и отправка» с понятным состоянием записей | Даёт новичку ответ «что нажать сейчас» без чтения всего экрана |
| v5 | счётчик «Осталось отметить: N» в осмотре | Видно, сколько осталось, не листая список |
| v2 | ничего обязательного | Лист быстрого ввода — кандидат на полевую проверку; передача смены не переносится (решение владельца 27.09.2026) |

Единые слова (обязательные к употреблению во всех экранах):
**«Смена», «Принять установку», «Записать сваи», «Неисправность», «Происшествие»,
«Закрыть смену и отправить отчёт».**

## 4. Как достигнуты правила раздела 4 задания

1. **Передачи смены нет.** Во всём коде нового модуля отсутствует `submit-report`/передача;
   закрытие — только `close-shift` из экрана «Отчёт и отправка».
2. **Запрет закрытия с неотправленным.** `report-send.tsx` получает список записей
   устройства, показывает «Не отправлено на сервер: N» и блокирует закрытие.
3. **Нет автовыбранных значений.** Все формы выработки стартуют с пустого выбора;
   кнопка записи погашена с причиной.
4. **Тип смены виден и выбирается явно.** `shift-start.tsx` показывает оба варианта с окнами.
5. **Приёмка — отдельная кнопка.** `shift-start.tsx`.
6. **Введённое не стирается.** Общий `run()`: очистка формы только по `true`;
   `QueuedOffline` считается успехом.
7. **Нет тупиков.** `ReasonNote` у каждой заблокированной кнопки; экраны ошибки ведут назад/вперёд.
8. **Ошибки по-русски.** `words.ts#humanError` переводит технические ответы сервера на русский.
9. **Чужие записи видны, но не отправляются.** Плашка очереди + фильтр по владельцу.
10. **Единые слова.** `words.ts` и все новые экраны.
11. **Крупно и контрастно.** `Screen` из `operator-mobile/ui` несёт `.operator-screen`,
    который поднимает шкалу шрифта (базовый текст 18 px), кнопки действий — минимум 56 px
    (`.onx-action`), зоны нажатия — минимум 48 px, светлая тема, только системные токены
    продукта с контрастом WCAG AA.

## 5. Границы решения

- Серверный код (`src/modules/**`, `src/app/api/**`), схема БД, версии v2/v5/v7/v10 и
  общие компоненты `operator-mobile/**` не изменяются — только импортируются.
- Новые npm-пакеты не добавляются. Тесты — существующие `vitest` + Testing Library.
- Если чего-то нет на сервере, экран честно говорит «пока недоступно», а не выдумывает
  поведение; такие места перечислены в `REPORT.md`.

## 6. Круг 3: отложенный осмотр и черновики (ревью №2)

- **Фазовый осмотр можно отложить** («Отложить осмотр»): ответы сохраняются, человек возвращается
  к смене, вкладки доступны; карточка «Следующее действие» ведёт обратно к осмотру, «Допуск к работе
  не выдан» виден явно. Без связи показывается: «Осмотр сохранён на устройстве, отправить можно,
  когда появится связь». Уход — только явным действием с объяснением, «незаметно» уйти нельзя.
- **Ответы осмотра** живут в оболочке по этапу; **форма паспорта** не размонтируется при
  «Назад к смене» и переключении вкладок (ключ — смена). Смена сменилась — форма начинается заново.
- Осталось ограничением: паспорт не переживает уход в обходной осмотр (детур); серверная очередь
  для осмотра не делалась (вне зоны правок).
