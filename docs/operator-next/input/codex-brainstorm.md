Предоставленные **10 091 строка — общий объём**, а не сопоставимые размеры пяти независимых реализаций. По ним нельзя вычислить стоимость каждой версии. Главная нагрузка поддержки — необходимость проверять одни и те же правила смены в пяти интерфейсах.

Что конкретно собрать в базе:

- **Из `/operator` оставить:** допуск, секционный осмотр с замерами, учёт свай/бурения/простоя, журнал с поправками, происшествия со снимками, закрытие с квитанцией.
- **Из v7 взять:** явную приёмку с видимым выбором дня/ночи, название текущего этапа и крупные кнопки марки. **Без автоматического выбора первой марки.** Выбор типа смены уже есть в базе — перенести подачу, не создавать вторую логику.
- **Из v10 взять:** карточку «Следующее действие» и отдельный экран «Отчёт и отправка» с понятным состоянием записей.
- **Из v5 взять:** счётчик «Осталось отметить: N» в осмотре; из v5/v7 — предупреждение перед закрытием, сверив его с реальными правилами исправлений.
- **Из v2 пока ничего обязательного:** лист быстрого ввода оставить кандидатом на полевую проверку. Передачу смены не переносить: владелец уже решил её убрать.

Единые названия: «Смена», «Принять установку», «Записать сваи», «Неисправность», «Происшествие», «Закрыть смену и отправить отчёт». У каждой недоступной кнопки — причина и понятный следующий шаг.

**2. Как перейти, сохранив работу людей**

Абсолютного отсутствия риска обещать нельзя. Практический принцип: **смена сохраняет свой идентификатор, запись — автора и идентификатор команды; смена интерфейса не создаёт их заново.**

**Этап А — выяснить, чем реально пользуются.** Составить список десяти машинистов и планшетов: версия, открытая смена, неотправленные записи, срок отсутствия связи. Проверить хранилища очередей всех версий: общие ли они, переживают ли обновление и смену пользователя. Наличие файла `offline-queue.ts` этого не доказывает.

Пока варианты используются, исправить в них найденные P0 и тупики потери связи. Это защита действующих пользователей, независимая от выбора дизайна.

**Этап Б — обеспечить совместимость данных до переключения.**

- Одна реализация очереди и правил смены для итогового интерфейса; старые форматы читаются переходным кодом.
- Каждая команда сохраняет исходные компанию, машиниста, установку, смену, время события и постоянный идентификатор. Повтор отправки не создаёт дубль.
- Локальное сохранение завершается **до** сообщения «Сохранено на планшете». «Принято сервером» показывается только после подтверждения конкретной записи.
- Перенос очереди — копирование с проверкой состава; исходник сохраняется до подтверждённой доставки. Два отправителя не должны одновременно независимо обрабатывать одну очередь.
- Смена пользователя не очищает очередь и не переписывает её автора. Записи Иванова нельзя отправлять как записи Петрова. Для ожидающих отправки записей нужна серверная проверка исходного авторства.

**Этап В — проверить на разрешённом локальном стенде.** Обязательные сценарии:

1. Записать без связи, закрыть приложение, открыть снова — запись сохранилась.
2. Сервер принял запись, ответ потерялся — повтор не создал дубль.
3. На общем планшете вошёл другой машинист — автор старых записей сохранился.
4. Обновить интерфейс с открытой сменой и очередью — продолжилась та же смена.
5. Доставить запись после автозакрытия либо архивации марки — данные не исчезли, исход понятен.
6. Вернуть старый интерфейс после работы в новом — очередь остаётся доступной.

**Этап Г — пилот на одной установке.** Два человека: новичок и опытный машинист. Пройти несколько полных смен, включая обрыв связи. Проверить фактические нажатия в перчатках и на солнце. Размер шрифта прототипов не менять вопреки решению владельца.

Переходить дальше, когда нет потерянных, чужих и повторных записей; итоги совпадают; оба человека самостоятельно записывают работу, исправляют ошибку и закрывают смену.

**Этап Д — переключать по установкам между сменами.** На общем планшете это понятнее, чем разный интерфейс у соседних пользователей.

- Незакрытую смену по умолчанию заканчивают в прежнем интерфейсе. Принудительно закрывать её ради обновления нельзя.
- Если перейти посреди смены необходимо — новая оболочка открывает тот же `shiftId`, после проверки совместимости.
- Непустая очередь остаётся доступной и видимой. Нельзя требовать очистить данные браузера или переустановить приложение.
- Устройство, долго бывшее без связи, проходит проверку совместимости при возвращении; старую ссылку нельзя безусловно перенаправлять на новый экран.

**Автозакрытие сохранить по решению владельца:** дневная смена 07–19 закрывается в 00:00, ночная 19–07 — в 12:00. Оно не означает, что все планшеты уже отправили записи. Позднюю доставку нужно обрабатывать отдельно: сохранить исходную запись и показать результат принятия либо необходимость разбора. Не переносить её молча в следующую смену. Работу по архивной марке, выполненную до архивации, принимать согласно решению владельца.

**Откат:** вернуть прежний интерфейс переключателем для установки, сохранив серверные данные и очередь. Поэтому на время перехода API и форматы хранения должны оставаться совместимыми. Восстановление старой базы — плохой способ отката интерфейса: оно уничтожит новые записи.

После успешного перехода убрать альтернативы из обычной навигации **по решению владельца**. Удаление исходников отложить до отдельного разрешения и обработки вернувшихся устройств.

**3. Пять улучшений на ближайший месяц**

Оценки предварительные: человеко-дни одного разработчика, включая целевые проверки. Отсутствующая серверная поддержка может увеличить сроки.

| Приоритет | Улучшение | Польза именно «Ориону» | Стоимость |
|---|---|---|---|
| **1** | Надёжная очередь: сохранение до подтверждения, защита от дублей, восстановление после перезапуска, видимые ошибки отправки | Сохраняет выработку при обычных для площадки обрывах связи | **4–6 дней**, высокая |
| **2** | Одна понятная последовательность смены: следующий шаг, единые слова, причины блокировок, исправление P0 действующих версий | Новичок реже звонит диспетчеру и реже подтверждает не то действие | **3–5 дней**, средняя |
| **3** | Общий планшет: постоянно видимые имя и установка, явная смена пользователя, сохранение авторства очереди | Предотвращает чужие смены и записи при передаче устройства | **2–3 дня**, средняя |
| **4** | Быстрая запись свай: крупный явный выбор марки, количество, рассчитанный метраж, понятная поправка | Экономит время на многократно повторяемом действии; снижает ошибки марки | **2–3 дня**, средняя |
| **5** | Один список для диспетчера: незакрытые смены, черновики с пометкой, давно не выходившие на связь устройства, проблемные записи | Позволяет проверить десять человек за несколько минут и адресно связаться с нужным | **3–4 дня**, средняя |

Итого **14–21 человеко-день**, плюс время людей на полевой пилот. Для одного разработчика месяц плотный: сначала пункты 1–3, затем 4–5. Не включать в этот месяц полный переписанный модуль.

Для диспетчерского списка важная граница: сервер не знает точного содержимого отключённого планшета. Показывать «последний известный статус» и время связи, а не обещать актуальное число неотправленных записей.
