# Модуль оператора — реализация по визуализации

Артефакт воспроизводит приложенную визуализацию (5 баннеров) как рабочий прототип модуля оператора
PilingTrack: мобильные экраны в каркасе телефона, плюс презентационный борд «один-в-один» с исходниками.

## Где лежит

> **Важно про git.** `public/prototypes/` и `/output/` в этом проекте в `.gitignore` (локальные макеты и
> результаты прогонов). Поэтому долговечная копия поставки лежит в отслеживаемой папке `docs/operator-module/` —
> именно её стоит коммитить. Остальные копии — рабочие, локальные.

| Что | Путь (durable, в git) | Рабочая копия |
|---|---|---|
| Модуль (плеер + борд + стили) | `docs/operator-module/site/` | `public/prototypes/operator-module/` |
| Отчёт | `docs/operator-module/operator-module-report.html` | `output/operator-module/` |
| Скриншоты рендера | `docs/operator-module/screens/` | `output/operator-module/` |
| Сверка с оригиналом | `output/operator-module/verify/compare.html` (локально, с исходниками) | — |
| Проверки | `output/operator-module/qa/`, `…/interaction/`, `…/app/` | — |

**Источник — `docs/operator-module/site/`. Правки вносить только туда.** Папка
`public/prototypes/operator-module/` — одноразовая рабочая копия: она нужна лишь затем, чтобы Next.js
раздавал макет на `localhost`, в git её нет и на боевом сервере её не будет. Восстановить/обновить копию:

```bash
cp -r docs/operator-module/site/. public/prototypes/operator-module/
```

Открыть при запущенном `npm run dev`:
`http://localhost:3000/prototypes/operator-module/index.html` (плеер) и
`…/board.html` (борд).

> **Почему нет короткого адреса `/operator/module`.** Он был, и его убрали: страница-редирект — обычный
> файл, который попадает в git, а макет, на который она вела, — нет. На чужой машине и на проде такой
> маршрут отдавал бы 404. Ссылка в пустоту хуже, чем адрес на один сегмент длиннее.

## Как запускать и что менять

- **Запуск приложения:** `npm run dev` (Next.js), макет раздаётся как статика из `public/`.
- **Статический просмотр без сборки:** открыть `site/index.html` или `site/board.html` файлом (самодостаточно).
- **Контент экранов:** `screens-tb.js` (баннер ТБ) и `screens-1..4.js` (подэкраны 1/4…4/4).
- **Общие элементы каркаса:** `common.js` (статус-бар, нав-бар, вкладки, кнопка инцидента).
- **Иконки:** `icons.js` (встроенные SVG).
- **Стили:** `operator-module.css` (дизайн-система и компоненты), `extra.css` (специфика экранов), `board.css` (борд).
- **Порядок/навигация плеера:** `app.js`.

Стили и компоненты: `public/prototypes/operator-module/operator-module.css` (дизайн-система),
`extra.css` (экраны), `board.css` (борд), скрипты `icons.js`, `common.js`, `screens-*.js`, `app.js`.

## Ограничения и допущения

- Прототип самодостаточный и не подключён к живому API: данные — демонстрационные, как в визуализации.
- Живой модуль `/operator` (`OperatorMobileApp`) и прототипы `/operator/v2`, `/operator/v5` не изменялись,
  чтобы не сломать производственный контур и тесты.
- Иконки — встроенные SVG (lucide-подобные). Фотографии (установка, карта, канат) — CSS-градиенты-заглушки.
- Строка «Прохождение занимает 5–10 минут» дана в корректной орфографии (в макете была опечатка «Проходжение»).
- Экран «Забивка свай» приведён к словарю проекта, а не к подписям с картинки: «Секция / Кластер» →
  **«Поле / Куст»** (иерархия `Site` → `PileField` → `Cluster` → `Picket`), «Тип свай» → **«Марка сваи»**
  (`PileGrade`). Длина и сечение сделаны **нередактируемыми**: в проекте длина сваи берётся из
  `PileGrade.lengthMm` одним резолвером — это чинили отдельно, после того как м.п. разъезжались в семи
  местах. Свободное поле «Длина свай, м» в макете вернуло бы ту же ошибку в новое ТЗ.

## Куда подключать в приложении

Живой контур уже закрывает почти весь этот макет: 8 фаз `IDENTITY → ADMISSION → PRESHIFT_INSPECTION →
STARTUP → SITE_READY → WORK → CLOSING → CLOSED` (`src/modules/operator-mobile/domain/shift-phases.ts`),
а экраны — в `src/components/piling/operator-mobile/screens/`. Инструктажи, проверка знаний, приёмка,
погода, чек-листы, паспорт сваи, лидерное бурение, дефекты и закрытие смены **уже написаны**.

**Единственный экран макета, которому нет пары в живом контуре, — «Передача смены» (4/4 №7).** Но писать
его с нуля не нужно: реализация есть в предыдущем поколении экрана —
`src/components/piling/operator/handover-dialog.tsx` (два готовых ответа одним нажатием, текст обязателен
только там, где есть замечание). Этот код без маршрута, но живой; при переносе брать его логику, а не
придумывать заново.

Остальное — вопрос вида, а не функции, поэтому «перенести 36 экранов в React» было бы переписыванием
работающего: сравнивать нужно поэкранно.
