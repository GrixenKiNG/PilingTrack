# H15 — Изолировать daily-summary тесты от DB

Родитель: **I10**, [STRATEGY-2026Q4.md](../STRATEGY-2026Q4.md). CODEX-S2. Исполнитель Hermes, приёмка Claude.

## Цель и разрешённое изменение

Менять только существующие mocks/fixtures/beforeEach для импортов, создающих DB-зависимость. Сначала воспроизвести семь baseline failures; использовать hoisted mocks без env/DB. Сохранить смысл assertions о tenant, projection, retry и cache. Код приложения не менять.

## Whitelist

Ровно один разрешённый путь для изменений:

- `src/services/reports/__tests__/daily-summary.test.ts`

## Зависимости и стоп-условия

БЛОКИРУЮЩАЯ зависимость: исходный запуск целевого теста в текущей ветке. Если уже исправлен, сообщить без изменения. Реальный дефект приложения или неясный контракт передать Claude/Codex; whitelist не расширять.

## Критерии приёмки

Целевой тест: exit 0, 0 skipped без DB/env. Assertions не ослаблены, нет skip, сокрытия ошибки catch или подмены смысла проверки. Полный unit-прогон не получает новых failures/skips; посторонние failures указаны отдельно.

## Проверка

RED: `npx.cmd vitest run src/services/reports/__tests__/daily-summary.test.ts`. GREEN: повторить ту же команду, затем отдельно `npx.cmd tsc --noEmit` и `npm.cmd run test:unit`. Не задавать вымышленные process.env для DB/секретов, не читать .env и не подменять проверяемую production-команду пустым mock.

## Общие правила

- Менять только указанный whitelist. Остальные проблемы записать в отчёт, область задачи не расширять.
- Работать в назначенной Claude локальной ветке codex/*. Не менять ветку самостоятельно; не коммитить в main, не push/merge/rewrite history, не deploy/SSH/scp/production DB.
- Не читать, создавать или менять .env* и секреты. Не устанавливать зависимости и не менять версии.
- Не менять src/services/auth/**, src/app/api/auth/**, src/core/security/**, src/lib/csrf-protection.ts, src/lib/rate-limiter.ts, RLS/tenancy, prisma/schema.prisma, prisma/migrations/**, Dockerfile*, docker-compose* и scripts/deploy-*.
- Не менять frozen области: src/app/operator/**, src/app/(app)/operator/**, src/components/piling/operator*/**, src/modules/operator-mobile/**, src/app/orion/**, src/app/api/orion/**, src/components/orion/**, public/orion*. Не удалять данные, экспорты и rollback-код.
- Новые файлы тестов запрещены. Использовать существующие тесты и локальный браузер в рамках задачи. Для кода показать узкую регрессию до/после; assertions не ослаблять, skips не добавлять. Для документов и комментариев искусственные тесты не нужны.
- До изменения символов выполнить GitNexus impact, до коммита — detect-changes. Только при подтверждённом отказе GitNexus использовать разрешённый на эту ночь fallback: rg callers по src/tests/e2e/scripts и git diff --stat. UNKNOWN не означает отсутствие риска.
- Каждую команду выполнять отдельно; записать реальный exit, passed/failed/skipped. Браузерную приёмку заявлять только после реальной проверки.
- При отсутствующей зависимости или неясном контракте отложить задачу и сообщить Claude. Этот документ не разрешает обход whitelist.

## Отчёт

Указать изменённые пути и число строк, причину, команды с exit и числами тестов/скипов, состояние браузерной проверки, оставленное без изменения и риски. Один коммит на логическое изменение; приёмку выполняет Claude. Локальная сборка и чтение исходников не доказывают применение на production.
