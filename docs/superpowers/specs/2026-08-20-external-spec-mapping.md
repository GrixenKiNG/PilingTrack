# Внешняя спецификация «жизненный цикл смены» → код PilingTrack

**Дата:** 2026-08-20
**Источник:** спецификация из 50 требований (внешний агент), приложена владельцем
**Решение по границам:** совет 2026-08-20, см. `2026-08-20-operator-shift-cycle-design.md`

Обозначения: **есть** — работает в коде; **частично** — работает не полностью,
расхождение названо; **не берём** — сознательное решение с причиной;
**осталось** — не сделано, стоит делать.

## Ядро процесса

| № | Требование | Статус | Где / почему |
|---|---|---|---|
| 1 | Действующий допуск к типу оборудования | частично | `operator-clearance.ts` — допуск по документам работника. Связи «вид документа → тип машины» нет: перечень обязательных документов пока общий для всех установок |
| 2 | Проверки до смены | частично | оператор, назначение, тех. блокировки, документы — есть; «нет другой активной смены» держится уникальностью экипажа на машину, а не явной проверкой |
| 3 | Приёмка установки с фиксацией | частично | оператор, машина, время, моточасы, состояние — есть (`ShiftHandover` + `MeterReading`); **топлива и координат нет** |
| 4 | Динамические чек-листы по модели | есть | `block-composition.ts`: БАЗА + МОЛОТ + ВРАЩАТЕЛЬ по атрибутам машины |
| 5 | PASS / WARNING / FAIL / NOT_APPLICABLE | есть | тип ответа `STATUS4`; рядом живут `YES_NO`, `DONE`, `MEASURE` |
| 6 | WARNING создаёт замечание | частично | ответ снижает балл здоровья и уходит в передачу смены; отдельной сущности «замечание» нет и не нужна |
| 7 | FAIL создаёт дефект | есть | `defect-rules.ts`, признак `createsDefect` в снимке шаблона |
| 8 | Критический дефект блокирует пуск | есть | препятствия контура готовности |
| 9 | Описание, фото, запись, BLOCKED, уведомление | есть | фото обязательно при «неисправно»; уведомления подключены 12.08.2026 |
| 10 | Проверка рабочего места | есть | раздел внутри ЕО, а не отдельная фаза: по руководству Liebherr 4.11.1 машину и площадку обходят разом |
| 11 | READY CHECK | есть | фаза 4 «Допуск и пуск» со списком препятствий |
| 12 | Пуск только из READY | есть | `transitions.ts` + `start-decision.ts` |
| 13 | Фиксация на старте | частично | время и моточасы — есть; **топлива и координат нет** |
| 21 | Промежуточная проверка перед завершением | есть | фаза 6 |
| 22 | Проверки перед закрытием | частично | осмотр после работ и отправленный отчёт — есть; «незакрытые инциденты» отсутствуют вместе с инцидентами |
| 23 | Послесменный осмотр | есть | разделы «После смены» действующих шаблонов, `phase-split.ts` |
| 24 | Сравнение состояния вход/выход | есть | `state-diff.ts`, результат уходит в передачу |
| 25 | Ежесменное обслуживание в конце | есть | те же разделы конца смены (очистка, осмотр, наработка) |
| 26 | Короткий отчёт о смене | частично | `Report` связан со сменой; **топлива в отчёте нет** |
| 27–28 | Передача машины и замечаний | есть | `ShiftHandover` + сводка изменений состояния |
| 34 | Серверная валидация переходов | есть | команды контура: версия агрегата, `If-Match`, SERIALIZABLE |
| 49 | Аудит | есть | `TenantAuditChain` — хеш-цепочка, а не просто журнал |

## Что сознательно не берём

| № | Требование | Причина |
|---|---|---|
| 2 (enum) | 19 состояний смены | Состояний шесть, фаз для человека семь. Девятнадцать состояний в базе — это девятнадцать способов застрять; переходы пришлось бы описывать матрицей 19×19 |
| 17 | PAUSED | Пауза неотличима от простоя, а простой уже учитывается в отчёте по причинам. Два способа записать одно и то же расходятся в отчётности |
| 15, 22 | Отдельная сущность «инцидент» | Дефект с признаком «влияет на безопасность» делает то же самое и уже блокирует пуск. Вторая сущность потребовала бы своего журнала, прав и уведомлений ради того же смысла |
| 31–33 | Offline-first, Dexie, очередь синхронизации | Отдельная работа масштабом с весь модуль: своя модель конфликтов, свои тесты, свой класс ошибок. На объектах связь есть; заводить это «на будущее» — против принципа не строить впрок |
| 35 | 20 маршрутов `/api/shifts/*` | Команды уже живут на `/api/readiness/shifts/*` с идемпотентностью и ETag. Второй набор маршрутов к тем же данным — два места правки и два набора багов |
| 37 | 19 новых моделей | Тринадцать из них уже есть под другими именами. Добавлено четыре миграции |
| 38 | 12 маршрутов `/operator/*` | Один экран, который сам знает, какой шаг показать. Двенадцать адресов — двенадцать способов войти не туда |
| 45–46 | Демо-парк LB 20 #002, PVE 50PR #01 | В базе девять настоящих машин и живые чек-листы по руководствам. Выдуманная техника рядом с настоящей — источник ошибок в отчётности |

## Что осталось

| Что | Зачем | Оценка |
|---|---|---|
| **Топливо** при приёмке, на старте, в отчёте | Единственная величина из спецификации, которой нет нигде. Нужна колонка `Shift.startFuel/endFuel`, поле в приёмке и строка в отчёте | полдня |
| **Этап смены у диспетчера** | Сейчас в списке смен видно состояние (`Запланирована`, `Идёт`), но не человеческий этап («осмотр, 8 из 12»). Правило уже есть чистой функцией — нужно посчитать его на сервере для списка | полдня |
| **Допуск по типу техники** | Сегодня обязательные документы общие для всех установок. Связь «вид документа → вид техники» нужна, когда появится техника, требующая разных удостоверений | день, по потребности |

Прочее из списка (39–44, 47, 50) закрыто: русские названия вместо технических,
показ этапа и прогресса, запрет пропуска шага, тесты переходов, обратная
совместимость API.
