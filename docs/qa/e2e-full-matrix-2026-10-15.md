## Две дорожки

Стандартный `npx playwright test` собирает всё сразу: 97 тестов на профиль, из них 57 — это
QA-спеки (`e2e/qa`, `e2e/qa-ac`). Им нужны `D:\PillingR\qa` и дев-сервер. Поэтому на
одноразовом стенде их нельзя запускать вместе с основными. Разделяем.

### Дорожка A. Одноразовый стенд (боевая сборка, HTTPS, своя БД)

Покрывает 3 профиля: `chromium`, `Mobile Safari`, `Mobile Chrome`.
Все 7 ролей входят настоящими учётками (`e2e/role-audit.spec.js`, без «Действую как»).

| Роль | Домашняя страница | Что проверяет `role-audit` |
|---|---|---|
| ADMIN | `/admin` | вход, права, мобильная вёрстка |
| DISPATCHER | `/admin` | то же |
| OPERATOR | `/operator` | то же |
| ASSISTANT | `/assistant` | то же |
| MECHANIC | `/admin/to` | то же |
| FOREMAN | `/admin` | то же |
| SAFETY_ENGINEER | `/admin/safety` | то же |

Сквозные сценарии (ADMIN, DISPATCHER, OPERATOR): отчёт «черновик → отправка → дневная проекция →
KPI → PDF воркером», наряд ТО, удаление куста с подтверждением, сбой аналитики, Telegram,
печать инструктажа, осмотр → поток, редактор плиток монитора (с одноразовым S3), лимит запросов.
Изоляция арендаторов: учётка `OPERATOR_B` из другого арендатора.

Запуск (Git Bash, из корня проекта):

```bash
bash scripts/test-day-stand.sh
```

Стенд собирает боевой Next и ждёт команду в `output/codex-t5/stand-command.json`.
Записать в этот файл (UTF-8 без BOM):

```json
{"id":"playwright-all","args":["e2e/fixtures/disposable-https.mjs","node_modules/@playwright/test/cli.js","test","--workers=1","--reporter=line","e2e/admin-dictionaries.spec.ts","e2e/admin-users.spec.ts","e2e/app.spec.ts","e2e/inspection-to-flow.spec.ts","e2e/monitoring-tile-editor.spec.ts","e2e/operator-report-smoke.spec.ts","e2e/orion-industrial-cinematic.spec.ts","e2e/rate-limit-e2e.spec.ts","e2e/release-critical-path.spec.ts","e2e/report-creation-flow.spec.ts","e2e/smoke-e2e.spec.ts","e2e/role-audit.spec.js"]}
```

Результат: `output/codex-t5/playwright-all-result.json` (код возврата) и `playwright-all.log`.
После завершения записать `{"stop":true}` в тот же файл — стенд сам уберёт свои контейнеры.
Для повторного прогона нужен новый стенд: часть сценариев меняет данные и идёт один раз.
Для проверки реальных фото и PDF добавить `CODEX_WITH_S3=true` (см. `e2e/README.md`).

Ожидание: 120 тестов в сборе. Часть сценариев идёт только в Chromium, так что на мобильных
профилях пропусков больше. Любой пропуск записать в отчёт с причиной.

### Дорожка B. Дев-сервер + локальная QA-база (роли, права, запись, экспорт)

Покрывает права по ролям и «Действую как», все варианты экрана машиниста, экспорты до файла,
мобильную вёрстку 375px, клавиатуру, заголовки безопасности.
Роли из `matrix.json`: ADMIN, DISPATCHER, MECHANIC, FOREMAN, SAFETY_ENGINEER; ASSISTANT и
OPERATOR берутся из версий экрана машиниста (`operator`, `v2`, `v5`, `v7`, `v10`).
Исключённые владельцем учётки (2 шт.) тесты не используют.

```bash
npx playwright test --config playwright.acqa.config.ts   # 36 тестов: права, запись, экспорт, 375px
npx playwright test --config playwright.qa.config.ts     # 21 тест: 7 на desktop, 14 на phone (экран машиниста)
```

Условия: дев-сервер на `http://localhost:3000` запущен, база локальная тестовая.
`write-flows` пишет данные в локальную QA-базу. Вход ограничен 20 попытками за 15 минут,
сессии кэшируются в `D:\PillingR\qa\.auth`.

## Замечания

- `integration.yml` (на каждый push и PR) гоняет только Chromium и 5 спеков + `role-audit` + редактор
  плиток. Мобильные профили и остальные сценарии идут в ночном прогоне (раздел ниже).
- `playwright.config.ts` собирает QA-спеки вместе с основными. Если в окружении нет
  `D:\PillingR\qa`, импорт `e2e/qa/helpers.ts` падает при сборе. Менять конфиг не стал:
  в CI он не мешает (там указаны файлы), на стенде достаточно списка файлов выше.
