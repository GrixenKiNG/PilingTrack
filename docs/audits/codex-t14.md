## X8: проверка и включение владельцем

Workflow только отредактирован. Никакие содержащиеся в нём SSH/deploy-команды не выполнялись. Временный локальный harness проверил YAML, `bash -n` всех run-блоков, затем исполнил только preflight и health с mock gh/curl/sleep. Успешный CI разрешает продолжение; failed/in progress/чужой SHA/пустой CI/невалидный SHA отклоняются. Старая версия, сменившаяся нужной, проходит; постоянно старая версия даёт ожидаемый exit 1 после 30 попыток.

Фильтрация CI использует GitHub REST [List workflow runs for a workflow](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-workflow): workflow `ci.yml`, `head_sha`, `branch=main`, `event=push`; отдельно сверяются SHA, completed и success. Проверяется последний запуск: старый success не маскирует новый failed/in progress.

Владельцу после ревью необходимо отдельно включить изменения workflow в main, дождаться успешного CI выбранного полного main SHA и вручную передать этот SHA в Run workflow. Существующий барьер остановки внешних workers сохранён. Здесь workflow не активировался и готовность production не удостоверялась; это инструкция для отдельного решения о выкладке, не разрешение на неё.
