# Запрос точечного исключения: GET карточки установки

Дефект воспроизведён: EQUIPMENT-ACCESS-RED.md/json. Оператор обходит ограниченный список прямым id и получает паспорт неназначенной установки своего арендатора.

## Предлагаемая правка

Только обработчик GET в src/app/api/equipment/[id]/route.ts. После существующего getEquipmentByIdOrThrow(id, tenantId), перед возвратом ответа добавить:

~~~ts
    if (user?.role === 'OPERATOR') {
      const assignedCrew = await db.crew.findFirst({
        where: { operatorId: user.id, equipmentId: id, isActive: true, equipment: { tenantId } },
        select: { id: true },
      });
      if (!assignedCrew) {
        return NextResponse.json({ error: 'Установка не найдена' }, { status: 404 });
      }
    }
~~~

Это девять добавленных строк. db уже импортирован; новых импортов/зависимостей не нужно. Существующая строгая tenant-проверка остаётся перед этим блоком. Запрос ищет любую активную бригаду для сочетания operatorId/equipmentId, поэтому не подменяет несколько назначений выбором первой бригады. Своя установка продолжает давать200. Неназначенная даёт404 без паспортных данных. Другие роли, POST/PUT/DELETE, общие auth/security/RLS, схема, индексы и транзакции не меняются.

Проверки — новый уже красный реальный E2E (своя200, список ограничен, чужая403/404) во всех трёх браузерах; случаи GET в существующем route.test.ts, сохранность прежних unit; типы/lint/полный unit/list/build последовательно на новом SHA; операторские циклы с одной/несколькими установками для проверки допустимых назначений. Assertions красного теста не ослаблять.

Приложение пока не изменено. AGENTS.md §1 запрещает «anything RLS/tenancy-related», а исходное ночное задание оставляет auth/security только для чтения. Для применения именно этого блока и проверок требуется разрешение владельца. Предыдущие исключения S3/outbox/idempotency сюда не распространяются.

## Решение владельца

28 октября2026, в этом чате: «Разрешаю этот GET и тесты». Разрешён только предложенный девятистрочный блок проверки назначения в GET и проверки в существующих тестах. Остальные роли, общие auth/RLS, схема, миграции и прочие tenancy-файлы не включены. Исправление будет отдельным коммитом после RED.
