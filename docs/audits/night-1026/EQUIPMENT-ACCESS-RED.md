# ДЕФЕКТ P2: оператор читает неназначенную установку по прямому id

На собственной сборке 00ac751ffa4c22cb2117a189474ce7bcc73410cc, обычный OPERATOR, настоящий вход, свои disposable PG18 и fixtures. Создана вторая установка того же арендатора с уникальным синтетическим маркером в имени и VIN. Активной бригады этого оператора для неё нет; SQL проверен.

| Запрос | Факт |
|---|---|
| GET /api/equipment | 200; назначенная установка есть, неназначенной нет |
| GET /api/equipment/<назначенная> | 200 — это штатный доступ, его необходимо сохранить |
| GET /api/equipment/<неназначенная>/details | 403 |
| GET /api/equipment/<неназначенная> | **200; возвращены имя, модель и VIN с точным синтетическим маркером** |

Итог нового целевого сценария: **0 passed / 1 failed / 0 skipped / 0 flaky**, exit1, 39с со стендом; 5.63с Playwright. Падает требование отказа при обращении по прямому id. Это не сбой harness: авторизованный субъект, принадлежность оборудования и содержимое ответа подтверждены отдельно. Стенд очищен: cleanup=true, errors=[]. Сырой JSON/скриншот/сценарий — equipment-access-red-raw; точные ids и ответ — EQUIPMENT-ACCESS-RED.json.

Обход фильтра позволяет читать паспорт другой установки внутри одного арендатора. Межарендаторская утечка этим тестом не показана и не заявляется. Роли ADMIN/DISPATCHER не ограничиваются этим предложением. ASSISTANT и остальные варианты доступа ещё не проверены этим сценарием.

Причина в исходнике: GET /api/equipment/[id] проверяет аутентификацию и tenant, но не назначение. Список ограничивает OPERATOR через active crews, а details проверяет equipment.read. Соседние маршруты моточасов/топлива также проверяют назначение. Эти пять связанных исходников побайтно равны BASEefd95008 по Git blob. Это проверка исходников, отдельная HTTP-сборка BASE не запускалась.

File-impact E2E и symbol-impact GET: UNKNOWN/0; это не считалось безопасным. Вход сценария подтверждён playwright.night.config.ts и nightly workflow; текстовый поиск HTTP-потребителей дал38файлов, полный лог equipment-direct-id-text-callers.log. UID GET разрешён с точным file_path. Правка приложения не применена: проверка назначения относится к закрытой AGENTS.md §1 зоне tenancy/security. Точечное предложение — PERMIT-EQUIPMENT-ACCESS.md.

Новый тест добавлен только в существующий e2e/release-critical-path.spec.ts, старые тела побайтно сохранены. Красный результат не скрыт skip и не заменяет положительный users/UI6 или полный unit5776/0/0 на той же прикладной сборке. После будущей правки нужны новые проверки её SHA.

Перед фиксацией RED: tsc exit0/15с; lint exit0/63с без предупреждений; Playwright collection 402/30 против BASE 318/28, оба exit0/40с. Владелец разрешил только предложенный GET и существующие тесты; разрешение записано в PERMIT-EQUIPMENT-ACCESS.md. Приложение до этого RED-коммита не меняется.
