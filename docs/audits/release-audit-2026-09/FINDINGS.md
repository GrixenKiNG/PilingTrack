## F-02. ЗАКРЫТО (перепроверено 22.09.2026) — Кэш API и повторная проверка доступа
- **Компонент:** `src/core/api-wrapper.ts`, `src/core/cache/response-cache.ts`.
- **Было:** закешированный 200 отдавался после отзыва доступа/смены роли, т.к. контекст исполнения не входил в ключ.
- **Факт на 22.09.2026:** поле `CacheKey.userId` заполняет не идентификатор пользователя, а `getSessionCacheScope` (`api-wrapper.ts:44`): `sha256(sessionToken + ':' + actingAs)`. Разобраны все пути отзыва:
  - «действую как» тем же токеном → `x-acting-as` входит в хеш ключа, ячейки разные;
  - сессия отозвана/истекла → `requireAuth` вызывается ДО обращения к кэшу (`api-wrapper.ts:88`), невалидная сессия идёт мимо кэша;

  - блокировка, смена пароля/PIN → тот же `sessionVersion++` (`user-service.ts:234`).
- **Покрытие:** `core/__tests__/api-wrapper.test.ts:162` (отозванная сессия не читает кэш) и `:184` (полные права и «действую как» разведены по ячейкам). Прогон 22.09.2026: 25/25 зелёных.
- **Остаточный зазор — нет:** смена прав без смены роли невозможна (права выводятся из роли в `authorization-service`); привязка к объектам в фильтрацию `listReportsForReview` не входит, а `/api/sites/*` при переназначении чистится через `invalidateSites` (`lib/cached-queries.ts:96`).
- **Почему аудит 21.09 этого не увидел:** прочитан только `cacheKeyToString` (форма ключа), без разбора вызывающих, которые его заполняют. Имя поля `userId` вводит в заблуждение — там хеш токена с ролью.
- **Статус:** закрыто, покрыто тестами. **Блокирует релиз:** нет.

## F-03. ПРИЧИНА НАЙДЕНА, исправление готово (не выкачено) — `/api/health/deep` = 503
- **Компонент:** `src/lib/redis-cache.ts`, `src/core/observability/health-tracker/checkers/{websocket,workers}.ts`, `aggregate.ts`.
- **Факт 22.09.2026:** 503 и на локальном инстансе, и **на проде**: `{"database":"ok","redis":"ok","storage":"ok","websocket":"down"}`. При этом ws-сервер жив — upgrade-запрос к `https://orionpiling.ru/ws/` отвечает **101**, контейнер `pilingtrack-ws` в статусе healthy.
- **Корневая причина — два Redis и переменная, заданная не всем.** `getRedisClient()` берёт адрес как `REDIS_URL_CACHE || REDIS_URL` (`redis-cache.ts:45`). На проде:

  | Контейнер | `REDIS_URL_CACHE` | Куда попадал пульс |
  |---|---|---|
  | `app` (читатель) | есть | искал в `redis-cache` |
  | `ws` (писатель) | **нет** | писал в `redis` (состояние) |
  | `workers` (писатель) | есть | писал в `redis-cache` |

  Одинаковый код, разные адреса. Ключ `system:ws:connections` writer'ом и reader'ом не совпадал → чекер (ужесточённый в 6b6a3d7d по H3) честно отвечал `down` → `computeOverallStatus` → `unhealthy` → 503. Пульс workers совпадал случайно, поэтому та половина была зелёной.
- **Почему это не только косметика:** пульс — состояние, а не кэш; на `allkeys-lru`-инстансе вытесненная запись читается как «служба мертва». Локальные 503 — тот же механизм плюс отсутствие ws-сервера в дев-режиме.
- **Исправление (готово локально, 22.09.2026):** добавлен `getStateRedisClient()` — всегда `REDIS_URL`, без подмены на кэш (тот же довод, что у списка отозванных токенов в `session-service`); чтение и запись пульса ws/workers и метрика `activeWsConnections` переведены на него. Отдельного кэш-инстанса нет → второе соединение не открывается.
- **Покрытие:** `observability/__tests__/health-tracker.test.ts` — 2 теста: пульс в состоянии → служба жива; тот же пульс в кэше → мертва (ровно продовая картина). Мутационная проверка: возврат чекера на кэш-клиент → тесты красные.
- **⚠️ Условие деплоя:** собирать и поднимать `app` **и** `workers` вместе. Если обновить только `app`, он станет читать пульс из состояния, а необновлённый `workers` продолжит писать в кэш — `workers` перевернётся в `down`, и 503 останется, только по другому компоненту.
- **Альтернатива, которую сознательно не выбрали:** дописать `REDIS_URL_CACHE` в env контейнера `ws` — правка одной строки без пересборки, но тогда состояние живёт на инстансе с вытеснением, против прямого указания в `redis-cache.ts:44`.
- **Статус:** причина подтверждена, исправление готово и покрыто тестами, **на прод не выкачено**.
