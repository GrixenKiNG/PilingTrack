## Предлагаемый SQL (НЕ выполнять; сначала бэкап)

Проверка правила «не удалять без проверки ссылок» (всё по локальной БД, для прод — см. «Не проверено»):
- входящих внешних ключей на `ReportAnalytics` — **0**;
- обе читающие выборки отбирают строки по `reportId` живых `Report`, сироты не попадают в UI;
- триггеров `append-only` на `ReportAnalytics` нет (список в `scripts/check-postgres-rules.js:68` — это линтер схемы, не ограничение БД);
- сам продукт удаляет строки `ReportAnalytics` в маршруте удаления (`delete/route.ts:165`) — прецедент.

Значит, удаление именно этих 5 строк безопасно по ссылкам. Инвентаризация, затем удаление:

```sql
SET app.current_tenant = 'orion';   -- RLS: без контекста 0 строк

-- 1) Инвентаризация (выполнить и сохранить вывод)
SELECT a."reportId", a."tenantId", a.status, a."createdAt", a."lastEventAt"
FROM "ReportAnalytics" a
LEFT JOIN "Report" r ON r."reportId" = a."reportId"
WHERE r."reportId" IS NULL
ORDER BY a."createdAt";

-- 2) Удаление сирот по явному списку (аудитопригодно; ожидаемо 5 строк)
BEGIN;
DELETE FROM "ReportAnalytics"
WHERE "reportId" IN (
  '00fc064e-924e-4456-b8d2-79ed2c69bf97',
  '5bf66128-a0d3-403c-8361-13e30c84cd9d',
  '880c6af8-b6df-4820-80a1-b9607b3e2ce3',
  '174f9e42-20d3-44d5-af7c-d6c59b4c97ad',
  'operator-v3-bfc41098-0efc-4f4f-ac02-be5d6d7c9369'
);
COMMIT;
```

Альтернатива «по правилу», без списка ключей (то же множество при текущих данных):
```sql
SET app.current_tenant = 'orion';
BEGIN;
DELETE FROM "ReportAnalytics" a
WHERE NOT EXISTS (SELECT 1 FROM "Report" r WHERE r."reportId" = a."reportId");
COMMIT;
```
Оговорка: вариант без списка удаляет всё, что не подтверждено живым отчётом, — при кросс-тенантном запуске без `SET` (0 строк по RLS) или в базе с чужими тенантами нужно гонять per-tenant. Список ключей предпочтительнее.

**Что перестроить:** 6-я строка (отсутствующая аналитика) уже не нужна — она появилась сама 06.10 19:14 через `ReportSubmitted`. Если бы окно осталось, «долив» делается либо перестройкой `POST /api/admin/projections/rebuild?name=report-analytics` (`rebuild.ts:177-230`), либо `scripts/backfill-report-analytics.sql:42-66` (идемпотентный `ON CONFLICT DO NOTHING`). Ни один из путей сирот не трогает.

**Постоянное лечение (предложение, не в этой задаче):** в `rebuildReportAnalyticsForTenant` (`rebuild.ts:187-230`) добавить удаление строк аналитики, чей `reportId` не входит в множество `Report.reportId` текущего тенанта (в той же транзакции/проходе), иначе класс сирот не закрывается кодом.
