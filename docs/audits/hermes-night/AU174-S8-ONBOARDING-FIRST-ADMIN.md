## Итог

Аудировано 12 шагов первого запуска; найдено 16 находок: 6 «критично», 6 «важно», 4 «мелочь».

1. Организация (Tenant) и первый администратор создаются **исключительно** в `prisma/seed.ts`. Ни одна миграция и ни один путь в `src/` тенант не создают — проверка по `prisma/migrations/**` и по `src/` дала ноль совпадений на вставку Tenant.
2. Сид отказывается работать при `NODE_ENV=production` (`prisma/seed.ts:36`), а прод-оверлей compose ставит `SKIP_SEED=1` по умолчанию (`docker-compose.prod.yml:144`). Итого: на штатном боевом развёртывании нет ни организации, ни администратора, и документированного способа их создать — тоже нет.
3. Документированный способ «через psql» нерабочий: в SQL несуществующее поле `passwordHash`, нет обязательного `tenantId`, ссылка на несуществующий `scripts/hash-password.ts` (`docs/deployment.md:115-121`).
4. Пароли «по умолчанию» зафиксированы в коде и **печатаются в лог** (`prisma/seed.ts:140-153`), продублированы в `LOCAL-ACCESS.md`, `scripts/reset-passwords.ts`, e2e-тестах.
5. Обязательной смены пароля нет вообще: в схеме нет поля «сменить пароль» (0 совпадений по репозиторию), и нет маршрута смены пароля самим пользователем (`src/app/api/auth/` содержит только `login`, `logout`, `me`). Первый вход администратора с фиксированным паролем остаётся таким навсегда.
