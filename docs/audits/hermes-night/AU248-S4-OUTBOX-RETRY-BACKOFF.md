# AU248-S4-OUTBOX-RETRY-BACKOFF: повторы outbox — пауза и предел

Версия кода: `git rev-parse HEAD` → `d2b8befeefe6326a21cf1521e96be7ff7a6695de` (ветка `hermes/q4-0926`, worktree `D:\PillingR\wt-night`).
Задача: только чтение кода приложения; новых файлов — один (этот отчёт).

## Итог

Счёт по серьёзности: критично — 0, важно — 8, мелочь — 9 (итого 17).
Топ-5:
1. [важно] Счётчик `attempts` и пауза общие на двух потребителей одной строки outbox и не сбрасываются при успехе (`src/services/reports/outbox-publisher.ts:85,156-164,170-173`) — строка, потратившая попытки на публикатора, уходит в DLQ на первой же ошибке проекции, то есть без повторов. Сброс счётчика есть только в ручной операции `/api/admin/dlq/retry` (`src/core/outbox/dead-letter-queue.ts:138`); в `src/modules/reports/infrastructure/report.repository.ts:65` attempts при создании строки задаётся как 0.
2. [важно] Запись повтора идёт через `update` без защиты от гонки (`src/services/reports/outbox-publisher.ts:215-222`) — при одновременной работе двух потребителей возможен потерянный инкремент: `attempts` понижается, предел 5 не достигается, пауза сбрасывается.
3. [важно] В ветке DLQ используется `update` (не `updateMany`) (`src/services/reports/outbox-publisher.ts:200-209`): исключение (P2025 при удалённой строке) вылетает из блока `catch` и роняет всю пачку — остальные события тика не обрабатываются вообще.
4. [важно] `getOutboxStats().failed` (`src/services/reports/outbox-publisher.ts:315-332`) не является счётчиком DLQ: строка после предела помечается `published=true` и в этот счётчик не попадает. В журналах «failed» почти всегда 0, реальное число недоставленных видно только в `/admin/dlq` и метрике `dlq_pending_count`.
5. [важно] Событие, ждущее паузу (attempts 1–4), не видно ни в интерфейсе, ни (по умолчанию) в журналах: единственный экран — `/admin/dlq`, а он читает только DLQ; лог «Outbox event scheduled for retry» пишется на уровне debug (`src/services/reports/outbox-publisher.ts:224`), а в проде минимальный уровень — info (`src/lib/logger.ts:31-42`).

Пауза и предел считаются в одном месте — `src/services/reports/outbox-publisher.ts:26-41`: `MAX_RETRIES = 5`, база 1000 мс, множитель 2, потолок 60000 мс, джиттер +0..30% (`attempts` в формуле 1-базовый). Накопленная минимальная пауза до DLQ — 30 с (проверено расчётом формулы в node: 2+4+8+16 с), потолок 60 с в реальности недостижим, так как на 5-й ошибке строка уходит в DLQ.
