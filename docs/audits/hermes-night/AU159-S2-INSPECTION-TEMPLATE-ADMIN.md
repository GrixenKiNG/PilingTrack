# AU159-S2-INSPECTION-TEMPLATE-ADMIN — администрирование шаблонов осмотров

Версия кода: `git rev-parse HEAD` = `d475da08d80d7b7c7e41e11ead8fc58927968a20` (ветка `hermes/q4-0926`).
Только чтение: код приложения не изменялся, создан один файл — этот отчёт.

## Итог

Аудировано администрирование двух каталогов шаблонов осмотров: «механика» (`ChecklistTemplate` + `ChecklistSection`/`ChecklistItem` в БД) и «машиниста» (`OperatorChecklistTemplate`, состав задан в коде). Всего 27 находок: **критично — 0, важно — 14, мелочь — 13**; отдельно 5 проверок пройдены без замечаний (изоляция организаций, атомарность замены, защита начатого осмотра снимком, валидация тела запроса, безопасное удаление).

Главное:

1. **Правка шаблона во время смены не защищена сервером.** Предсменный и послесменный осмотры одной смены собираются в разные моменты из «действующих сейчас» шаблонов: правка между ними даёт смену, где приёмка по старой редакции, а сдача — по новой, а удаление раздела «После смены» вообще лишает смену возможности закрыться (`src/modules/inspections/application/commands/inspection-commands.ts:87-90,130-139`, `src/modules/operator-mobile/application/commands/shift-close.ts:265-277`).
2. **Два каталога не связаны ничем.** Мобильный чек-лист машиниста живёт в коде, не имеет ни админ-экрана, ни авто-версионирования, а строки его шаблона создаёт сам машинист при первой сдаче этапа (`src/modules/operator-mobile/application/commands/checklist.ts:25-43`). Одна и та же неисправность, найденная механиком и машинистом, заводит **два** дефекта — ключи дедупликации у каталогов разные (`src/modules/inspections/domain/defect-rules.ts:89` против `src/modules/operator-mobile/domain/checklist-run.ts:125`).
3. **Серверных гарантий у правки нет** — только подсказки в браузере: снятый (архивный) шаблон можно выпустить заново прямым `PUT`, а одновременная правка двумя админами даёт два действующих блока на одну модель, и какой из них попадёт в осмотр машины, не определено (`src/modules/inspections/application/commands/template-commands.ts:82-87`, `src/modules/inspections/application/commands/inspection-commands.ts:87-90`).
4. **Правила безопасности правятся широким правом.** Шаблоны осмотров редактируют четыре роли по праву `maintenance.manage` (заявки, ремонты, планы ТО); отдельного права/подтверждения на смену состава пунктов нет (`src/services/auth/authorization-service.ts:108`).
5. Шаблоны **недоступны из меню** ни одной роли: вход только через вкладку «Чек-листы» внутри `/admin/to` или по прямой ссылке, а у раскладки раздела и у API **разные права** (`src/components/piling/icons/role-navigation.ts:33-160`, `src/app/(app)/admin/checklists/layout.tsx:4` против `src/app/api/checklist-templates/route.ts:49`).
