## Не проверено

- **Фактический боевой деплой.** Сколько реплик контейнера `workers` (актуально для #3), включён ли контейнер, установлены ли четыре systemd-таймера — из этого окружения не проверить (нет доступа, AGENTS.md §1 запрещает прод). Выводы «при двух репликах» — статические, по коду и compose.
- **Значения `.env` на проде.** Файлы `.env*` не читались (запрет AGENTS.md §1). Поэтому «BACKUP_ENABLED не задан» (#9), «IDEMPOTENCY_CLEANUP_ENABLED/PDF_TEMP_CLEANUP_ENABLED не заданы» (#12) и «S3 включён» (#1) — по коду и compose, а не по факту на сервере.
- **Живые прогоны периодики.** Интеграционных прогонов планировщиков против реальной БД/Redis не делал (vitest не читает `.env`, окружение не поднималось). Утверждения об идемпотентности — из кода и комментариев, не из наблюдения.
- **Гонка с двумя `ReportSubmitted`** (#3б) выведена чтением кода под READ COMMITTED; экспериментально не воспроизводилась.
- **`scripts/backup.sh` (legacy) и `scripts/pitr-basebackup.sh`** открыты не полностью: расписание и юниты сверены, построчная логика — предмет отдельных аудитов бэкапов.
- **Часовой пояс боевого хоста.** `timedatectl`/`date` на сервере не выполнялись; вывод «МСК» взят из ранбука 013 и не подтверждён машиной (#10).
- **Таймер `docker-prune`** (#11) существует только по документации ранбука 013; в репозитории его нет, проверить его фактическое содержимое на сервере нельзя.
