# N17-44-CLIENT-INTERVAL-LEAKS — Таймеры и подписки в клиентских компонентах: очистка при уходе со страницы

Версия (`git rev-parse HEAD` рабочей папки): `ffaa71a404ea25643dd15f01e55c65056b3da24e`
Ветка: `hermes/code-1011`. Рабочая папка: `D:/PillingR/wt-night-code`. Режим: только чтение — код приложения не менялся, создан и закоммичен только этот файл.

## Резюме для владельца

1. Утечек таймеров при переходах между экранами нет: все интервалы создаются в `useEffect` и снимаются в очистке; модульный таймер ленты уведомлений один на всё приложение и рефкаунтится (`use-feedback-feed.ts:126-151`).
2. Главная реальная проблема — **медленное зависание ленты уведомлений**: в `loadFeedbackFeed` ветка `/api/ready` идёт «сырым» `fetch` без таймаута, а модульный флаг `inFlight` снимается только в `finally` (`use-feedback-feed.ts:85,88,104`). Один зависший запрос `ready` навсегда останавливает опрос у админа до перезагрузки страницы.
3. На экране смены машиниста (`operator-v2`, замороженная зона) опрос фактов раз в 6 с идёт **без защиты от наложения**: на слабой сети запросы копятся и приходят вразнобой → экран может мигнуть устаревшим снимком (снова «нет осмотра») (`operator-shift-v2.tsx:351-361,458-462`).
4. Единственная «честная» забытая очистка в незамороженном коде — debounce 300 мс у фильтров журнала: таймер не снимается при уходе со страницы, и `onChange` (включая `history.replaceState`) срабатывает уже на другой странице (`shared.tsx:141-149,190`).
5. Тест на очистку таймера есть только у ленты уведомлений (`use-feedback-feed.test.tsx:84-98`); у фильтров, панелей-ресайзеров, SSE-потока и опроса смены очистка тестами не покрыта.
