# Формы: говорит ли интерфейс, ЧТО и ГДЕ не так — на русском и рядом с полем

## Итог

Проверено 30 файлов форм/диалогов/редакторов из `src/components/piling/**` (глобы задания),
прочитано около 10 API-маршрутов и схемы валидации как источник сообщений. Ни один файл не изменялся.
Итог по severity: **критично — 6, важно — 21, мелочь — 12** (39 строк).

Главное: **сервер ни разу не отдаёт в интерфейс построчные ошибки валидации**. Все проверенные
маршруты возвращают `400/422` с `details` (`{field, message}` или `fieldErrors`) —
`src/app/api/reports/upsert/route.ts:46`, `.../admin-upsert/route.ts:27`,
`src/app/api/readiness/work-permits/route.ts:66`, `src/app/api/equipment/[id]/maintenance/route.ts:65`
и т.д. У 30 форм есть ровно один способ прочитать ответ — `err.error || '…'`, то есть общее
«Некорректные данные». Поиск по `src/components/piling/**` показал **ноль** мест, где читается
`details` (единственное исключение — `operator-mobile/api.ts:31`, замороженная зона). Итог: при
отказе формы пользователь видит одно слово и не знает, какое поле править.

Вторая массовая картина — **тихая пустота вместо ошибки чтения**: не загрузился справочник → в
форме пустой выпадающий список без объяснения (и до этого он выглядел как «данных нет»). Здесь же
и худший случай: оператор вводит дробные моточасы, отчёт сохраняется «успешно», а показание молча
выбрасывается.

Топ-5:
1. `report-form/report-form.tsx:29–45` — кнопка «+» в строках свай/бурения/простоя при неполном
   вводе не делает ничего и **ничего не говорит** (сообщения хука недостижимы) — критично.
2. `use-report-form.ts:409–412` — нецелые моточасы не попадают в payload, отчёт сохраняется, экран
   рапортует успех: введённое значение потеряно без предупреждения — критично.
3. `admin-reports/use-reports-data.ts:143,152` — не загрузился `/api/dictionary/all` → диалог
   отчёта открывается с пустыми «Марка сваи / Тип скважины / Причина простоя», в форме причины нет,
   повтор не предусмотрен (`referenceDataLoadedRef`) — критично.
4. `admin-reports/report-form-dialog.tsx:189` и `use-report-form.ts:427` — 400 с построчными
   ошибками показывается как тост «Некорректные данные» — критично.
5. `to/readiness/forms/permit-form.tsx:208,278` — текст «Заполните обязательные поля, отмеченные
   звёздочкой» недостижим (кнопки отключены при `!ready`), а причина отключения не показана ни
   у одного поля (у `Наименование`/`Описание` есть только счётчик до `limit`, минимальные 3 и 2
   символа нигде не названы) — важно.

Полезно как образец (ничего менять не нужно): `admin-users/user-dialogs.tsx:416–433` — русские
построчные ошибки под полем с `role="alert"`; `report-form/submit-bar.tsx:54–61` — подсказка,
почему кнопка отправки неактивна; `to/readiness/shift-create-form.tsx:118–125,197` — плашка
«Не загружено: установки», а не пустой список; `admin-sites/site-editor/edit-site-dialog.tsx:137–144,233`
— проверка координат текстом у самих полей.

## Методика

Что и как искал (повторяемо, Windows + Git Bash, node; Python в проекте нет):

1. Инвентаризация объёма задания:
   `search_files(target=files, pattern="*form*.tsx|*dialog*.tsx|*editor*.tsx") ` по
   `src/components/piling/**` + `ls src/components/piling/forms/*` и `report-form/*`; размеры —
   `wc -l`. Замороженные зоны (варианты операторского экрана, `operator-mobile`, ORION) исключены
   поимённо, не по содержимому.
2. Чтение всех 30 файлов целиком через `read_file` (не выборкой), включая вложенные под-компоненты
   форм: `report-form/*.tsx` (7 файлов), `forms/creation-form.tsx`, `to/readiness/forms/form-kit.tsx`.
3. Источник сообщений: `read_file src/lib/api.ts` (только `authFetch` отдаёт тело ошибки
   вызывающему), затем `search_files pattern="details", path=src/components/piling` — проверка,
   читает ли хоть кто-нибудь построчные ошибки API.
4. Язык сообщений сервера: `search_files pattern="error: '[A-Za-z]"` по `src/app/api/**` и
   `src/services/**`; `search_files pattern="invalid_type_error|required_error"` и чтение
   `src/lib/validation-schemas.ts` — есть ли русские подписи у zod (нет, кроме трёх мест).
5. Тексты контура готовности: чтение `src/modules/readiness/application/command-pipeline/etag.ts`,
   `.../errors.ts`, `src/app/api/readiness/_shared/response.ts`,
   `src/components/piling/to/readiness/screens/shared.tsx:262` (`commandFailure`) — как сообщение
   сервера доходит до экрана.
6. Каждое утверждение в таблице — строка, которую я открыл; там, где вывод сделан по коду, но не
   воспроизведён в браузере, это отмечено в «Не проверено».
