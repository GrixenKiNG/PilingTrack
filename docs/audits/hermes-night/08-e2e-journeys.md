# E2E-покрытие критических пользовательских сценариев (Playwright)

Отчёт по исследованию READ-ONLY. Никакие файлы кода не менялись. Все пути проверены открытием файлов.

## Итог

Проверено 12 спецификаций Playwright (38 уникальных тестов × 3 проекта = **114 тестов по `npx playwright test --list`**). Из 10 затребованных бизнес-сценариев **полноценно не покрыт ни один**; частично покрыты 7, полностью не покрыты 3. Главные проблемы: (1) весь файл `tech-readiness-production.spec.ts` (готовность смены и передача) обёрнут в `test.describe.skip` — 5 тестов существуют, но **не запускаются**; (2) «создание отчёта диспетчером/оператором» на деле не создаёт отчёт ни через UI, ни с drilling/downtime, а лишь дёргает API и принимает любой статус; (3) тест «оператор подаёт отчёт через UI-форму» вообще ничего не заполняет. Авторизация по PIN (`/api/auth/pin`), история отчётов, PDF-экспорт, наряд на ТО (create→accept→close) и форма лида ORION не имеют e2e вообще.  

Критичных дефектов покрытия — 4, важных — 5, мелочей — 7.

## Методика

1. `npx playwright test --list` (exit 0) → 114 тестов в 12 файлах (38 уникальных = суммарный счёт/3 проекта).
2. Прочитаны все 12 спецификаций из `e2e/`: `app.spec.ts`, `smoke-e2e.spec.ts`, `report-creation-flow.spec.ts`, `operator-report-smoke.spec.ts`, `admin-users.spec.ts`, `admin-dictionaries.spec.ts`, `inspection-to-flow.spec.ts`, `tech-readiness-production.spec.ts`, `rate-limit-e2e.spec.ts`, `orion-industrial-cinematic.spec.ts`, `monitoring-tile-editor.spec.ts`, `role-audit.spec.js`.
3. Прочитаны вспомогательные: `playwright.config.ts`, `global-setup.ts`, `page-objects/login.page.ts`, `fixtures/auth.fixture.ts`, `fixtures/role-audit.mjs`, `comprehensive-test.ts`, `tests/fixtures/tech-readiness.fixture.ts`, `e2e/README.md`.
4. Для каждого сценария проверялось: какие тест-файлы и имена тестов его касаются, что именно утверждается (UI-текст / HTTP-ответ / состояние после перезагрузки) и какие шаги бизнес-цепочки отсутствуют.
5. Поиск в `e2e/**` по ключам `pdf|export|history|maintenance|lead|pin|drilling|downtime` для подтверждения отсутствия покрытия.
6. Проверка существования не/покрытых маршрутов в `src/app/api/` (`auth/pin/route.ts`, `reports/export/route.ts`, `reports/period`, `maintenance-plans/*`, `orion/lead/route.ts`) — маршруты есть, e2e на них нет.
7. Подсчёт `npx playwright test --list` разбит по проектам: 3 активных проекта × 38; проект `unauthenticated` собирает 0 тестов (его `testMatch: /login\.spec\.ts/` не находит файлов — `e2e/tests/login.spec.ts` не существует).

Перезапуск: `npx playwright test --list` из корня; `testDir: './e2e'`, так что скрипт-раннер `comprehensive-test.ts` в список не попадает (не матчится `.spec/.test`).

## Не проверено

- **Фактический запуск тестов** — по условию задачи тесты не запускались (`npx playwright test` не выполнялся), проверялся только `--list`. Итог «зелёный/красный» каждого теста не подтверждён.
- **Наличие реальной базы/seed-данных** для `login(@piling.ru)` и фикстур не проверялся — при отсутствии локальной БД многие UI-тесты могут скипаться/падать на setup; это отдельный риск, вне рамок задачи.
- Состояние маршрутов `maintenance-plans`, `reports/export`, `auth/pin`, `orion/lead` после их вызова в e2e не проверялось (e2e на них нет) — юнит-тесты (`__tests__/route.test.ts`) существуют, но в этом отчёте разбирался только e2e-слой.
- Для скрипта-раннера `comprehensive-test.ts` (строки 264-286: история и экспорт) точно не собран в Playwright только на основании `testMatch` по умолчанию; полнота соответствия дефолтному glob не перепроверялась отдельной командой — вывод опирается на его отсутствие в `--list`.
