# W70 — тупики нижней панели шагов («Следующий шаг» / «Завершить смену») в 5 модулях машиниста

Отчёт только для чтения. Новый порядок 07.10.2026 («все действия связать со «Следующим
шагом»; завершить смену во всех модулях») проверен по коду. Ничего не изменялось; создан
только этот файл.

ВАЖНО ПРО ЧТЕНИЕ. Ветка `hermes/q4-0926` отстала от `main` на 11 коммитов, и весь новый
порядок (файлы `shift-next-step.ts`, `step-bar.tsx`) живёт ТОЛЬКО в `main`. Поэтому код
читался через `git show main:<путь>`; **номера строк в этом отчёте относятся к `main`**, а не
к файлам рабочей копии (в рабочей копии этих файлов нет вовсе).

## Итог

Всего находок — 12: **критично 1, важно 5, мелочь 6**. Разбор шёл по 5 модулям × 8 фазам;
матрица «модуль × фаза × кнопка» — в конце раздела «Находки».

Главное: общий расчёт «что дальше» (`shift-next-step.ts`) корректен, но два модуля из пяти
**не выполняют его результат** — кнопка включена, а нажатие ничего не меняет.
- **v2** вообще не связан с панелью: «Следующий шаг» на всех шагах = `onNext={goHome}` —
  кнопка всегда возвращает на текущий же экран (находка 1).
- **v1 и v5** в фазах ADMISSION, предсменных осмотрах и CLOSING посылают `goHome()`, а
  главный экран фазы — это и есть тот же экран: нажатие «Следующего шага» ничего не делает
  (находки 2-4).
- **«Завершить смену» в фазе CLOSING включена** (`finishShift` возвращает `GO_CLOSING`,
  `enabled: true`), но обработчик у v1/v5/v10/v2 только открывает экран закрытия — саму смену
  не закрывает (находки 2, 6). Подпись обещает завершение, действие — навигацию.
- В v5/v7/v10/v2 кнопка реального закрытия смены блокируется общим счётчиком очереди,
  включая отклонённые записи (`FAILED`), которые «Отправить сейчас» не отправляет — тот самый
  класс дефекта, что уже разведён в v1 (находка 5).

Модуль **v7** — единственный, где «Следующий шаг» ведёт к настоящему следующему шагу во всех
фазах; v10 близок к нему.

## Методика (как воспроизвести)

1. `git log --oneline -3`, `git branch --show-current` → `hermes/q4-0926`; `git log main --oneline`
   показал, что новый порядок уже в `main`.
2. `git ls-tree -r --name-only main | grep -iE "shift-next-step|operator-(mobile-app|shift-v2|v5-app|v7-app|v10-app)"`
   → пути модулей. `git diff --stat main -- <пути>` подтвердил: в рабочей копии файлов
   `shift-next-step.ts` / `step-bar.tsx` НЕТ (они добавлены в `main`), поэтому читаю `main`.
3. Версии из `main` выгружены во временную папку вне репозитория
   (`git show main:<путь> > $SCRATCH/...`) и открыты `read_file` — так у находок точные
   номера строк `main`. Прочитаны полностью или в нужных частях:
   - `src/components/piling/operator-mobile/shift-next-step.ts` (154 стр.);
   - `src/components/piling/operator-mobile/step-bar.tsx` (165);
   - `src/components/piling/operator-mobile/operator-mobile-app.tsx` (1098) — оболочка + нижняя панель;
   - `src/components/piling/operator-mobile/ui.tsx` (368) — где рисуется панель (`Screen`);
   - `src/components/piling/operator-mobile/screens/{closing-screen,admission-screen,checklist-screen,work-screen}.tsx`;
   - `src/components/piling/operator-v2/{operator-shift-v2.tsx, step-bar-model.ts, shift-flow.ts, ui.tsx}`;
   - `src/components/piling/operator-v5/operator-v5-app.tsx` (1365) + встроенный `CloseScreen`;
   - `src/components/piling/operator-mobile/v7/{operator-v7-app.tsx, v7-shift.tsx, v7-screens.tsx}`;
   - `src/components/piling/operator-mobile/v10/operator-v10-app.tsx` (1703).
4. `git grep -n -E "nextStep|finishShift|StepBar|goNext|onGoClosing|Следующий шаг|Завершить смену" main -- <модули>`
   — чтобы не пропустить вторую точку подключения панели (в v2 нашлась своя копия модели —
   `step-bar-model.ts`).
5. Проверка очереди: `git grep -nE "FAILED|unsent=|queued\.length|retryFailed" main -- <модули>`
   + `read_file` `use-offline-queue.ts` и `offline-queue.ts` (что делает `flush` с `FAILED`).
6. Замороженные зоны (`src/app/operator/**`, ORION) не читались; сами модули `src/components/
   piling/operator-mobile/**` — заморожены для ПРАВОК, но задача прямо велит их прочитать,
   поэтому они прочитаны (файлы не менялись).

## Не проверено

- **Поведение в браузере (кликовые прогоны) не проверялось** — это чтение кода; выводы о
  «нажатие ничего не меняет» сделаны по обработчикам, а не по экрану. Стоит подтвердить
  Playwright-ом: v2 (нажатие «Следующий шаг» на шаге приёмки) и v1/v5 (CLOSING).
- **Не проверено, попадает ли `FAILED`-запись в очередь на самом деле** при типичном отказе
  (например 409 «Смена уже закрыта»): `offline-queue.ts` помечает `FAILED` для «отказа по
  существу» (строки 378-418), но какие коды сервер реально шлёт на `log-production`, я не
  трассировал. Если на практике `FAILED` не возникает, находка 5 — теоретическая.
- **Не проверено**, доходит ли `state.checklists` до модуля всегда с чек-листом текущей фазы
  (находка 9) — нужен серверный контракт `ChecklistView[]`; без него неизвестно, достижим ли
  сквозной `CloseScreen` в v5.
- **v10 `ScreenWork`/`ScreenToday`** прочитаны частично (только переходы панели и лестница);
  встроенных кнопок в них я не разбирал до конца, поэтому в матрице v10 отмечен «✓» по
  навигации, а не по полноте действий на экране.
- **Модуль v2** — замороженный кандидат; правки в нём (если решат) требуют решения владельца,
  я их не предлагал как обязательные.
- Файлы в рабочей копии `hermes/q4-0926` **отличаются** от `main` (в них нет панели вовсе);
  отчёт описывает только `main`.
