# AU189-S6 — Аналитика: окна недели и месяца (границы недели/месяца/смены, часовой пояс)

Версия кода: `git rev-parse HEAD` = `641a7786105c97dfd8b117042791f6ad94bd7f4f` (ветка `hermes/q4-0926`).
Тип работы: независимый аудит по коду, только чтение. Код приложения не изменялся.
Frozen-зоны (`src/app/orion/**`, `src/components/orion/**`, варианты экрана оператора) не открывались.

## Резюме

1. Ни одной «критичной» находки нет: все окна считаются целыми днями-строками, утечек и потери денег не найдено.
2. 8 находок уровня «важно», 7 — «мелочь». Главная беда — не одна ошибка, а **расхождение определений одного и того же слова**: «неделя», «месяц», «сегодня» на разных экранах означают разное.
3. Три разных «часовых пояса суток» живут рядом: `Europe/Moscow` захардкожен в аналитике и журнале отчётов, пояс браузера — на экране аналитики парка, пояс из настроек тенанта — только в техготовности (ТО) и журнале свай. В проде тенант один и он МСК, поэтому сегодня расхождения не видно; оно проявится при втором тенанте.
4. Тренд по объектам (Monday-бакеты) читается из проекции `SiteWeeklyTrend`, а KPI на том же экране — напрямую из `Report`; экраны могут показывать разные числа для одного периода.
5. Единственное «окно недели», которое действительно выравнивается по календарю (ISO, с понедельника) — это тренд; фильтр «7 дней» в журнале и период KPI — скользящие 7 суток. Календарного месячного окна в коде нет вообще: «месяц» = 4 недельных бакета или «30 дней».
