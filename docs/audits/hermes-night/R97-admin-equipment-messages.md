## Что видит человек: сценарий за сценарием

### 1. Открыть раздел «Установки»

Успех: заголовок `Установки` + подпись «Центр управления парком техники · данные из отчётов» (`admin-equipment.tsx:100-105`), KPI-полоса `Всего / В работе / Простой / В ремонте / Операторы на смене / ТО` (`equipment-stats-bar.tsx:22-29`), фильтры и список (`Плитки`/`Таблица`/`Конструктор`).

- **403.** Список берётся не из `/api/equipment`, а из снимка `GET /api/monitoring/fleet` (`use-fleet.ts:19`), у которого нет `assertCan` — только `requireAuth` (`monitoring/fleet/route.ts:13-34`). Поэтому 403 на списке недостижим: даже в режиме «Действую как OPERATOR» снимок отдаётся (суженный до экипажа оператора). Отказ приходит только на детальную карточку (п. 3).
- **5xx / обрыв.** `useFleet` кладёт в `error` строку `Сервер вернул ${res.status}` (`use-fleet.ts:21`) или `err.message` (браузерное «Failed to fetch», `:26-28`); экран заменяется на «Не удалось загрузить парк техники: <...>.» с кнопкой «Повторить» (`admin-equipment.tsx:82-92`). Код статуса читателю ничего не говорит, а слово «права» отсутствует.
- **Пусто.** «Нет установок» (парк пуст) либо «Нет установок под выбранные фильтры» + «Сбросить фильтры» (`admin-equipment.tsx:133-144`) — сделано верно, оба случая разведены.
- **401.** `authFetch` делает logout в store (`api.ts:56-69`), раскладка уводит на `/login`. Сообщения об истечении сессии нет.
- **409** к чтению неприменим.
