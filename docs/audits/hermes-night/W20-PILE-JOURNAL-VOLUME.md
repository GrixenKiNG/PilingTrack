# W20-PILE-JOURNAL-VOLUME — журнал забивки после W14: объём, страницы, итоги

## Итог

Всего находок: 10 — 2 критично, 6 важно, 2 мелочь.

Проверено на локальной базе `localhost:5435/pilingtrack_test` (tenant `orion`, `SET app.current_tenant='orion'`): `PileWork` = 280 строк, `SUM(count)` = 3025 свай; `PilePassport` = 10 штук (270 строк без паспорта, 3015 свай).

Топ-5:
1. **критично** — при усечении (`truncated`) титул журнала считается только по первым 500 СТРОКАМ, но подаётся как итог периода и так же уходит в подшиваемый `.xlsx` (total по неполной выборке).
2. **критично** — выгрузка `.xlsx` жёстко ограничена теми же 500 строками: полный нормативный журнал (СП 45.13330) выгрузить нечем.
3. **важно** — в титуле смешаны единицы: «Свай в журнале» = сумма `count` (сваи, 3025), а «Принято/Не разобрано/На добивку» = число СТРОК и только по паспортам (1/8/1); 270 строк (3015 свай) без паспорта не попадают ни в один счётчик.
4. **важно** — «Свай в журнале» не сходится с плиткой «Сваи» главной панели: разные поля даты и черновики в журнале. За сентябрь: журнал 717 (все) / 708 (без черновиков) против панели 626; за всё время 3025 против 3003.
5. **важно** — нет индекса по `(tenantId, occurredAt)` / `receivedAt`; запрос журнала идёт `Seq Scan` по `PileWork` (локально 0,16–0,32 мс на 280 строках, но O(таблица) на боевом объёме).

## Не проверено

- Усечение `truncated=true` и его влияние на титул/выгрузку **не воспроизведено на данных**: локально 280 строк < 500. Находки 1, 2, 6, 8 — из чтения кода + арифметики, не из прогона с усечением.
- Боевой объём и точное поведение `truncated` на проде — **не проверено** (доступа к боевой БД нет, работать с ней запрещено).
- `EXPLAIN` снят на 280 строках (0,16–0,32 мс); на объёме, где план сменился бы, **не проверено** (нет prod-данных). Планировщик на малой таблице склонен к `Seq Scan` — отсутствие индекса подтверждено каталогом `pg_indexes`, а не только планом.
- Сравнение за сентябрь использовало границы МСК (`2026-08-31T21:00Z`…): `TenantSettings` локально пуст, часовой пояс брался по умолчанию. Если фактический пояс тенанта иной — числа за период сместятся (на итоги «за всё время» это не влияет).
- Тесты (`pile-journal.test.tsx`, `pile-passport.service.test.ts`) на предмет усечения/единиц **не прогонялись** — задача read-only и требует отчёта, не проверки тестов.
