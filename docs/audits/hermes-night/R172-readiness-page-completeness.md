## Итог

- Находок **12**: **критично — 0**, **важно — 6**, **мелочь — 6**. Потери данных как таковой нет;
  проблема в том, что сервер **молча обрезает** наборы (`take` без `limit+1` и без курсора), а экран
  считает плитки/сводки по **загруженной странице**, принимая её за весь набор, — то есть часть данных
  не просто не показана, а **неверно посчитана** (счётчики, проценты, дельты «к предыдущему периоду»).
- Что **работает корректно** (не переоткрываю): авторитетная готовность парка/центра/отчётов считается
  по `currentReadiness`, а он отдаётся **без лимита** (`api/readiness/current/route.ts:20-27`, одна
  строка на установку) — сводка парка не обрезана; выгрузка CSV (`api/readiness/export/route.ts:43,59,102`)
  отдаёт **весь** набор без `take` и расходится со списками экрана (см. №2/№3/№5); журнал инструктажей —
  единственный, кто **честно** сообщает об усечении (`briefings-screen.tsx:99,117,381-386` +
  `operator-mobile/application/briefing-journal-query.ts:127-130`) — это образец, которого нет у списков
  техготовности; счётчики `readiness-centre` по блокерам теперь по тонам (`readiness-centre.tsx:224-242,786-789`),
  дефекты/наряды имеют на сервере настоящий `total`/`hasMore`/`nextCursor` (см. №2/№3) — экран их не читает.
- Топ-5:
  1. **важно** — история готовности (`/api/readiness/history?limit=500`) читается **без пагинации**
     (`api/readiness/history/route.ts:39`, `api/client.ts:211`), а «Динамика за 30 дней» и дельта
     «к предыдущему периоду» строятся по ней (`reports-screen.tsx:152-157`). Больше 500 снимков — часть
     окна и весь прошлый период исчезают молча (№1).
  2. **важно** — счётчики нарядов «Всего нарядов», «из N нарядов», доли-полосы — по `props.permits`
     (`permits-screen.tsx:177,183,196,201`), а он обрезан до 200 (`api/client.ts:176`), хотя сервер уже
     отдаёт верный `page.total`/`hasMore`/`nextCursor` (`work-permits/route.ts:55`, `permits/queries.ts:42-53`).
     >200 нарядов — плитка и проценты врут (№2).
  3. **важно** — «открытых N» на журнале дефектов и «Критические дефекты/открытых замечаний: N» на
     «Обслуживании ТО» — по `props.defects`, обрезанному до 200 (`defects-panel.tsx:83,149`,
     `maintenance-screen.tsx:63,130`, `api/client.ts:190-192`) (№3).
  4. **важно** — список смен **вообще без пагинации**: маршрут не принимает `cursor` (`shifts/route.ts:24`),
     репозиторий делает `take: limit` без `+1` (`shift-repository.ts:81`), ответ отдаёт только `page.total`
     (`shifts/queries.ts:10`). KPI «Смен сегодня» и метрики отчётов («Смен допущено/Отказано») считаются по
     обрезанным 200 (`shifts-screen.tsx:56-61,186`, `reports-screen.tsx:135-140`) (№4).
  5. **важно** — парк в модуле собирается из `/api/equipment?limit=100` (`to-module.tsx:430`), а маршрут
     ограничен 100 и сортирует по имени, игнорируя `nextCursor` (`equipment/route.ts:20`,
     `equipment-query.service.ts:499-501`). При >100 установках машины за первой сотней исчезают из парка
     целиком (не как «не подтверждено»), хотя истинное число уже есть в `bootstrap.counts.equipment`
     (`bootstrap-query.ts:168-170`) (№5).
