## Что проверено и закрыто (чтобы не переоткрывать)

- **Текст отказа доходит дословно — закрыто.** `use-site-mutations.ts:317` → `extractApiError` (`:56-63`) → `apiErrorMessage` берёт поле `error` (`api-error-message.ts:19-22`); тест `use-site-mutations.test.ts:85-96` фиксирует именно серверную фразу для удаления узла.

- **Защита от двойного DELETE — закрыто и не регрессировало.** `busyRef.current` ставится синхронно в `hierarchy-tree.tsx:189` до первого `await`, поэтому второй клик до ответа запрос не повторяет (F-R113-1).
- **Описание окна и вложенность считаются по дереву — верно.** `childClusters`/`childPickets` берутся из `tree` (`hierarchy-tree.tsx:93-97,125-128,151-154`), т.е. при повторном открытии окно показывает те же имя и предупреждение — контекст восстанавливается заново из дерева, теряется только факт прошлого отказа.
- **Сервер отвергает удаление только по выработке/отчётам — подтверждено кодом и тестами.** `assertNoSubtreeProduction` (`site-admin-command.service.ts:381-394`), тесты `src/modules/sites/__tests__/site-hierarchy-guards.test.ts` (коммит `c7571679`).
