# N17-21-PERMIT-OVERDUE-FILTER-UI — фильтр «Просроченные» и кнопка «Закрыть наряд»: READ-ONLY аудит

## Итог

Независимый аудит экрана нарядов. Версия: `git rev-parse HEAD` = **fdb7e97017768f766da51b843191b3cbfb1037ec**, ветка `hermes/code-1011`.
Код приложения не менялся, создан только этот отчёт.

- **Находок: 11** — критично 0, важно 2, мелочь 9 (из них 1 — ГИПОТЕЗА).
- **Фильтр «Просроченные» устроен корректно:** это `APPROVED` + `PENDING_APPROVAL` с `validTo <= now`; граница (`<=`) и состав совпадают с ночным планировщиком. `EXPIRED` и `CLOSED` в него не попадают (ПРОЙДЕНО, вопрос 1).
- **Кнопка «Закрыть наряд» на просроченном наряде пишет `closeReason='WORK_DONE'`, а не `VALIDITY_ELAPSED`** (`work-permit-repository.ts:265-271`): причина неверна, комментарий уходит только в аудит, а в снимке готовности пропадает признак «срок вышел» (важно, вопрос 2).
- **Права совпадают:** видимость кнопки `entities.permit.edit` = серверное `readiness.permit.edit`; диспетчер/оператор/помощник кнопку не видят и получают 403 (ПРОЙДЕНО, вопрос 3).
- **Счётчики:** лента дашборда и метка фильтра считают одним и тем же `actionableOverduePermits`, но на разных наборах данных — могут расходиться (мелочь, вопрос 4).
- **Главное:** ручное закрытие просроченного `APPROVED`-наряда выдаёт «работы закончены» за факт, которого никто не подтверждал (`permits-screen.tsx:460` спрашивает «Работы закончены?»), и подменяет причину закрытия.

## Ответы на вопросы задания

**Вопрос 1 — что попадает в фильтр «Просроченные».** В фильтр `OVERDUE` попадают только `APPROVED` и `PENDING_APPROVAL` с `validTo <= now`; источник — `actionableOverduePermits` (`permit-role-steps.ts:29-35` через `permits-screen.tsx:112,149`). `EXPIRED` и `CLOSED` в него не входят (хотя `isOverduePermit` для `EXPIRED` возвращает `true`, `permit-role-steps.ts:18-22`): `EXPIRED`/`REVOKED` показывает фильтр «Заблокированные» (`permits-screen.tsx:148`), `CLOSED` — «Закрытые» (`:150`). Граница у фильтра `<=` (`permit-role-steps.ts:21`) совпадает с отбором планировщика `validTo: {lte: now}` при `state in ('APPROVED','PENDING_APPROVAL')` (`scheduler.ts:130-131`). Статус ПРОЙДЕНО.

**Вопрос 2 — что отправляет «Закрыть наряд» на просроченном наряде.** Кнопка показывается для `APPROVED` при `validFrom <= now` и праве `permit.edit` (`permits-screen.tsx:303,324`) — то есть на просроченном `APPROVED` она есть всегда. По нажатию открывается диалог и POST `/close` с телом `{expectedVersion, reason}`; на сервере `repository.close` жёстко пишет `closeReason: 'WORK_DONE'` (`work-permit-repository.ts:269-270`), а комментарий идёт только в аудит (`commands.ts:246-248,307`). Пользователь видит toast «Наряд закрыт» (`permits-screen.tsx:179`); после обновления строка исчезает из «Просроченных»/«Все», статус в «Закрытых» — «Закрыт», не «Закрыт по сроку» (`permits-screen.tsx:303,320,147`). Статус ПРОЙДЕНО.

**Вопрос 3 — роли.** Кнопку видит носитель `bootstrap.capabilities.entities.permit.edit` (`permits-screen.tsx:303,324`), который равен `can('readiness.permit.edit')` (`bootstrap-query.ts:268`). Сервер требует то же право `readiness.permit.edit` (`commands.ts:219` → `assertPermitEditor` `:68-72`). По умолчанию право есть у ADMIN, MECHANIC, SAFETY_ENGINEER и нет у DISPATCHER, OPERATOR, ASSISTANT (`capability-defaults.ts:65-74,75-94,106,107-118,128-135`). Прямой POST от роли без права даёт 403 «Нет права редактировать наряд-допуск». Кнопка и серверная проверка совпадают. Статус ПРОЙДЕНО.

**Вопрос 4 — счётчик дашборда и число в фильтре.** Лента «Требует решения сейчас» берёт `actionableOverduePermits(input.permits, now)` (`dashboard-attention-items.ts:41-53`); метка фильтра и алерт считают `overduePermits.length` тем же `actionableOverduePermits` (`permits-screen.tsx:112,246,294`). Функция одна, но данные разные: у экрана `props.permits` отфильтрованы серверными фильтрами (`status/from/to/risk`, `to-module.tsx:463`), у ленты дашборда — нет (`dashboard-attention.tsx:22`). На одинаковых данных числа совпадают; при выбранном на экране серверном статусе могут расходиться. Плитки KPI при этом считают иначе (см. находку №2/№4 таблицы). Статус ПРОЙДЕНО (совпадение) с оговоркой.

**Вопрос 5 — пустой список, ошибка загрузки, повторное нажатие.** Пустой список: «По выбранным условиям наряды не найдены.» (`permits-screen.tsx:308,329`). Ошибка загрузки нарядов: `setPermits([])` и в общий список проблем пишется «Техготовность» (`to-module.tsx:507,519-534`); сам экран нарядов состояния ошибки не имеет и покажет то же «не найдены». Повторное нажатие: после закрытия строка исчезает; повтор для той же версии отбивается сервером — 422 «Наряд закрыт — действие «закрыть» сейчас недоступно» (`transitions.ts:10,33-40`) или 409 (`commands.ts:240-241`), второй записи нет. Статус ПРОЙДЕНО.
