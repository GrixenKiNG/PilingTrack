# N17-43-CSV-FORMULA-INJECTION — выгрузки CSV: экранирование ячеек с формулами

## Итог

- Найдено: **8** — критично **0**, важно **0**, мелочь **8**.
- **Главное: подстановка формул (CWE-1236) в CSV закрыта в обоих живых экспортёрах.**
  Все ячейки данных проходят через эскейпер: отчёты — `report-export.service.ts:40-45`,
  техготовность — `csv-export.ts:44-48`; метаданные файла готовности тоже
  (`csv-export.ts:67-75`). Кавычки удваиваются, поле оборачивается в кавычки,
  ведущие `= + - @` (и табуляция/возврат каретки) обезвреживаются апострофом,
  обычные числа не трогаются.
- **Excel (.xlsx) не нуждается в апострофе:** ячейки-строки пишутся как
  `t="inlineStr"` (`xlsx-writer.ts:79-80`), а формула в OOXML — это элемент `<f>`,
  которого в файле нет. Комментарий оператора и «Примечание» уезжают текстом.
- Пункты задания: (1) да, `= + - @ \t \r` экранируются; (2) да, кавычки удваиваются,
  перенос строки внутри поля остаётся внутри кавычек; (3) **общей функции нет — две
  независимые реализации** (находка 1); (4) пользовательские поля (ФИО, название
  объекта, комментарий простоя, примечание, объём работ наряда) попадают в выгрузку
  уже обезвреженными — таблица ниже; (5) тест на формулы есть в обоих модулях.
- Топ-5: 1) два разных CSV-эскейпера вместо одного помощника; 2) .xlsx защищён
  «по устройству формата», отдельного теста-инварианта нет (есть только e2e);
  3) у CSV техготовности формулы не проверяются e2e, только unit; 4) вектор
  возврата каретки (`\r`) не закреплён юнит-тестом ни в одном наборе; 5) клиентский
  `downloadCsv` игнорирует свой аргумент `_rows` и молча уходит на серверный экспорт.
