## Что видит машинист: сценарий за сценарием

Тексты приведены дословно; «дубль» — буквальное совпадение фразы в двух блоках.

### 1. Запись → обрыв сети (`QueuedOffline`)

Путь: `api.ts:501-511` (`enqueue`) → `postCommand` бросает `TypeError` → `api.ts:545-548` `markAttempt(..., 'Failed to fetch', false)` (строка английская, `PENDING`) → `throw QueuedOffline('Выработка','при связи')` → `operator-mobile-app.tsx:399` `setNotice(error.message)`.

- строка состояния: «Офлайн · На устройстве ждёт отправки: 1» (`operator-status-strip.tsx:21-24`), либо, если флаг браузера врёт, «Ожидает отправки: 1 · Передадим автоматически, как только сервер ответит» (`:29-31`);
- плашка очереди: «На устройстве: Выработка. Отправим, когда появится связь.» (`offline-queue-banner.tsx:80-85`); английский `lastError` отсечён фильтром кириллицы (`:58-59`) — верно;
- уведомление: «Выработка: сохранено на устройстве, отправим при связи» (`operator-mobile-app.tsx:399`).
- Дубль: «отправим при связи» (уведомление) и «Отправим, когда появится связь» (плашка) — две почти одинаковые фразы рядом (находка 11).

### 2. Запись → 400 «Паспорт заполнен не полностью» с подробностями

Источники текста: `production.ts:286` (паспорт, команда откладываемая), `checklist.ts:127` (чек-лист, команда **не** откладываемая); форма `details` — `{field,message}` (`pile-passport.ts:100-101`) и `{itemId,message,label}` (`checklist-run.ts:14-20`), отбор — `api.ts:99-108`.

- Откладываемая (паспорт): `api.ts:537-544` → `FAILED`, `lastError = 'Паспорт заполнен не полностью'`.
  - строка состояния: «Нужно проверить: 1 · Сервер отклонил запись — причина показана ниже» (`:12-16`);
  - плашка: «Выработка не принята» + «Паспорт заполнен не полностью» (`offline-queue-banner.tsx:113,117`);
  - форма паспорта: `ErrorNote` «Паспорт заполнен не полностью» + список полей (`pile-passport-form.tsx:391`, `api.ts:99-108`).
  - Дубль: одна и та же фраза дважды (карточка + `ErrorNote`) — находка 3.
- Неоткладываемая (чек-лист): только `ErrorNote` на экране чек-листа (`checklist-screen.tsx:300`); строка состояния при этом зелёная «Всё отправлено · очередь на телефоне пуста» (`:34-39`) — формально верно (очередь пуста), но рядом с красным отказом читается двусмысленно (находка 13).
- Поправка (`correct-production`, откладываемая): отказ виден только карточкой вверху (`entries-list.tsx:32-62` — экран не принимает `error` вовсе), находка 12.

### 3. Запись → 409 «Смена уже закрыта»

- **Перечитывание успешно** (`operator-mobile-app.tsx:422-429` → фаза `CLOSED`):
  - строка состояния: «Нужно проверить: 1 · Сервер отклонил запись — причина показана ниже»;
  - плашка: «Выработка не принята» + «Смена уже закрыта»;
  - экран «Смена закрыта»: панель «Принято сервером»/«Смена закрыта сервером» (`closing-screen.tsx:189-199`) и `ErrorNote` «Смена уже закрыта» (`:187`).
  - Дубль фразы — находка 3. Ложных «Записано» нет: `STALE_SCREEN_NOTICE` на 409 не ставится (`operator-mobile-app.tsx:74-75,426`) — верно.
- **Перечитывание неуспешно (503)**: добавляется уведомление «Экран не обновился — обновим, как появится связь.» + кнопка «Обновить» (`:74-75,426,845-849`). Связь при 503 есть, и повтор идёт по таймеру 15 с независимо от `navigator.onLine` (`:286-305`) — обещание «как появится связь» неточно (тот же класс, что находка 4).

### 4. Запись → 503 HTML от прокси

`api.ts:180-197`: `response.json()` на HTML даёт `null`, `!ok` → «Сервер временно недоступен (код 503).» (`:155-157`); для откладываемой команды `withQueuedFailureNote` дописывает «Запись сохранена — отправим автоматически.» (`:474-479`), затем `:545-548` → `PENDING` + `throw QueuedOffline(..., 'при связи')`.

- строка состояния: «Ожидает отправки: 1 · Передадим автоматически, как только сервер ответит» (`:29-31`) — точно по причине;
- плашка: «На устройстве: Выработка. Сервер не принял запись, повторим автоматически.» + строка причины «Сервер временно недоступен (код 503). Запись сохранена — отправим автоматически.» (`offline-queue-banner.tsx:84,87`);
- уведомление: «Выработка: сохранено на устройстве, отправим при связи» (`operator-mobile-app.tsx:399`).
- Противоречие: уведомление отправляет ждать **связь**, а плашка и строка — ждать **сервер**; связь есть (находка 4). В одной плашке при этом «автоматически» сказано дважды: «повторим автоматически» + «отправим автоматически» (находка 8).

### 5. Запись → 403 CSRF

`api.ts:189-193` → `ApiError(403, CSRF_REJECT_MESSAGE, …, 'csrf')`.

- Откладываемая команда (`api.ts:532-536`): запись остаётся `PENDING`, `lastError` = CSRF-текст.
  - строка состояния: «Ожидает отправки: 1 · …как только сервер ответит»;
  - плашка: «Сервер не принял запись, повторим автоматически.» + «Запрос отклонён проверкой безопасности. Обновите страницу — запись сохранена на телефоне и уйдёт после обновления.» (`offline-queue.ts:158-159`);
  - `ErrorNote` на экране: тот же CSRF-текст (`operator-mobile-app.tsx:403-404`). Дубль (находка 3).
- Команда-переход (`close-shift` и др.): в очередь ничего не кладётся, но текст тот же — «запись сохранена на телефоне и уйдёт после обновления» **неверно**: ни сохранения, ни автоотправки (находка 1).

### 6. Запись → 401 (истёкшая сессия)

Ответ сервера — русский: `command/route.ts:184` «Войдите в систему».

- Откладываемая: `api.ts:545-548` → `markAttempt(AUTH_WAIT_MESSAGE)` → `QueuedOffline(...,'после входа')` → `operator-mobile-app.tsx:384-389`: уведомление «Сессия истекла. Записи сохранены на телефоне и уйдут после входа.» и переход на `/login` через 2,5 с.
  - плашка: «На устройстве: Выработка. Войдите снова — запись отправится после входа» (`offline-queue-banner.tsx:81-82`, `offline-queue.ts:146`);
  - строка состояния: «Ожидает отправки: 1 · Передадим автоматически, как только сервер ответит» — «сервер ответит» вместо «после входа» (находка 7).
- Команда-переход: `run()` ветку `QueuedOffline` не получает, редиректа нет (`operator-mobile-app.tsx:360-402` — переход к `/login` есть только у `QueuedOffline.reason === 'auth'`, у `reload` `:229-232` и у загрузки вопросов `knowledge-screen.tsx:65-69`). Машинист остаётся на экране с `ErrorNote` «Войдите в систему» и без действия — находка 5.

### 7. Загрузка состояния → 502 HTML; → 403

- 502 HTML: `api.ts:155-157` → «Сервер временно недоступен (код 502).» → `operator-mobile-app.tsx:244-245` `serverFault = true` → экран «Сервер не отвечает» + «Связь есть, но сервер временно не работает…» (`:487,493-495`). Сверху — зелёная «Всё отправлено · очередь на телефоне пуста» (`:478`, `operator-status-strip.tsx:34-39`) — находка 9.
  - Если прокси отдал **200** с HTML (страница-перехватчик): `api.ts:203-205` → «Ответ пришёл не от сервера приложения — возможно, сеть требует входа (Wi‑Fi). **Запись осталась на устройстве.**» Никакой записи при чтении состояния нет; для экрана вопросов ту же фразу уже переписали отдельно (`api.ts:342-343`) — находка 10.
- 403: `state/route.ts:23` «Экран доступен только машинисту» → `operator-mobile-app.tsx:236-239,440-473`: панель с текстом, пояснение про роль и кнопка «Войти другим пользователем». Выход есть — верно.

### 8. Снимок: PUT 413; подтверждение 422

- Получение ссылки `POST /api/media` (`api.ts:588-609`): тело читается `grant.json()` и `ApiError` получает **сырое** `error` сервера (`:608`) — сюда попадают английские строки CSRF (`csrf-protection.ts:78`) и `requireAuth` (`lib/auth.ts:166`); `operatorErrorText` покажет их как есть (`api.ts:59-73`) в `ErrorNote`/подписи снимка (`checklist-screen.tsx:457`, `incidents-tab.tsx:290-292`). Находка 2.
- PUT 413 → «Снимок слишком большой. Сделайте фото заново с меньшим качеством.» (`api.ts:562-567,620`) — текст верный, дублей нет.
- Подтверждение 422 → русский текст сервера показывается (`media-service.ts:244,268-271`), иначе общая фраза (`api.ts:639-644`). Если приходит 403 CSRF, он не кириллический и подменяется «Снимок не подтверждён сервером» — подсказка «обновите страницу» теряется (находка 14).

### 9. В очереди одновременно PENDING (сеть) и FAILED (отказ)

- строка состояния: только «Нужно проверить: 1 · Сервер отклонил запись — причина показана ниже» (`:11-17`) — про вторую, ждущую запись не сказано ничего (находка 6);
- плашка: блок ждущих «На устройстве: Выработка. Отправим, когда появится связь.» (`offline-queue-banner.tsx:78-90`) и отдельные карточки «… не принята» (`:91-93,110-118`) — здесь всё различимо, порядок и счётчики верные;
- экран закрытия смены: панель «На телефоне ждёт отправки: 1» (`closing-screen.tsx:83-93`) и красная «Сервер не принял 1 запись» (`:95-109`), футер отдаёт приоритет ждущим (`:64-78`) — согласовано; противоречие только со строкой состояния.
