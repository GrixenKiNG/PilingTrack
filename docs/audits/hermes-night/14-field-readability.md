# Аудит 14: читаемость текста на полевых экранах (телефон/планшет)

Дата: 2026-09-25 · Ветка: `hermes/q3-0925` · Агент: hermes (код: `deepseek/deepseek-v4-flash-0731`)

## Итог

Проблема подтверждена и системна. Достоверные факты шрифтовой шкалы: `text-3xs` = 10px, `text-2xs` = 11px, `text-xs` = 12px (токены в `src/app/globals.css:79-82`).

Ключевой вывод по обёртке: **все** экраны `src/components/piling/to/readiness/screens/**` рендерятся внутри `ReaderReadinessReferenceUi`, у корня которой стоит класс `tech-readiness-module` (`readiness-reference-ui.tsx:87`; та же оболочка, что и у `TechReadinessModule`). Поэтому глобальный «лифт» 3xs/2xs → 12px из `globals.css:340-345` действует на них **только на телефонах (max-width: 639px)**. На **планшете** (ширина > 639px, incluso при `pointer: coarse`) бампа шрифта **нет** — есть только подъём тач-целей 44px (globals.css:334-337). Итог: диспетчер на планшете видит кнопки и статусы в 10–11px. Это главный пробел.

Вторая группа (report-form, inspections, maintenance, report-history, equipment-tile) **вообще не внутри** `tech-readiness-module` — для них лифта нет ни на телефоне, ни на планшете; там 2xs = 11px и 3xs = 10px остаются как есть. Мастер (форма сменного отчёта, осмотры) и механик (заявки/задачи ТО) на телефоне получают самый мелкий текст.

Найдено (выборка — см. таблицу и приложение):
- **критично: 4** (кнопка-решение или решающее значение < 12px):
  1. `shifts-screen.tsx:202` — кнопки допуск-решения диспетчера 10px (планшет);
  2. `defects-panel.tsx:233,236,243` — «Взять в работу / Отклонить / Решить» 11px;
  3. `permits-screen.tsx:282-285` — «Проверить и согласовать» 11px;
  4. `safety-screen.tsx:296-304` и `documents-screen.tsx:160` — кнопки 11px.
- **важно: 32** (статус/метаданные ≤ 11px, вкл. таблет-кейс готовности и 11px-бейджи на телефоне вне обёртки);
- **мелочь: 4** (декор/справка/метки).

Итого в таблице: 40 строк. Полный перечень строк `path:line` с пометкой класса — в приложении.

## Методика

1. `grep -rnE 'text-(3xs|2xs|xs)\b|text-\[[0-9]+px\]'` по всем файлам области: `src/components/piling/report-form/**`, `inspections/**`, `maintenance/**`, `to/readiness/screens/**`, `report-history.tsx`, `admin-equipment/equipment-tile.tsx`. Зафиксированы все вхождения с номерами строк.
2. Отдельным grep проверено `text-[Npx]` с N<13 — **в области ни одного** (только классы).
3. Подсчёт вхождений каждого класса по файлам (для таблицы и приложения).
4. Определение обёртки: `grep -rn 'tech-readiness-module' src` → класс встречается в `globals.css` и на корне `readiness-reference-ui.tsx:87` + как селектор в `tech-readiness-module.tsx:99`. Прочитаны `to-module.tsx:728-798` (обе ветки рендерят `referenceUi` внутри `.tech-readiness-module`), подтверждено правило из `globals.css:334-345`.
5. Для каждого класса-кандидата открыт контекст (read_file) и определён смысл текста: решающая кнопка, значение/статус для решения, метаданные или декор.
6. Принадлежность к пользователю: `grep -rln` по точкам входа (`src/app/(app)/inspections/**`, `admin-equipment.tsx`, `admin-dashboard-bits.tsx`, `(app)/history/page.tsx`). Замороженные зоны оператора/ORION не затрагивались (по AGENTS.md).

Ограничения: рендер-скриншот в конкретном браузере не делался; выводы о «видимости» — по токенам CSS и расположению относительно обёртки. Значения цветов взяты из `globals.css` (`--muted-foreground: oklch(0.5 0 0)` на `--muted: oklch(0.965 0 0)` → контраст серого по серому низкий по построению).

## Не проверено

- Фактический рендер на устройствах (скриншоты) не делался — выводы по CSS-токенам и структуре обёртки, а не по браузеру. Если нужна уверенность «в поле», нужен Playwright с системным Chrome в viewport планшета/телефона.
- Точная ширина планшета, на которой «съезжает» тот или иной экран в mobile-карточку (у части экранов свои `md:`-точки) — по месту не проверял; проверял только глобальную обёртку.
- Контраст серого на сером (`text-muted-foreground` на `bg-muted`) описан как системный факт (токены из globals.css), но численных измерений WCAG на каждом экране нет.
- Экран `settings-workspace` частично скрыт `xl:` (desktop-only) — на планшете не всегда показывается; отметил, но фактическую раскладку на 800-1024px не снимал.
