## Итог

Аудит: как меняется оператор/помощник бригады, что это делает с ОТКРЫТОЙ сменой, с допуском по документам и что остаётся в журнале изменений.
Найдено 13 находок: **2 критично**, **5 важно**, **6 мелочь** (по моей классификации, обоснование в таблице).

Смена оператора бригады — это правка одной колонки `Crew.operatorId`. Она не трогает открытую смену (`Shift` не знает оператора, кроме `startedById`), не перепроверяет допуск и никого не уведомляет. Отсюда главная проблема:

1. **критично** — если оператора бригады сменили (или бригаду расформировали) при открытой смене, смена «осиротела»: старый машинист уже не в бригаде (его экран пуст), новый блокируется как «смена чужого машиниста». Сдать/закрыть её с телефона не может никто; диспетчер может только ОТМЕНИТЬ её, работа за день остаётся без отчёта.
2. **критично** — пуск смены не проверяет, что установка закреплена за тем, кто пускает: любой `OPERATOR` с правом `readiness.shift.authorize` (есть у всех) может заявить `request-acceptance` и запустить подготовленную чужую смену.
3. **важно** — допуск по документам берётся у оператора АКТИВНОЙ бригады; если активной бригады нет, проверка допуска молча пропускается (`crewOperatorId → null`), и смену можно пустить без допуска.
4. **важно** — правка состава бригады задним числом меняет прошлые документы: «Помощник» в PDF/отчёте берётся живой связью `Report → Crew → CrewAssistant`, а состав на каждой правке перезаписывается (`deleteMany` + `createMany`).
5. **важно** — бригаду можно закрепить за неактивным (уволенным) машинистом: API проверяет только роль `OPERATOR`, но не `isActive`; установка оказывается занятой и недоступной.
