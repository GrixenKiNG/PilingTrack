# N1021-G6 — проглоченные ошибки (catch без ответа вызывающему)

Область: `src/modules/**`, `src/core/**`, `src/services/**`, `src/lib/**` (только чтение).

## Итог

- Просканировано 589 файлов в 4 каталогах, найдено **142 catch-блока** (~123 в прод-коде, ~19 в `__tests__`).
- По классам: **критично — 0, важно — 6, мелочь — 11**, «безопасно (по замыслу/кэш/degrade)» — 24 строки, честные rethrow/перепаковки ошибки — 26 (не проблема).
- «Пустых» catch (только комментарий или вообще ничего) — 8 в прод-коде; catch с одиночным `return null/false/undefined/[]/0` — 17; catch «только лог» — 16; остальные осмысленно ветвятся или перепаковывают ошибку.
- Топ-5: (1) сбой записи в DLQ теряет событие навсегда — `src/core/outbox/dead-letter-queue.ts:125`; (2) тихая потеря записей аудита — `src/modules/reports/application/event-handlers.ts:434`; (3) непрочитанные конфиги Telegram → все уведомления молча пропадают — `src/core/notifications/telegram.ts:67`; (4) монитор «обнуляет» метрики дрейфа при сбое — `src/core/observability/lag-monitor.ts:200`; (5) fail-open проверки отзыва сессии — `src/services/auth/session-service.ts:155`.
- Почти каждое глотание снабжено комментарием-обоснованием, но значительная часть глотаний всё равно остаётся «только в логе» — без метрики или алерта, а иногда и на уровне `debug`, невидимом в проде.

## Методика

1. Node-скрипт (запущен вне репозитория, репозиторий не изменял): во всех `.ts/.tsx` четырёх каталогов найдены вхождения `catch`, тело блока извлечено скобочным матчингом (с учётом вложенных `try` и строковых литералов), классифицировано: пустое / одиночный `return null|undefined` / только `logger.*` / rethrow / прочее. Получен полный список всех 142 тел, просмотренных вручную.
2. Контрольный ripgrep: `\.catch\(\s*\(\)\s*=>` (стрелочные формы, скрипт их обрабатывал по-другому), `catch \{` как перекрёстная проверка, а также точечные поиски потребителей заглушенных результатов: `recordAuditFeedbackFailure`, `\.getLeader\(`, `invalidatePattern`, `report_analytics_status_mismatch_total`.
3. Каждый кандидат открыт в исходнике с контекстом (30–80 строк) и попал в таблицу только если цитата сверена с файлом. Классификация «опасно/безопасно» — по последствию (потеря записи, молчаливый отказ/пропуск проверки доступа, устаревшие данные), с учётом комментариев-обоснований в коде. Замороженные области (экраны оператора, ORION) не анализировались; auth-файлы только читались.
