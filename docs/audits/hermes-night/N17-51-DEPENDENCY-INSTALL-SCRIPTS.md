# N17-51-DEPENDENCY-INSTALL-SCRIPTS — скрипты установки зависимостей

- Версия (git rev-parse HEAD): `cac8f4a020d357b9ac80fed3a8bbb07e4a5cf468` (ветка `hermes/code-1011`)
- Область: install-скрипты пакетов (`preinstall`/`install`/`postinstall`/`prepare`), источники пакетов в lock, закрепление версий, сборка образа, проверки перед выкладкой.
- Режим: только чтение. Изменён (создан) ровно один файл — этот отчёт.

## Итог

- Всего 12 находок: **критично — 0, важно — 4, мелочь — 8**. Плюс 3 наблюдения в «Что не проверено».
- Install-скрипты есть у **7 записей** lock (`hasInstallScript`, включая корневой проект); политика разрешений — `.npmrc:2 allow-scripts=…` (только npm ≥ 11.16).
- **Самое серьёзное:** allow-list в `.npmrc` не работает в CI — там Node 22, а Node 22 несёт npm 10.9.x, где механизма `allow-scripts` нет вовсе. В CI (`ci.yml:44,171 npm ci`) выполняются install-скрипты всех зависимостей, то есть защита «как задумано» не действует именно на сборочном конвейере.
- Второе по значимости: разрешения заданы точными версиями (`prisma@7.10.0` и т.д.), а в `package.json` у этих пакетов стоят диапазоны `^`/`~`. Обычное обновление Prisma/esbuild сдвинет версию и молча «разжалует» пакет (npm по умолчанию `strict-allow-scripts=false`) — скрипт просто перестанет запускаться без ошибки.
- В lock **нет** пакетов из нестандартных источников (git/http/file/link) — все `resolved` указывают на `registry.npmjs.org` (ПРОЙДЕНО). В Docker install-скрипты не запускаются (`--ignore-scripts`), но `prisma generate` в builder-стадии ходит в сеть за движком (binaries.prisma.sh).

## Ответы на вопросы 2–5

- **(2) Нестандартные источники в lock.** НЕТ: ни одного `"resolved": "git…`, `"resolved": "file:…`, `"resolved": "http://…`, `"version": "file:/git`, `"link": true`. Все распакованные — `https://registry.npmjs.org/...`. `npm-shrinkwrap.json` отсутствует. «github» в lock — только в полях `funding`. ПРОЙДЕНО. Отдельно: 6 записей с `"inBundle": true` (bundled-зависимости `@tailwindcss/oxide-wasm32-wasi`, строки 5289-5348) — install-скриптов у них нет, но их скрипты в принципе нельзя внести в allow-list (`@npmcli/arborist/lib/script-allowed.js:34`).
- **(3) Закреплены ли версии у пакетов с install-скриптами.** В `package.json` — НЕТ: прямых зависимостей с install-скриптами нет вовсе, все 7 приходят транзитивно/корнем; объявленные диапазоны — `prisma: ^7.8.0`, `@prisma/client: ^7.8.0`, `sharp: ^0.35.5`, `tsx: ^4.22.4`, `bullmq: ^6.3.12` (`package.json:72,134,102,105,87`). В `package-lock.json` версии точные. В `.npmrc:2` allow-list — точные версии (`@prisma/engines@7.10.0,prisma@7.10.0,esbuild@0.28.2,msgpackr-extract@3.0.4,unrs-resolver@1.12.2`) и они совпадают с lock на сегодня. Итог: закрепление есть только в lock + allow-list, но не в манифесте.
- **(4) Запускается ли это в Dockerfile при сборке.** В `Dockerfile` и `Dockerfile.workers` — НЕТ: `npm ci --ignore-scripts` (`Dockerfile:15`, `Dockerfile.workers:29`), корневые хуки тоже пропускаются, поэтому дальше явные шаги: `npx prisma generate` (`Dockerfile:40`, `Dockerfile:68`), `npm run db:generate` (`Dockerfile.workers:48`). Побочный эффект: пропущенный `postinstall` у `@prisma/engines` означает, что движок должен скачаться на шаге `prisma generate` (сеть до `binaries.prisma.sh`). В `Dockerfile.quick:7` `npm ci` **без** `--ignore-scripts` — там скрипты всех зависимостей выполняются (файл никем не собирается, см. находку 8).
- **(5) Шаги проверки перед выкладкой** (предлагаю закрепить в чек-листе деплоя):
  1. `node -v` / `npm -v`: npm должен быть **≥ 11.16**, иначе allow-list в `.npmrc` игнорируется и запускаются все скрипты. На CI сейчас `node-version: '22'` (`ci.yml:40,167`) → npm 10.9.x.
  2. `npm ci`, затем `npm install-scripts ls` и/или `npm approve-scripts --allow-scripts-pending` — увидеть, есть ли непроверенные install-скрипты, и осознанно их утвердить/запретить.
  3. Сверить, что у 5 пакетов разрешённые версии совпадают с lock — при обновлении Prisma/esbuild обновлять и allow-list; включить `strict-allow-scripts=true` в `.npmrc`, чтобы рассинхрон падал с ошибкой, а не молча.
  4. Контроль источников: `rg '"resolved": "(git|http|file)' package-lock.json` и `rg '"version": "file:' package-lock.json` — пусто.
  5. Сборка боевых образов только по `Dockerfile`/`Dockerfile.workers` (там `--ignore-scripts`); проверить, что сборщик имеет доступ к `binaries.prisma.sh` либо задан `PRISMA_ENGINES_MIRROR`; дым `GET /api/health`.
  6. Не собирать `Dockerfile.quick`.
