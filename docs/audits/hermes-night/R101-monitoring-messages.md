## Итог

- Находок 18: **критично — 0**, **важно — 5**, **мелочь — 13**. Потерь данных в сценариях раздела не найдено; проблема — вранье и разнобой в объяснении отказов и одно необратимое действие без подтверждения.
- Главный дефект класса: **отказ выдают за «данных нет» или за «нет связи»**. Фото, не прочитавшееся по 403/500/сети, показывается как «Фото не загружено» (`equipment-tile-block.tsx:42-63,67`); сохранённая раскладка плиток, не прочитавшаяся с сервера, молча подменяется шаблоном по умолчанию (`use-layout-template.ts:77-79`).
- Второй класс: **сохранение/сброс шаблона плитки молчит при обрыве сети** — `saveDraft`/`reset` вызывают `authFetch` без `try/catch`, промис отклоняется, сообщения нет вовсе (`use-layout-template.ts:125-138,140-151`).
- Топ-5:
  1. **Обрыв сети при сохранении/сбросе шаблона плитки — полная тишина** (`use-layout-template.ts:127,143`): админ нажимает «Сохранить шаблон», ничего не происходит; `void controller.saveDraft()` (`layout-editor.tsx:157`) гасит необработанный rejection.
  2. **«Сбросить» удаляет сохранённый шаблон плиток одним кликом без подтверждения** (`layout-editor.tsx:156` → `use-layout-template.ts:140-151`, `DELETE /api/layout/monitoring-equipment-tile`); рядом закрытие редактора и удаление блока спрашивают (`layout-editor.tsx:124,142`). Класс уже отмечен R97 №3 для плитки установки — тот же общий `LayoutEditor`, здесь поверхность мониторинга.
  3. **Сбой чтения раскладки = подмена шаблона по умолчанию** (`use-layout-template.ts:72-79`): `if (res.ok)` без ветки ошибки, `catch {}` — при 403/500/сети экран рисует заводской шаблон, и админ думает, что настройки потеряны.
  4. **Фото, не загрузившееся из-за отказа, подписано «Фото не загружено»** (`equipment-tile-block.tsx:51,67`): фото есть, но не прочиталось (403/500/сеть) — диспетчер видит «фото нет».
  5. **Любой отказ снимка парка и таймаут опроса — «Сервис мониторинга временно недоступен» / «Нет соединения»** (`fleet-dashboard.tsx:70,79`): код статуса скрыт, а разбор тела/таймаут (15 с) помечены как «нет соединения», хотя связь есть.

## Что видит человек: сценарий за сценарием

Тексты дословно; источник — файл:строка.

### 1. Открыть экран «Мониторинг» (`/monitoring`)

Успех: `StatusBar` — «Сегодня · <дата>», «N из M в работе», бейдж связи, «Данные обновлены <относительное время>» и шесть KPI-плиток (`fleet-dashboard.tsx:239-284`); селекты «Все объекты»/«Сначала активные» (`:174-200`); сетка карточек.

- **403.** `GET /api/monitoring/fleet` не содержит `assertCan` — только `requireAuth` (`monitoring/fleet/route.ts:21-35`), поэтому 403 на снимке недостижим (админ в режиме «Действую как OPERATOR» получает снимок, сужённый до экипажа). Отказ возможен лишь как 5xx/429/таймаут.
- **5xx / 429 / обрыв.** Любой не-ok → `setError('Сервис мониторинга временно недоступен.')` (`fleet-dashboard.tsx:69-71`), код статуса не разбирается. Разбор тела, обрыв и `AbortSignal.timeout(15_000)` попадают в `catch` → «Нет соединения с сервисом мониторинга.» (`:77-80`) — в том числе когда связь есть, а сервер ответил мусором/не успел. Экран ошибки: заголовок «Мониторинг не загрузился» + «<текст>. Проверьте подключение и повторите попытку.» + кнопка «Повторить загрузку» (`:135-150`).
- **Устаревший снимок.** Если ошибка случилась после успешной загрузки — баннер `<текст> Показан предыдущий снимок.` + «Обновить» (`:168-171`), а бейдж связи становится «Нет связи» (`:108,255-262`) даже при 500 (сервер доступен).
- **Пусто.** «На выбранном объекте нет назначенных установок. Выберите другой объект.» при активном фильтре или «Нет установок для отображения.» (`:214-220`). Пустой парк и «нет прав» не разведены, но последнее недостижимо.
- **401.** `authFetch` делает logout в store (`api.ts:56-69`), раскладка уводит на `/login`; сообщения об истечении сессии нет, на миг может мелькнуть «Сервис недоступен».
- **409** к чтению неприменим.

### 2. Клик по карточке установки

- Успех: карточка — ссылка на `/admin/equipment/{id}` (`equipment-card.tsx:29-32`).
- **Ссылка только у ADMIN/DISPATCHER** (`clickable = role === 'ADMIN' || role === 'DISPATCHER'`, `:23`). У FOREMAN и MECHANIC (мастер видит «Мониторинг» в меню, `role-navigation.ts:126`) плитка не кликабельна и **ни слова о причине** — нажатие не делает ничего.
- Успех перехода на карточку/403/404 — описаны в R97 (не дублируется).

### 3. Смена фильтра/сортировки

- Успех: локальный пересчёт (`:110-127`), запрос не уходит. Фильтр «Объект» появляется только при >1 объекте, сортировка — при >1 установке (`:174-200`).
- Пусто после фильтра: тот же уместный текст (`:214-220`).

### 4. Фото на плитке

- Успех: пресigned-ссылка получена (`useResolvedPhotoUrl`, `equipment-tile-block.tsx:37-63`), фото показано.
- **Отказ:** любой не-ok (`:51`) или обрыв (`:55-57`) → URL остаётся `null` → блок пишет «Фото не загружено» (`:67`), как будто снимка нет. То же для блока `kind: 'image'` без серверного `photoUrl` (`:134`).
- Статус на фото: «В ремонте» / «В работе» / «Ждём отчёт» / «Нет отчёта» (`:78-85`).

### 5. Открыть редактор плитки («Настройки → Плитки установок (мониторинг)»)

- Успех: список установок из `GET /api/monitoring/fleet?_ts=…` (`equipment-tile-template-settings.tsx:30-43`), кнопка «Открыть редактор плиток» → модальный `LayoutEditor` («Редактор плитки установки»), предпросмотр на реальной карточке. Вид — только ADMIN (`equipment-tile-editor.tsx:45,55`).
- **Отказ списка:** не-ok → «Не удалось получить список установок.» (`:34`), обрыв → «Нет соединения с сервисом мониторинга.» (`:41`); текст выводится голым `<p className="text-sm text-destructive">` вместо карточки (`:54-56`), **без кнопки «Повторить»**. Код статуса скрыт.
- **Пусто:** «Пока нет ни одной установки — редактировать плитку не на чем.» (`:62-68`) — уместно.

### 6. Сохранить / сбросить шаблон в редакторе

- Успех сохранения: `PUT /api/layout/monitoring-equipment-tile`, редактор закрывается (`use-layout-template.ts:125-138`); сообщения «Сохранено» нет (тихо). Успех сброса: `DELETE`, шаблон возвращается к заводскому, `onAfterReset` чистит локальные ассеты (`:80-82,140-151`).
- **403:** тост «Только администратор может сохранять шаблон» / «…сбросить шаблон» (`:133,145`). **400/500:** «Не удалось сохранить шаблон» / «Не удалось сбросить шаблон» (`:133,145`) — серверный текст («Некорректные данные», `layout/[surfaceId]/route.ts:73`) отброшен.
- **Обрыв сети:** `authFetch` бросает исключение, `try/catch` нет → **ни тоста, ни изменения**; `void controller.saveDraft()` (`layout-editor.tsx:157`) гасит необработанный rejection. Человек жмёт кнопку и не понимает, сохранилось ли.
- **Необратимое без подтверждения:** «Сбросить» (`layout-editor.tsx:156`) удаляет сохранённый шаблон сразу; закрытие редактора (`:124`) и удаление блока данных (`:142`) спрашивают.
- **401:** logout + уход на `/login`; редактор исчезает без сообщения.
- **409** к сохранению неприменим (upsert без проверки версии).
- Загрузка фото в редакторе: свой контроль типа/размера («Поддерживаются только JPG, PNG и WebP», «Размер изображения не должен превышать 12 МБ», `equipment-tile-asset-storage.ts:33-34`); ошибки upload — «Не удалось начать загрузку (403)», «Загрузка в хранилище не удалась», «Не удалось подтвердить загрузку» (`equipment-photo-upload.ts:23,28,31`).

### 7. Загрузка раскладки на самом экране мониторинга (только чтение)

- `useEquipmentTileTemplate` отдаёт шаблон в `FleetDashboard` (`fleet-dashboard.tsx:88`). `GET /api/layout/monitoring-equipment-tile` — при отказе/обрыве `loadTemplate` молча отдаёт заводской шаблон (`use-layout-template.ts:72-79`): сетка нарисована верно с точки зрения кода, но сохранённая админом раскладка на экране не та, и признака нет.
