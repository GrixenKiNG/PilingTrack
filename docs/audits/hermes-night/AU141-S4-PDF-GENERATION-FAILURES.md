## Итог

- Найдено 16 находок: **критично — 2**, **важно — 5**, **мелочь — 9**.
- Топ-5:
  1. О сбое фоновой генерации узнать нечем: ни алерта, ни метрики очереди, ни записи в ленту обратной связи; Sentry в воркере включается только при `SENTRY_DSN`, в compose он по умолчанию пуст.
  2. Результат PDF при отсутствии S3 пишется в файловую систему контейнера `workers`, а читается из файловой системы контейнера `app` — общего тома нет. Асинхронный скачок файла в таком режиме ломается (ENOENT → 500).
  3. Асинхронный путь (POST → jobId → опрос → download) не используется ни одним экраном приложения: единственный потребитель — e2e-спек. То есть очередь, повторы и Redis-фallback в бою не ходят.
  4. У PDF-воркера нет `lockDuration`/`stalledInterval` и нет обработчика `stalled` (он есть только у второго, дублирующего воркера) — дефолт BullMQ 30 с; тяжёлый PDF, блокирующий цикл событий, рискует получить «stalled», повторную обработку и провал.
  5. Синхронная генерация периода не имеет таймаута (`await` без гонки): 30-секундный предел есть только в ветке одиночного PDF, и он не прерывает уже начатый рендер.
