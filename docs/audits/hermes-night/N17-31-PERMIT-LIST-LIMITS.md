# N17-31-PERMIT-LIST-LIMITS — Наряды: список без пагинации и предела

READ-ONLY аудит. Ветка `hermes/code-1011`, HEAD `deaa962ddcaf70a1418674c29d69fef0fc436616`
(`git rev-parse HEAD`). Код приложения не менялся; создан только этот отчёт.

## Итог

- **Серверный запрос списка нарядов — пагинируемый и ограниченный:** курсор `(updatedAt,id)`, `take = limit+1`, `limit` по умолчанию 50, максимум 200 (`route.ts:33-36`, `queries.ts:42-53`, `work-permit-repository.ts:157-162`). Утверждение задания «без пагинации и предела» верно **только для экрана**, не для API.
- **Экран жёстко просит `limit=200` и молча выбрасывает всё остальное** (`api/client.ts:176-177`): `total`, `hasMore`, `nextCursor` из ответа не читаются, кнопки «показать ещё» нет. При большом объёме пользователь видит ровно 200 самых свежих по `updatedAt`.
- **Все счётчики и пометка «Просрочено: N» считаются на загруженных ≤200 строках** (`permits-screen.tsx:100-119,144-154,217-220,243-251,294`), а не на всём наборе — при >200 нарядах они занижены.
- **Найдено: критично — 0, важно — 2, мелочь — 9** (всего 11). Индексы не измерялись (`EXPLAIN` не снимался) — это ГИПОТЕЗА; отсутствие `[tenantId, updatedAt]` уже зафиксировано в `N17-17-INDEXES-VS-QUERIES.md` №4.
- **Топ-5:** (1) клиент режет список до 200 без «показать ещё» и без «показано 200 из N»; (2) KPI/алерт «Просрочено» считаются по усечённому набору; (3) фильтр «Просроченные» существует только на клиенте (в API нет состояния `OVERDUE`); (4) лента дашборда «Требует решения сейчас» усечена тем же лимитом 200; (5) выгрузка нарядов, в отличие от экрана, предела не имеет — расхождение «экран ↔ файл».

## Ответы на вопросы задания

**Вопрос 1 — есть ли take/skip или курсор, какой максимум.** Пагинация **курсорная** (offset/`skip` нет). `route.ts:33` — `limit` по умолчанию `50`; `route.ts:34` — допустимо `1..200`, иначе 400; `work-permit-repository.ts:159` — `take: input.limit + 1`; `queries.ts:42-52` — `hasMore`, `total`, `nextCursor`. Курсор кодирует `(updatedAt,id)` (`queries.ts:16-29`), `where` продолжения — `OR` по паре (`work-permit-repository.ts:152-155`). **Максимум — 200 строк за один запрос.** Статус ПРОЙДЕНО.

**Вопрос 2 — что вернётся при 5000 нарядах на объекте за год.** API вернёт **первые 200** строк в порядке `updatedAt DESC, id DESC` (`work-permit-repository.ts:158-160`) плюс истинное `total` в `page.total` (`:161`, `queries.ts:48`). Экран (`api/client.ts:174-178`) читает только `body.data`, поэтому пользователь видит **200** нарядов; остальные 4800 в интерфейсе недостижимы, счётчики занижены, признака усечения нет. Статус ПРОЙДЕНО (по коду; фактическое число нарядов арендатора `orion` не измерялось — см. «Не проверено»).

**Вопрос 3 — индекс под фильтр и сортировку `WorkPermit`.** См. `prisma/schema.prisma:1520-1526`: `[tenantId,equipmentId,state,validTo]`, `[tenantId,state,updatedAt]`, `[tenantId,risk,updatedAt]`, `[tenantId,shiftId]`, `[tenantId,workTypeId]`. Индексы со `state`/`risk`/`equipmentId` покрывают **соответствующие** фильтры + сортировку `updatedAt`. Для **дефолтного** списка (`where = {tenantId}` без `state`/`risk`/`equipmentId`, `orderBy updatedAt DESC`) подходящего индекса **нет** — это уже находка №4 в `N17-17-INDEXES-VS-QUERIES.md`. При фильтре по `validFrom/validTo` (диапазон) сортировка по `updatedAt` индексом тоже не покрывается. Статус ГИПОТЕЗА (план не снимался).

**Вопрос 4 — экран грузит всё сразу или по страницам.** **Одним куском ≤200, без страниц.** `to-module.tsx:463` → `fetchWorkPermits(...)` → `api/client.ts:176` (`limit=200`, курсор не передаётся) → `to-module.tsx:507` `setPermits(...)`. Разбиения на страницы / «показать ещё» в компоненте нет — `filteredPermits.map` рендерит весь набор в прокручиваемый контейнер (`permits-screen.tsx:296-308`). Готовый помощник `loadAllPages` (`src/lib/pagination-cursor.ts:73-96`) здесь не используется. Статус ПРОЙДЕНО.

**Вопрос 5 — фильтр «Просроченные» и счётчики: весь набор или страница.** **Только загруженная страница (≤200).** «Просроченные» — чисто клиентский отбор: `actionableOverduePermits(props.permits, now)` (`permits-screen.tsx:112,149`, `permit-role-steps.ts:29-35`); в API перечисленных состояний `OVERDUE` нет (`route.ts:42-44` — только `DRAFT/PENDING_APPROVAL/APPROVED/EXPIRED/REVOKED/CLOSED`). KPI «Всего/Действуют/На согласовании/Заблокированы», метка `Просроченные (N)` и красный алерт «Просрочено нарядов-допусков: N» считаются по `props.permits` (`permits-screen.tsx:100-119,217-220,243-251,294`). Статус ПРОЙДЕНО.
