# Дыры в покрытии: чистая доменная логика без unit-тестов — 06

Аудит «какие чистые расчёты, решающие денежный/безопасностный/производственный
результат, не имеют unit-теста». Читаются только `src/modules/*/domain/**`,
расчёты в `src/modules/*/application/**` и количественные помощники `src/lib/**`
(длина свай в м.п., часы простоя, допуск/готовность, интервалы ТО, агрегаты
аналитики). Замороженные зоны (варианты операторского экрана,
`src/modules/operator-mobile/**`, ORION) не анализируются как источники кода —
но их потребление общих lib-помощников учтено, т.к. эти помощники не
заморожены. Ни один файл не изменён. Тесты не пишутся: владельцу нужен худеющий
набор, вывод — короткий приоритизированный список.

## Итог

Проверены все количественные чистые функции в трёх областях скоупа. Точных
расчётов денег/производства/безопасности **без прямого unit-теста — 5 значимых**,
плюс **3 значимых с неполным/косвенным покрытием** и **3 мелких**. Ключевое:
- **часы простоя** (`downtime-hours.ts`) — ядро спора с подрядчиком «сколько
  стояла машина» — не имеют **ни одного** прямого теста; косвенное покрытие
  лежит только в замороженном домене оператора и математику часов не проверяет;
- **расход топлива** (`fuel-log.ts:72`) — деньги на горючее — ноль тестов;
- **итоги периода в PDF** (`pdf-data.ts:70`) дублируют протестированный
  `computePeriodSummary`, но сами не покрыты — риск расхождения цифр PDF и экрана;
- готовность/допуск и ТО в целом хорошо покрыты (evaluator, work-permit,
  readiness-score, pm-due, pile-length), дыры точечные.

Системная причина большинства дыр одна: готовые к юнит-тесту чистые функции
переехали в `lib/` (для переиспользования между сервером и интерфейсом), но
тестирование осталось на уровне обёрток-компонентов, которые покрывают только
частный случай и не добираются до веток расчёта.

## Методика (как воспроизводимо)

1. Полный перечень тестов: `find src -name '*.test.ts' -o -name '*.spec.ts'`
   (~210 файлов).
2. Полный перечень кандидатов: `find src/modules src/lib -name '*.ts'`
   (исключая `__tests__`, `*.test.*`), отфильтрован по «чистая функция» с
   сигнатурой `(вход) => число/статус/вердикт` без `db.` внутри.
3. Для каждого кандидата — перекрёстный `grep` имени функции (и имени файла) по
   `--include=*.test.ts`, чтобы отличить «теста нет вообще» от «покрыт через
   обёртку/маршрут». Для функций с косвенным покрытием открыт сам тест-файл и
   проверено, какие ветки реально затронуты (например `equipment-maintenance-flag.test.ts`
   зовёт только строковый флаг `getMaintenanceFlag`, а не разбор
   `checkMaintenanceDue`).
4. Для «мёртвых на вид» путей (например `buildReadinessFacts`) выполнен grep
   всех потребителей по всему `src`, чтобы не приписать ложную защищённость.
5. Замороженные зоны учтены: их код не анализируется, но потребляемые ими
   общие lib-помощники (`downtime-hours`, `maintenance-due`) не сняты с учёта —
   они в живой области.

## Не проверено

- **`src/modules/readiness/application/access-matrix-service.ts`** (`getAccessMatrix`,
  `saveAccessMatrixDraft`, `publishAccessMatrix`) — маршрут не в списке тестов;
  не трассировал до конца, есть ли e2e/route-тест. Потенциально соседняя дыра к №11.
- **Проекции аналитики** `reports/application/projections/projection-handlers.ts`,
  `rebuild.ts` — агрегаты по отчётам; покрытие искал только в соседнем каталоге,
  общей трассировки всех потребителей не делал. Db/event-driven, вероятно не
  «чистая логика», но денежные агрегаты — стоит отдельного взгляда.
- **`src/modules/equipment/application/queries/operational-state.ts:27`** —
  `resolveEquipmentOperationalStates` (working/repair/idle) без теста; db-зависимый,
  влияет на мониторинг/готовность. Не оценивал как pure.
- **`src/modules/monitoring/application/template-service.ts`**, **`src/modules/layout/**`**
  — вне денежных/производственных расчётов первый просмотр; не исключал
  проверить количественные части.
- **Backfill и `projection/current-read-model.ts`** — расчёт текущего read-модели
  готовности; не трассировал.
- **Часы простоя в отчётах по данным, где `endedAt` меньше `startedAt` не из
  ночной смены** — такой датасет в базе не проверял (было бы интеграционным).

  «расценки»; если они есть в БД (не в `src/**`), это вне рамок чтения.
