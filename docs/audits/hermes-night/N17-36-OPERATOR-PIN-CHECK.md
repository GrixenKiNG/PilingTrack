# N17-36-OPERATOR-PIN-CHECK — ПИН оператора: попытки и хранение

**Версия:** `b1e87d3b221e4aacd86cc44ec1ecf53e4eff5270` (HEAD, ветка `hermes/code-1011`, 2026-10-17).
**Тип:** независимый аудит, только чтение. Код приложения не менялся; создан и закоммичен только этот отчёт.
**Рабочая папка:** `D:/PillingR/wt-night-code`.

## Итог

- **Проверки ПИН-кода в текущем коде НЕТ.** Вход по ПИН-коду удалён решением владельца 27.09.2026 коммитом `bb40d7ed` «feat(auth)!: удалить вход по ПИН-коду» (25 файлов, −778 строк). В `src/app/api/auth` остались только `login`, `logout`, `me`; функции `authenticateUserByPin`, `hashPin`, `computePinLookup` отсутствуют; константы `PIN_RATE_LIMIT`/`PIN_*` в `src/lib/rate-limiter.ts` отсутствуют; схемы `pinAuthSchema`/`pin`/`pinLookup` в `src/lib/validation-schemas.ts` отсутствуют.
- **Хранение (исторически):** `bcrypt(PIN, 12)` в колонке `pin` + детерминированный `HMAC-SHA256(PIN, PIN_LOOKUP_SECRET)` в `pinLookup` для O(1)-поиска. Колонки и их глобальные UNIQUE-индексы **остались в схеме**, но код их не пишет и не читает.
- **Попытки (исторически):** 3 попытки / окно 10 минут, блокировка 1 час; счёт вёлся **по клиенту (IP/хост)**, ключ `pin-ip-<identifier>`, не по пользователю. Ничего из этого в текущем коде нет.
- **Постоянное по времени сравнение:** к ПИН применялось bcrypt-сравнение, а на legacy-ветке — `constantTimeEquals`. Сейчас к ПИН не относится; `timingSafeEqual` используется только для ключей устройств, вебхука алертов и метрик.
- **Подсчёт по серьёзности:** критично — **0**, важно — **2**, мелочь — **9**. Все находки — это остатки удалённого входа, а не действующие слабости ПИН-проверки.
- **Топ-5:** (1) `scripts/test-pilingtrack.sh:32-52` бьёт в удалённый `/api/auth/pin` и печатает ложные падения; (2) мёртвые секрет-колонки `pin`/`pinLookup` с UNIQUE и UPDATE-грантом identity-роли при комментариях «используется»; (3) мёртвые ярлыки аудита `auth.pin.*`; (4) `RELEASE-NOTES.md:13` рекламирует вход по PIN как действующий; (5) мёртвый `loginWithPin` в e2e, где `pinInput` фактически указывает на поле пароля.

## Методика

Что искал и как это повторить:

1. `git rev-parse HEAD` — версия; `git log --oneline --all --grep="ПИН" -i` и `--grep="pin" -i` — история; `git merge-base --is-ancestor bb40d7ed HEAD` — что удаление ПИН-кода уже в текущем дереве.
2. `Get-ChildItem -Recurse src/app/api/auth` — перечень маршрутов аутентификации.
3. `rg -n -i "pin|ПИН|pinCode|pinHash|pinLookup|timingSafeEqual" src` — весь `src`; отдельно `rg -n -i "pin" src/app/api/auth src/services/auth src/modules/operator-mobile src/lib/rate-limiter.ts`.
4. `rg -n -i "\bpin\b|pinCode|pin_code|ПИН" .` по всему репозиторию (кроме `node_modules`, `.next`) — чтобы найти остатки в скриптах, e2e, документации, схеме.
5. `git show bb40d7ed --stat` и `git show bb40d7ed^:<file>` — содержимое **удалённых** файлов до удаления (`src/app/api/auth/pin/route.ts`, фрагменты `auth-service.ts`, `rate-limiter.ts`), чтобы ответить на вопросы о попытках/блокировке/сравнении.
6. Чтение целиком: `src/services/auth/auth-service.ts` (155 строк), `src/app/api/auth/login/route.ts`, `src/core/security/identity-role.ts`, `src/modules/operator-mobile/domain/operator-credentials.ts`.
7. Проверка, что ПИН не принимается вместо пароля: `npx vitest run src/app/api/users/__tests__/route.test.ts` → **15 passed (15)**, включая тест `refuses to create a user with a PIN instead of a password` (`src/app/api/users/__tests__/route.test.ts:83`).
8. Проверка, что секреты не отдаются в списках: `rg -n "select|password|pin" src/services/users/user-service.ts` — все выборки перечисляют поля явно, `password`/`pin`/`pinLookup` не выбираются.
