# N17-05 — состояния показателей на экранах мониторинга и аналитики: READ-ONLY аудит

## Итог

Проверены экраны мониторинга и аналитики: оперативный дашборд (`/admin`), аналитика (`/admin/analytics`),
аналитика по установкам (`/admin/equipment-analytics`), парк (`/monitoring`), карточка установки →
телеметрия. Искались места, где разные состояния одного показателя — **реальный ноль**, **нет отчётов
за период**, **загрузка**, **отказ запроса**, **устаревшая проекция** — нарисованы одинаково.
Ничего в приложении не менялось; только этот отчёт.

**Находок: 16 — критично 1, важно 7, мелочь 8.** Топ-5:

1. **Критично.** Вкладка «Тренды по объектам» читает проекцию `SiteWeeklyTrend` без метки свежести
   (`site-weekly-trend/route.ts:25-31`). Если проекция не пересчитана (потерян/пропущен обработчик),
   строк нет, и экран печатает «Нет данных за недели. Числа появятся, когда поступят отчёты»
   (`admin-analytics.tsx:431`) — отказ проекции неотличим от честно пустого периода.
2. **Важно.** Плитка «Отчёты» на дашборде при сбое загрузки парка показывает `0 / 0`
   «машин с отчётом сегодня» вместо «—» (`admin-dashboard.tsx:335,357`).
3. **Важно.** В плитке установки «Простой» показывает «—» и при нуле, и при отсутствии отчёта
   (`equipment-tile-block.tsx:193`), тогда как «Сваи»/«Бурение» рядом печатают `0`.
4. **Важно.** В плитке установки «Статус» состояние `expected` («ждём отчёт») схлопывается в
   «Нет отчёта», как у простаивающей машины (`equipment-tile-block.tsx:177`).
5. **Важно.** Топливо `0` на «Аналитике по установкам» рисуется как «—» + «нужна телеметрия»;
   измеренный ноль (машина не расходовала) неотличим от отсутствия телеметрии
   (`equipment-analytics.tsx:195`; `equipment-analytics-service.ts:166-167`).

Версия. В задании названа база `main 1d24e24f`, но фактический `git rev-parse HEAD` =
`d618e96db274619b69b62acddf2025bdbcd62ce63`, ветка `hermes/code-1011`
(`docs(audit): путь сообщения Telegram и DLQ`, 2026-10-16). Ниже ссылки — на этот HEAD.

Аудит READ-ONLY: чтение файлов (`read`) и текстовый поиск (`ripgrep`) по `src/`. Приложение не
запускалось, живой БД нет — все выводы сделаны по коду; там, где вывод требует исполнения,
стоит «не проверено» (см. раздел).

## Топ-10 мест, где отказ/устаревание можно принять за «работы не было»

1. **Тренды по объектам** — устаревшая/несчитанная проекция печатается как «Нет данных… появятся с отчётами» (Ф1).
2. **Дашборд «Отчёты»** — при отказе парка `0 / 0` машин с отчётом вместо «—» (Ф2).
3. **Аналитика «Объектов»** — при отказе `/api/sites/all` печатает `0` (Ф6).
4. **«Требует решения сейчас»** — при полном отказе источников блок исчезает, будто срочного нет (Ф7).
