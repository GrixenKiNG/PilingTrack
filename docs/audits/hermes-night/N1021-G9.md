## Итог

Всего найдено **6 нарушений**, отсутствующих в `scripts/.layer-boundaries-baseline.txt`:

| Категория | Критично | Важно | Мелочь |
|-----------|----------|-------|--------|
| Production (services → modules) | 0 | 1 | 0 |
| Production (modules → services) | 0 | 0 | 0 (все 4 уже в baseline) |
| Test files (modules → services) | 0 | 0 | 2 |
| Test files (services → modules) | 0 | 0 | 1 |

**Самое важное:** `src/services/dictionaries/dictionary-service.ts:3` — production-код сервиса импортирует публичный API модуля `audit` (`@/modules/audit`). Это обратное направление по сравнению с зафиксированными в baseline нарушениями (modules → services), и скрипт его не ловит, потому что `FORBIDDEN['services']` не включает `'modules'`.

3. Запустил скрипт: `npx tsx scripts/check-layer-boundaries.ts` — вернул «0 new».
4. Ручной поиск (`rg`) по двум направлениям:
   - `src/modules/**` → `@/services/` (production + тесты)
   - `src/services/**` → `@/modules/` (production + тесты)
5. Сравнил найденные импорты с baseline. Исключил dynamic `import()` и `require()` — их нет.
6. Проверил каждый файл, чтобы подтвердить номера строк и контекст.

## Не проверено

- **Dynamic imports / require()** — поиск по `import\(['\"]@/services/` и `require\(['\"]@/services/` в `modules/`, и симметрично для `services/` → `modules/` — результатов нет.
- **Export ... from** — поиск по `export .* from ['\"]@/services/` в `modules/` и `export .* from ['\"]@/modules/` в `services/` — результатов нет.
- **Другие модули в `src/modules/`** — полный поиск `@/services/` в `src/modules/**/*.ts` дал ровно 4 production-файла (все в baseline) + 2 тестовых файла. Больше production-нарушений нет.
- **Другие сервисы в `src/services/`** — полный поиск `@/modules/` в `src/services/**/*.ts` дал 1 production-файл (`dictionary-service.ts`) + 1 тестовый. Больше production-нарушений нет.
- **Операторские экраны и ORION** — по условию задачи читать можно, править нельзя. Не сканировал их на предмет cross-layer импортов.
