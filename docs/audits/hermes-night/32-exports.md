# Выгрузки (CSV / XLSX / журнал забивки): те же ли числа, что на экранах, и только ли своя организация

Дата: 2026-09-26. Ветка: `hermes/q3-0925` (worktree `D:\PillingR\wt-night`). Только чтение кода: файлы не менялись, БД не открывалась, приложение не запускалось.

## Итог

Проверено 4 выгрузки данных (CSV/XLSX отчётов, XLSX журнала забивки, CSV готовности; PDF просмотрены только на фильтр организации) и их «парные» экраны. Фильтр организации **везде строгий**: `requireTenantId`/`context.tenantId` из сессии, ни одного `?? undefined`, `|| ''`, `IS NULL OR` в выгрузках нет — чужой организации в файле нет **ни в одной** из проверенных выгрузок (критичного IDOR не найдено). Моточасы «м/ч», «Установка», длина сваи из `PileGrade.lengthMm` — соблюдены; парсинга длины из названия марки в выгрузках нет.

Найдено **18 расхождений**: 1 критично, 4 важно, 13 мелочь. Топ-5:

1. **критично** — XLSX журнала забивки: границы периода считаются по UTC, а даты в файле — по поясу организации. Свая, забитая 26.09 в 00:30 МСК, в выгрузку «26.09» не попадает, зато в неё попадает свая 27.09 00:30 МСК. Подшиваемый документ содержит не тот набор свай, что заявлен в его же титуле.
2. **важно** — CSV/XLSX отчётов содержат только свою организацию, а экран `/admin/reports` для ADMIN/DISPATCHER показывает все организации: у администратора «на экране 2320 свай, в файле 300».
3. **важно** — в CSV и в листе «Итоги» XLSX нет м.п. свай вовсе (есть только штуки), тогда как экран показывает «шт/м.п.» — сверять погонные метры по файлу нечем.
4. **важно** — черновики (незакрытые смены, `Report.status = "draft"`) попадают и на экран, и в выгрузки, но исключены из аналитики/KPI (`status != draft`) — два «общих» числа за один период не сходятся.
5. **важно** — CSV готовности печатает даты как ISO-UTC (`2026-09-25T21:30:00.000Z`) без пояса, а экран показывает день в поясе организации; для ночных событий день в файле на единицу меньше.

Отдельно: два пункта прошлого аудита (`docs/audits/hermes-night/15-exports-consistency.md` #1 и #2) **исправлены** — лимит периода теперь 2000 с явной ошибкой 422 (`raw-queries.ts:25,99-104`), а лимит журнала един для экрана и выгрузки (`pile-passport.service.ts:134`, `pile-passports/route.ts:48`) — перепроверено по коду.
