# Настройки администратора: какие из них действительно действуют

Аудит 30, ветка `hermes/q3-0925` (worktree `D:\PillingR\wt-night`). Вопрос: у каждой настройки, которую может изменить администратор, есть ли настоящий читатель и действует ли она везде, где должна.

## Итог

- Всего находок: **21**. По severity: **критично — 0**, **важно — 11**, **мелочь — 10**.
- Главный вывод: настройки в контуре в основном «доведены» — правила готовности, матрица доступов, тумблеры уведомлений, шаблоны плиток и раскладки имеют реальных читателей (см. карту). Провалы — не в хранении, а в **точках чтения**: часовой пояс тенанта не читается ни в отчётах, ни в форме осмотра, а два интерфейсных экрана настроек способны затереть сохранённые значения.
- `planDeviation` (эталон из задания) — единственный ключ уведомлений без отправителя; экран честно подписывает «Отправитель не реализован» только на одной из двух вкладок, а умолчание у него `true`.
- Часового пояса, автозакрытия смен и погодной политики: у первого настройка есть, но её не читают ~7 мест; у двух последних **настройки нет вовсе** — значения зашиты в код (полдень, 15 м/с).
- Топ-5 по последствиям:
  1. `notifications-section`/`workspace-settings`: тумблер уведомления отправляет весь объект настроек — при неудачной загрузке он обнуляет название компании и часовой пояс тенанта (`workspace-settings.tsx:67,81-84,111-136` + `settings.ts:81,93`).
  2. Публикация матрицы доступов не действует на дефекты: `defects/commands.ts:55,62` считает права по значениям по умолчанию, игнорируя `context.accessMatrix`.
  3. Дата осмотра в форме ЕО/ТО берётся по Москве (`start-inspection-form.tsx:68`), а критерий «осмотр за сегодня» считается в поясе тенанта — осмотр восточнее Москвы уходит в прошлые сутки, установка «не готова».
  4. Проверка «отчёт не из будущего» (`report-validation.service.ts:38`) — тоже по Москве: тенант восточнее не сдаёт отчёт за своё «сегодня» между 00:00 и 07:00 местного.
  5. `leadTimeDays` («предупредить за N дней») задаётся только при создании вида документа; изменить срок у существующего вида из интерфейса нечем (`user-document-types-dialog.tsx:166-183`).

5. Проверялись именно точки чтения: серверные выборки (`modules/**`), маршруты `app/api/**`, клиентские формы и дашборды. Для каждой находки приведён `path:line`, который я открывал в этой сессии (или строки из грепа с контекстом).
6. Severity по заданию: критично — настройка про безопасность/деньги (допуск, блокировки, закрытие смены) не действует; важно — действует частично; мелочь — косметика.
7. Ничего в коде не менял: задача read-only, единственный созданный файл — этот отчёт.
