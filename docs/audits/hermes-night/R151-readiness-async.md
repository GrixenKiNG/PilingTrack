  1. **важно** — сбой **истории** готовности (`/api/readiness/history`) выдаётся за сбой **текущего
     снимка**: `setAuthoritativeReadinessError(currentResult.error ?? historyResult.error)`

     «Авторитетная оценка недоступна» / «Не подтверждено» (`fleet-workspace-model.ts:63-65`,
     `readiness-centre.tsx:396-398`), хотя снимки на месте. Один несвязанный источник гасит доску.
  2. **важно** — догрузка журнала/карточки при выборе установки помечает **отказ источника за успех**:
     `setJournalLoaded(..., true)` выполняется безусловно, а записи берутся как `journal?.records ?? []`
     (`to-module.tsx:602-605`); при первой загрузке сделано правильно — `primaryJournal.data != null`
     (`to-module.tsx:547-548`). Ошибка 500/403 на `/api/to/journal` для выбранной позже машины читается
     как «журнал пуст» (`readiness-model.ts:99-105,197-204`), а не «журнал недоступен».
  3. **важно** — догрузка пользуется «молчаливым» `readOptionalJson` (`to-module.tsx:173-181`) и не
     пишет `WorkspaceIssue`, поэтому панель парка не может показать причину: она ищет ошибку по
     источнику ``Карточка «<имя>»`` (`fleet-evidence-panel.tsx:48`), а такой источник создаёт только
     первичная загрузка (`to-module.tsx:528-531,536-537`). Для машины, выбранной после первой загрузки,
     остаётся общее «Подробности установки ещё не получены» (`fleet-evidence-panel.tsx:74-77`).
  4. **важно** — производная модель `readinessByEquipment` (`to-module.tsx:611-668`) **не имеет ветки
     `authoritativeReadinessError`** в отличие от парка/центра, а её читают «Отчёты»
     (`reports-screen.tsx:100-107`) и блок «Экипажи и загрузка» смен (`shifts-screen.tsx:263-275`):
     там сбой авторитетного чтения не показан, экран считает по производной оценке.
  5. **мелочь** — догрузка пропускает повтор, если удалась любая из двух половин:
     `journalLoaded[equipmentId] || details[equipmentId]` (`to-module.tsx:589`). Упавшая карточка при
     успешном журнале больше не перезапросится до полной перезагрузки.
