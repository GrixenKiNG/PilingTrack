## Итог

Резюме для владельца (5 строк):
1. Отдельного «сменить свой пароль» в системе нет: пароль меняет только администратор через «Пользователи» → «Редактировать» (`src/app/api/users/route.ts:95`).
2. Любая смена пароля повышает `User.sessionVersion` на 1 (`src/services/users/user-service.ts:236-238`), и из-за этого у пользователя гаснут СРАЗУ ВСЕ сессии — на всех устройствах, включая текущую.
3. «Отозвать только другие сессии, а свою оставить» технически невозможно: счётчик один на пользователя, различия между сессиями в нём нет.
4. Если администратор меняет пароль сам себе, он немедленно вылетает из системы: подтверждения нет, предупреждения нет, новая cookie не выписывается (`src/app/api/users/route.ts:117-118`).
5. Токены устройств (ключи телеметрии `DeviceKey`) к смене пароля отношения не имеют и не отзываются — они привязаны к технике, не к человеку.

Числа: найдено 8 находок — критично 0, важно 3, мелочь 5.

Топ-5 по значимости:
1. Счётчик `sessionVersion` глобальный: смена пароля гасит все сессии, включая текущую; «другие сессии» отдельно не отзываются (важно).
2. Саморедактирование администратора = мгновенный самовылет без предупреждения и без перевыпуска cookie (важно).
3. Смена пароля неотличима в журнале аудита и в «Истории» карточки пользователя — видно только «Пользователь изменён» (важно).
4. Кэш `authUserCache` в `src/lib/auth.ts` никогда не читается — мёртвая ветка, вводящая в заблуждение комментарием.
5. Блокировка входа в Redis не снимается при смене пароля: заблокированный сотрудник после сброса пароля всё равно не войдёт (гипотеза).
