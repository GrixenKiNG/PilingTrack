## Что видит человек: действие за действием

Тексты дословно; источник — файл:строка.

### 1. Открыть журнал (`?view=briefings`)

Успех: заголовок «Инструктажи» + подзаголовок, 4 + 5 KPI-плиток, строка фильтров, таблица (11 колонок), правый блок и примечание (`briefings-screen.tsx:247-266,268-293,301-467,521-529`).

- **403.** Сервер `{"error":"Недостаточно прав для просмотра журнала инструктажей"}` (`briefing-journal-query.ts:95`). Экран: `setFailed(body.error)` → абзац `role="alert"` тем же текстом (`briefings-screen.tsx:119-124,295-299`). Про права сказано верно; кнопки «Повторить» рядом нет (повтор — только общий «Обновить», `:256`). Достижимо по прямой ссылке ролью без `users.documents.read_all`: `?view=` закреплён, вкладку не подменяют (`to-module.tsx:319,356-363`).
- **401.** `authFetch` разлогинивает в store (`api.ts:56-69`), раскладка уводит на `/login` (`(app)/layout.tsx`), но до перехода абзац успевает показать серверное **«Unauthorized»** (`auth.ts:166` → `briefings-screen.tsx:122`).
- **5xx.** «Внутренняя ошибка сервера. Повторите попытку; если повторится — сообщите администратору.» (`api-wrapper.ts:131`) в том же абзаце — по-русски, верно.
- **Обрыв сети.** `fetch` бросает `TypeError`; `error.message` = **«Failed to fetch»** в абзаце (`briefings-screen.tsx:122`).
- **Пусто.** «За выбранный период записей нет.» / «По запросу ничего не найдено.» (`:385-390`) — уместно.
- **429.** «Слишком много запросов. Подождите немного и повторите.» (`api-wrapper.ts:204`) абзацем — по-русски.

### 2. Фильтры (период, вид инструктажа, состояние, вид записи, объект, инструктор, поиск)

- Успех: смена любого серверного фильтра перезапускает `load` и заменяет таблицу (`briefings-screen.tsx:103-125`); «Объект», «Инструктор», поиск фильтруют уже загруженные строки на клиенте (`:200-216`).
- **«Объект» не работает никогда**: опции строятся из `row.siteName`, а маршрут `siteName` не отдаёт вовсе (`briefing-journal-query.ts:56-77`). Селект всегда «Все объекты» без опций, колонка «Объект» всегда «—». Комментарий `:346` («Объект и инструктор фильтруются на клиенте: сервер их не принимает») вводит в заблуждение: инструктор отдаётся (`:148`), объект — нет.
- Перевёрнутый период молча разворачивается (`briefing-journal-view.ts:123-129`) — «записей нет» без намёка, что даты поменяли местами.
- Неверный `kind/type/status` → сервер 400 с русским текстом (`journal/route.ts:39,46,51`), но селекты всегда дают только валидные значения.

### 3. Провести инструктаж (диалог «Провести инструктаж»)

- Успех: диалог закрывается, список перечитывается (`briefings-screen.tsx:577`). **Сообщения об успехе нет** — ни тоста, ни строки (`briefing-conduct-dialog.tsx:75-78`).
- Список работников берётся из `/api/safety/clearance` один раз при монтировании (`:132-145,151`); ошибка чтения **проглатывается** (`catch {}`). Если запрос отказал, селект пуст, кнопка серая — тупик без объяснения.
- **400** (zod): «Некорректные данные» без построчных деталей (`briefings/route.ts:40-45` → диалог `:71-82`). «Основание» длиннее 500 символов даёт ту же строку без указания поля (`:18`).
- **403 по правам**: «Недостаточно прав для проведения инструктажа» (`briefing-commands.ts:56`) — по-русски, верно. **403 CSRF**: «CSRF validation failed: origin mismatch» (`csrf-protection.ts:78` → диалог `:73`) — английская строка.
- **404**: «Работник не найден» (`briefing-commands.ts:71`); **400**: «Работник не числится действующим» / «Инструктаж нельзя записать будущей датой» (`:73,80`) — по-русски.
- **5xx**: «Внутренняя ошибка сервера. …»; **429**: «Слишком много запросов…» — по-русски.
- **Обрыв сети**: **«Failed to fetch»** (`briefing-conduct-dialog.tsx:82`).
- **401**: logout в store + уход на `/login`; диалог исчезает без сообщения.
- 409 к созданию записи неприменим (уникальных ограничений нет).
- Необратимость: запись неизменяема (нет update/delete), о чём честно сказано в диалоге и в примечании экрана (`briefing-conduct-dialog.tsx:133-137`; `briefings-screen.tsx:521-529`). Подтверждения действие не требует — ок.

### 4. Печатная форма журнала (`Печатная форма` → `/print/briefing-journal`)

- Успех: лист A4 landscape, шапка «Журнал регистрации инструктажей по охране труда», организация/период/вид, таблица, подписи; диалог печати открывается сам один раз (`briefing-journal-print.tsx:135-206,104-108`). Пустой журнал и отказ не печатаются (`:105`).
- **Период в ссылке отсутствует** → «В ссылке не указан период журнала.» (`:63`) — по-русски.
- **403** → «Недостаточно прав для просмотра журнала инструктажей» (`:79` от `briefing-journal-query.ts:95`). **401** → **«Unauthorized»** в теле листа (`:79`, `auth.ts:166`). **Обрыв** → **«Failed to fetch»** (`:93`). Строка для прочих не-ok — `Сервер вернул ${status}` (`:79`).
