## Итог

- Находок 14: **критично — 0**, **важно — 5**, **мелочь — 9**. Потерь данных в сценарии «двое правят одну карточку» не видно (перезапись молчаливая, но последняя), зато найдены два класса, которых не было ни в R97, ни в 38-concurrency.
- Главное: **схема PUT оживляет дефолты** — при каждом сохранении из формы `qty` уезжает в 1, а частичный PUT без `isActive` возвращает выведенную из эксплуатации установку «в работу». Проверено прогоном zod.
- **409 на карточке не наступает вообще**: у `PUT /api/equipment/[id]` нет токена версии (механизм есть только у отчётов). Двое админов правят одну установку — побеждает последний, оба видят «Установка сохранена».
- **Несохранённые правки теряются без вопроса**: Esc, клик вне окна, «Отмена», ссылки внутри вкладки «Обслуживание ТО» — всё закрывает/уводит молча. В проекте уже есть образец защиты (`layout-editor.tsx`, `use-report-form.ts`).
- **Очистка поля не сохраняется**: форма обещает «пустое поле ⇒ стереть» (`equipment-form.tsx:10-12`), но сервер превращает `null` в «не трогать» — стёртый VIN/модель/описание возвращаются после переоткрытия.
- **После правки список парка не перечитывается**: переименованная установка в плитке/таблице слева показывает старое имя до перезагрузки страницы (правка обновляет только правую карточку).
- Топ-5 по важности: (1) дефолты `qty`/`isActive` на PUT; (2) нет версии/409; (3) потеря несохранённого без вопроса; (4) очистка полей не работает; (5) список не обновляется после сохранения.
- Классы-повторы R97: тексты 400/401/403-CSRF (R97 №9, №10), «отказ выдан за пустоту» на вкладке ТО (R97 №11), таргеты/лейблы формы (R116 №2), тон «ты/вы» (R97 №18).
