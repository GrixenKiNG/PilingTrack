## Не проверено

- **Многопроцессность/многоинстансность прода** (п. 4): сколько инстансов крутится и общий ли у них Redis — не читал конфигурацию развёртывания; вывод «in-memory fallback не общий» — по коду, не по факту. ГИПОТЕЗА.
- **Фактические значения env** (`REDIS_URL`, `RATE_LIMIT_BYPASS`, `TRUST_PROXY`) в проде — файлы `.env*` не читались (запрещено). В `docker-compose.yml:81-82` `REDIS_URL` задан, поэтому в штатной сборке лимитер использует state-Redis, а не память; для иных окружений — не проверено.
- **Реальный сброс пароля через UI end-to-end:** e2e `e2e/admin-users.spec.ts` проверяет таблицу/поиск/панель, но сценарий «админ ввёл новый пароль → пользователь вошёл новым паролем» в нём не найден. Прогон Playwright не выполнялся (только `--list`: 291 тест в 27 файлах). НЕ ПРОВЕРЕНО.
- **Соответствие требование↔БД:** `prisma/schema.prisma` User.password допускает пустую строку (`@default("")`, строка 97); создание/правка требуют пароль на уровне сервиса, но БД инвариант «непустой пароль» не гарантирует. Полнота гарантии на уровне схемы не проверялась (схему не правим).
- **Смена пароля администратором самому себе и дальнейший вход** — по коду `sessionVersion++` гасит сессии, поведение UI после этого (разлогин/редирект) не прогонялось.
- **Проверки `npm run build`, `npx tsc --noEmit`, `npm run lint`** не запускались: задача read-only по коду, изменения не вносились. Unit-тесты и Playwright-список прогнаны (см. «Методика»).
