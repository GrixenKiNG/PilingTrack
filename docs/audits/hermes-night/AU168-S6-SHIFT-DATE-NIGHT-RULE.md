# AU168-S6-SHIFT-DATE-NIGHT-RULE: Ночная смена — дата отчёта и дата забивки

Задача: по КОДУ разобрать, как определяется `productionDate` смены 19:00–07:00, дата отчёта,
дата записи сваи после полуночи и окно автозакрытия; где эти правила расходятся.

- Репозиторий: `D:\PillingR\wt-night`, ветка `hermes/q4-0926`.
- Версия: `git rev-parse HEAD` → **f616a287a58e108daeaa916afce08f560b3d2900**
- Только чтение: код приложения не менялся. Единственный созданный файл — этот отчёт.
- Числа получены запуском node-скриптов, воспроизводящих код (см. «Методика»).

## Итог

По коду **производственные сутки смены — это календарный день** (в поясе работника/тенанта),
а не сутки смены 19:00–07:00. Окно 19:00–07:00 живёт отдельно и только для плановой шкалы
(`SHIFT_WINDOW`) и для окна автозакрытия (`SHIFT_END_HOUR`). Из-за этого граница «производственных
суток» приходится на **полночь**, то есть **посреди ночной смены**.

Найдено 14 находок: **2 критично, 7 важно, 5 мелочь**. Топ-5:

1. **критично** — в 00:00 посреди ночной смены день СИЗ-проверки меняется, и фаза оператора
   откатывается на «Допуск» (человека выбрасывает с экрана работы на СИЗ).
2. **критично** — оценка готовности машины теряет «осмотр за сегодня» в полночь
   (`readiness-score.ts:97-106`), хотя машину осматривали в этой же смене.
3. **важно** — у ночной смены, начатой после полуночи, плановое окно уезжает в **будущее**
   (00:30 → плановое начало 19:00 того же дня): проверено числами.
4. **важно** — автозакрытие такой смены срабатывает на **24 часа позже** реального конца
   (12:00 следующего дня вместо 12:00 текущего): проверено числами.
5. **важно** — дата забивки в журнале (`occurredAt`) — это момент **приёма** команды сервером,
   а не момент забивки; сваю, забитую в 23:50 и отправленную в 00:10, журнал отнесёт к новым суткам,
   а отчёт — к старым.

Положительный вывод: документированное решение владельца (`docs/product/tech-readiness-module-spec.md:410-413`)
описывает именно календарные сутки, и код ему соответствует. Расхождение — не в выборе правила,
а в том, что **границы суток (полночь) и границы смены (07:00/19:00) не совпадают**, и все
«суточные» проверки сбрасываются посреди ночи.
