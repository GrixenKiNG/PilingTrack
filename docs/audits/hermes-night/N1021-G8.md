1. Поиск `setInterval|setTimeout` в `src/core/**`, `src/workers/**`, `src/services/**`, `src/lib/**` через `search_files`.
2. Каждый найденный файл открыт через `read_file` для анализа контекста.
3. Проверено наличие `clearInterval`/`clearTimeout` в том же модуле, условия остановки, возврат функции остановки, вызов shutdown.

## Примечание про Next.js hot reload

В Next.js (особенно с Turbopack) при изменении файлов модули пересобираются и переимпортируются. Модульные переменные (`let x = ...`) пересоздаются, `globalThis` — нет. Таймеры, запущенные в теле модуля или в конструкторе синглтона, экспортируемого из модуля, **не очищаются автоматически** при reload. Старый таймер продолжает работать в фоне, новый добавляется. Это источник утечек памяти и «призрачной» нагрузки на БД/Redis в dev и (при неправильной сборке) в проде при перезапуске воркеров.

Рекомендуемый паттерн (уже используется в `lag-monitor.ts:94-95`, `health-tracker/tracker.ts:8-9`, `tenant-context.ts`):
```ts
const globalKey = '__pilingtrackMyTimer__';
const g = globalThis as typeof globalThis & { [globalKey]?: ReturnType<typeof setInterval> };
if (g[globalKey]) clearInterval(g[globalKey]);
g[globalKey] = setInterval(...);
```
Или — явные `start()`/`stop()` с вызовом `stop` в `gracefulShutdown` и (для dev) в `instrumentation.ts` / middleware при перезагрузке.
