# AU217-S2 — Черновики отчётов: жизненный цикл и потери

Версия: `git rev-parse HEAD` = `b13a7c2cae26eefbe3375ae64223d206e3e2bdc5`
Ветка: `hermes/q4-0926`. Только чтение кода; ни один файл приложения не менялся.
Отчёт: `docs/audits/hermes-night/AU217-S2-DRAFT-REPORT-LIFECYCLE-GAPS.md`

## Итог

Аудит двух независимых форм сменного отчёта: операторской (`src/components/piling/report-form/`) и админской (`src/components/piling/admin-reports/report-form-dialog.tsx`). У операторской формы есть автосохранение черновика в `localStorage`; у админской диалоговой формы автосохранения НЕТ вообще.

- Находок: 13. По важности: критично — 0, важно — 7, мелочь — 5, гипотеза — 1.
- Топ-5:
  1. Админская форма при повторном открытии НЕ пересоздаётся (`key` остаётся `'new'`) — в ней остаются строки прошлого отчёта (report-form-dialog.tsx:99,127; admin-reports.tsx:614).
  2. `reportId` не сохраняется в черновике — фото, загруженное до перезагрузки, «осиротеет» и не прикрепится к отчёту (use-report-form.ts:102,317-340).
  3. Две вкладки: сервер заменяет строки по естественному ключу без слияния, версия не проверяется — последняя вкладка стирает выработку первой (report-command.service.ts:124-129,325).
  4. Переход внутри SPA (кнопка «назад», `router.push`) не пишет черновик: таймер 800 мс сбрасывается без сохранения, `beforeunload` при SPA-навигации не срабатывает (use-report-form.ts:298-303).
  5. Админская форма теряет ВСЁ набранное при закрытии/Esc/клике мимо (report-form-dialog.tsx:127,231) — подтверждено отсутствием черновика.
- Самый важный вывод: админская `ReportFormDialog` живёт между открытиями и накапливает чужое состояние; это ведёт к сохранению неверных данных или к 409 при смене даты.
