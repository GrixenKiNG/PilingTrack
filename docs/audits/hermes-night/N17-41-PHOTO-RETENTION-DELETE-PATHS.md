- Топ-5: (1) спящий `runRetention(90)` — готовое удаление фото, противоречащее «навсегда», если его подключить; (2) отсутствие внешнего ключа на `Media` — почему удаления сущностей не задевают фото; (3) `hardDelete` удаляет строку БД даже при сбое S3 (`:407-414`) — осиротевшие объекты, но только если механизм запустят; (4) фоновая уборка покрывает лишь временные PDF, не медиа; (5) отсутствие теста на переживание фото удаления сущности.

## Ответы на вопросы задания

**(1) При удалении отчёта, записи ТО, чек-листа, сотрудника или объекта — удаляются ли связанные файлы?**
**Нет, ни в одном из пяти случаев.** Внешнего ключа на `Media` нет (`grep "Media\\b"` по `prisma/schema.prisma` — только поля `mediaId` без relation, `:202`, `:551`), поэтому каскад до фото не доходит. Детали — в таблице ниже; все пять путей ПРОЙДЕНО.

**(2) Есть ли фоновая задача очистки файлов?**
**Для фото — нет.** Единственная фоновая уборка — временные PDF: `src/workers/unified-worker/pdf-cleanup-scheduler.ts:7` (включается только при `PDF_TEMP_CLEANUP_ENABLED==='true'`, `:8`; первый прогон — dry-run, `:16`) вызывает `cleanupTemporaryPdfs` (`src/lib/pdf-generator/cleanup.ts:29`), который удаляет только объекты с префиксом `pdf-results` (`:78`) и по коду «Never scans Media» (`:28`). Механизм `runRetention` (`media-service.ts:442`) существует, но не вызывается ниоткуда (0 совпадений). ПРОЙДЕНО.

**(3) Может ли удалить фото обычный пользователь, и кто именно?**
Может, но только **мягко** (файл остаётся) через `DELETE /api/media/[id]` (`src/app/api/media/[id]/route.ts:9`). Права — `assertCanAccessMedia` (`src/core/media/media-auth.ts:186`): платформенные ADMIN/DISPATCHER — любое фото (`isPrivilegedRole`, `:203`); загрузивший — своё (`media.userId === actor.id`, `:208`, то есть оператор своё фото); для фото оборудования (`entityType='equipment'`) мутация — **только ADMIN** (`:199`). Маршрут под `withMutation` (`:9`) → CSRF + лимит. Физического удаления правом не даёт никто. ПРОЙДЕНО.

**(4) Совпадает ли поведение с решением владельца «фото навсегда»?**
**По проверенным путям — совпадает:** безвозвратного удаления фото нет (см. таблицу). Оговорка: в репозитории **не найдено** самого документа с этим решением (см. находку 15) — сверка сделана с формулировкой задания. И есть спящий механизм `runRetention(90)`, который при подключении нарушит решение (находка 1).

**(5) Есть ли тест на сохранность?**
**Прямого теста «фото переживает удаление сущности» нет** (находка 7). Косвенно сохранность подтверждают: `tests/integration/disposable-m6-m8.spec.ts:164-191` (уборка временных PDF не трогает строки `Media` и файлы фото — побайчно, `:189-190`); `tests/integration/disposable-idor.spec.ts:142` (чужое удаление не меняет `isDeleted`); `src/core/media/__tests__/filter-readable-media.test.ts:46-47` (удалённые/незавершённые исключаются из чтения).
