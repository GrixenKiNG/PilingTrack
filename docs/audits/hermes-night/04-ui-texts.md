# Аудит UI-текстов: корректность и согласованность русского языка

Дата: 2026-09-25 · Ветка: hermes/night-0925 · READ-ONLY (файлы не менялись)

## Итог

Просканированы UI-тексты в `src/components/**` и `src/app/**/page.tsx` (операторские экраны — read-only),
плюс сообщения об ошибках API-роутов, которые показывает интерфейс. Большинство экранов — чистый,
качественный русский: в плейсхолдерах, aria-метках и JSX-тексте английских строк почти нет (кроме
бренда и 4 технических исключений). Проблемы сгруппированы в 4 класса.

Итого: **критично 0 · важно 7 · мелочь 9** (всего 16 находок).

Топ-5:
1. API аутентификации возвращает английские ошибки, и форма входа показывает их пользователю дословно:
   «Invalid credentials» / «Too many login attempts» вместо русского.
2. Одна и та же ошибка «нужны даты» переведена в разных роутах по-разному: где-то по-русски,
   где-то по-английски.
3. Единица наработки моточасов пишется по-разному: «м/ч» (читается как «метров в час»), «м.ч.», «л/моточас».
4. Модуль ТО называется в интерфейсе тремя именами: «ТО», «Обслуживание», «наряд/журнал ТО» (две ТО-ловушки).
5. Роли дублируются в трёх картах labels, и в истории отчётов чужую неизвестную роль интерфейс помечает
   как «Оператор».

Откровенных орфографических опечаток в выборочно прочитанных крупных файлах не найдено
(см. «Не проверено» про охват).

## Методика

Всё read-only, только `search_files`/`read_file`. Проверяемые шаги (повторяемы):

1. Глоссарий: `.claude/skills/domain-glossary/SKILL.md` и `references/terms.md` — эталонная лексика
   (установка/копёр, две ТО, простой, свая/куст/пикет, ЕО/ТО).
2. Центральные карты меток, чтобы искать рассинхрон терминологии: `REPORT_LABELS` (`_LABELS`),
   `ROLE_LABELS` (lib/types.ts), `KIND_LABELS`/`HAMMER_KIND_LABELS` (equipment-form.tsx),
   static-метки в `maintenance-labels.ts`, `report-history.ts`, `audit-history-service.ts`.
3. Поиск английского в JSX: `>[A-Z][A-Za-z]{2,}`, `>[A-Za-z]+ [A-Za-z]+<`, `>[A-Za-z]+;[A-Za-z]`,
   `placeholder="[A-Za-z]`, `(aria-label|title|placeholder)="[A-Za-z]`, `[а-я] [A-Za-z]{2,}` по
   `src/components` и `src/app`.
4. Ошибки API: `error: [..][A-Za-z]`, `{ message: [A-Za-z]`, `error: 'Validation*'` по `src/app/api`.
5. Чистка шума: система «>…</» ловит бренд (PilingTrack) и технические аббревиатуры (SHA-256),
   отделена от кода. Опечатки проверялись ручным чтением крупных файлов (report-form, report-history,
   admin-dashboard, fleet-dashboard, work-screen оператора, to/readiness screens, maintenance), не авто-скором.

Результат: английские JSX-строки встречаются только в 4 местах (DLQ, Bot Token/Chat ID, PDF Preview,
бренд) — сам UI «по-русски».

## Не проверено

- **Полный орфографический прогон.** Авто-скор русского текста не запускался (нет инструмента/словаря).
  Опечатки искали ручным чтением ~15 крупных UI-файлов; мелкие файлы (админ-диалоги, to/readiness-подэкраны,
  лендинг ORION — заморожен) прочитаны фрагментарно/через grep. Возможны пропущенные опечатки в непрочитанных
  файлах.
- **Реальный рендер.** `npm run build`/сервер не поднимался; все выводы — по исходникам. Не проверено, какие
  именно из англ. ошибок API (класс B) рендерятся пользователю в админ-панели дословно, а какие клиент
  перехватывает и заменяет (подтверждён только случай входа — он показывается дословно, находка 1).
- **Замороженные зоны.** Экранные варианты оператора (v2/v3/v5/v7/v10/operator-mobile) и публичный ORION
  просканированы только по grep на английский; находки 10/16 в них зафиксированы read-only, как требует задача.
  Терминологический разнобой между этими вариантами («Завершить работу»/«Закрыть смену»/«Сдать смену») связан с
  тем, что владелец ещё выбирает финальную версию — править не стал.
- **EN-строки в не-рендерящихся путях.** Английские ошибки PDF/telemetry/device-key роутов часто машинно-ориентированы
  и не показываются человеку; их точная видимость пользователю не проверялась.
