- Топ-5:
  1. **409 перезагружает форму поверх несохранённых строк.** Любой серверный 409 (в т.ч. «свая с паспортом», «строка отчёта отсутствует») приводит к `loadData()`, который заменяет строки данными сервера, а текст советует «Обновите страницу и сохраните заново» — то есть правки уже потеряны (`use-report-form.ts:434-441`).
  2. **Набранная строка стирается до того, как стало известно об успехе.** `submitWithPending` очищает поля ввода сразу после вызова `handleSubmit`, но та при отказе валидации (не выбрана установка, нецелые моточасы) выходит раньше, чем строка попадает в состояние — человек теряет ввод (`report-form.tsx:180-185`).
  3. **Обрыв сети при отправке показывается английским «Failed to fetch»** (`use-report-form.ts:461-463`) — повтор находки 41 №3, в коде не исправлено.
  4. **CSRF-403 и 401 показываются сырым английским** («CSRF validation failed: …», «Unauthorized») — `use-report-form.ts:442` + `csrf-protection.ts:66-112` + `auth.ts:166`. M4 для админской формы CSRF перевёл — здесь нет.
  5. **Уход с формы не подтверждается, а автосохранение черновика опаздывает.** Черновик пишется по таймеру 800 мс и по `beforeunload`, который при переходе внутри приложения (`router.push`) не срабатывает, а таймер на размонтировании очищается — правки за последние <800 мс теряются молча (`use-report-form.ts:281-307`, `report-form.tsx:239`).
