## Итог

- Находок 22: **критично — 0**, **важно — 10**, **мелочь — 12**. Потери данных в сценарии диспетчера не найдено; проблема — враньё и разнобой в объяснении отказов.
- Главный дефект класса: на экране нет **ни одного** разбора «отказ по правам» (403). Все четыре места, куда приходит серверное «Доступ запрещён» (`authorization-service.ts:164`), показывают четыре разных текста, и ни один не говорит, что дело в правах.
- Топ-5:
  1. **403 на списке выглядит как поломка сервера** — `use-reports-data.ts:229` → «Не удалось загрузить отчёты. Сервер вернул ошибку.» Кнопка «Повторить» рядом будет отказывать всегда.
  2. **Конфликт 409 при правке загоняет в цикл и советует потерять правки** — текст «Обновите страницу и сохраните заново» (`report.repository.ts:124`) показан тостом поверх открытого диалога, но `version` в диалоге не перечитывается: повторное «Сохранить» даёт тот же 409, а выполнение совета закрывает форму и стирает введённое.
  3. **Английские строки в русском интерфейсе**: сеть в форме/выгрузке/журнале — «Failed to fetch» (`report-form-dialog.tsx:198`, `admin-reports.tsx:106`, `pile-journal.tsx:161,183`); CSRF-403 — «CSRF validation failed: origin mismatch» (`csrf-protection.ts:78`); 401 в журнале — «Unauthorized» (`auth.ts:166`).
  4. **Предпросмотр и скачивание PDF не имеют обработки отказа вовсе**: iframe грузит `/api/reports/single-pdf` напрямую — при 403/404/429/504/500 в модальном окне показывается сырой JSON; кнопка «Скачать» — обычная ссылка `<a href>`, которая уводит на страницу с JSON (`report-evidence-preview.tsx:200-205`, `pdf-preview-dialog.tsx:60-67`).
  5. **Ошибка удаления показывает служебный JSON с кодом** — `Ошибка удаления (403): {"error":"Доступ запрещён"}` (`admin-reports.tsx:134-135`). R41 №20 указывал этот класс на 500; на 403/404 он воспроизводится так же.

## Что видит диспетчер: сценарий за сценарием

Тексты дословно; источник — файл:строка.

### 1. Открыть список отчётов

Успех: шапка `Отчёты` + бейдж «N отчётов» (`report-evidence-row.tsx:57-61`, счёт из `admin-reports.tsx:182,227`), строка отбора «Загружено N · показано M» (`admin-reports.tsx:323-325`), KPI-плитки с подписью области («сданные · весь отбор» либо «по загруженным N из M», `report-evidence-row.tsx:131-135,157-161`), список строк.

- **403.** Сервер отвечает `{"error":"Доступ запрещён"}` (`authorization-service.ts:164` через `withApi:108-112`). Экран: `setError('Не удалось загрузить отчёты. Сервер вернул ошибку.')` + тост «Ошибка загрузки отчётов» (`use-reports-data.ts:229,233`) и баннер «Не удалось загрузить отчёты» / «Не удалось загрузить отчёты. Сервер вернул ошибку.» с кнопкой «Повторить» (`admin-reports.tsx:234-238`, `async-ui.tsx:64-80`). Про права — ни слова; повтор будет отказывать так же. Достижимо: администратор в режиме «Действую как OPERATOR» проходит серверный гвард раскладки (он по своей роли, `require-page-ability.ts:8-9`), а запрос уходит с `x-acting-as` (`api.ts:20-23`) и получает 403.
- **5xx / обрыв.** Тот же текст для 5xx (`:229`); для обрыва — «Не удалось загрузить отчёты. Проверьте соединение.» (`:237`). Тост «Ошибка загрузки отчётов» дублирует заголовок баннера.
- **Пусто.** «Отчёты не найдены» + «Попробуйте изменить быстрые фильтры, период, объект, установку или оператора.» (`admin-reports.tsx:342-345`).
- **401.** `authFetch` делает logout в store (`api.ts:66-68`), раскладка уводит на `/login` (`(app)/layout.tsx:339-343`). Сообщения об истечении сессии нет.
- **409** к чтению неприменим.

### 4. Править отчёт (диалог «Сформировать/Редактировать отчёт»)

- Успех: тост «Отчёт создан» / «Отчёт обновлён», диалог закрывается, список перечитывается (`report-form-dialog.tsx:195-196`).

- **400** (admin-upsert, zod): «Некорректные данные» + до 3 построчных строк из `details.fieldErrors` (`:194`, `api-error-message.ts:16-25`). Незнакомое поле остаётся техническим: «Поле count: …» (`api-error-message.ts:85`).

- **403 по правам/окну/владению** — русское: «Отчёт принадлежит другому пользователю», «Окно редактирования истекло: отчёт сдан N ч назад, правка — через администратора» (`report-command.service.ts:148,215`).
- **409** — три разных русских текста, все показаны тостом:
  - «Отчёт был изменён другим пользователем. Обновите страницу и сохраните заново.» (`report.repository.ts:124`) — `version` диалога не перечитывается, поэтому повтор кнопкой даёт тот же 409; выполнение совета закрывает форму и теряет введённое;
  - «Этот отчёт заведён на другую дату или другой объект. Обновите форму и отправьте заново.» (`report-command.service.ts:170-173`);
  - «Смена ещё идёт — выработку записывайте на экране смены, отчёт сдаётся при её закрытии.» (`:200-203`).
- **5xx**: «Внутренняя ошибка сервера. Повторите попытку; если повторится — сообщите администратору.» (`api-wrapper.ts:131`) — русский. **Обрыв сети**: тост с браузерным «Failed to fetch» (`report-form-dialog.tsx:197-199`).

### 7. Выгрузить PDF (предпросмотр и «Скачать») — только чтение

### 9. Журнал забивки (вкладка `?view=piles`, право `piles.manage`)

### Повторы одного и того же текста на разные ситуации (сводка)

- Отказ по правам: «Не удалось загрузить отчёты. Сервер вернул ошибку.» (список) / `Ошибка удаления (403): {"error":"Доступ запрещён"}` (удаление) / тост «Доступ запрещён» (выгрузка) / абзац «Доступ запрещён» (журнал) — четыре разных текста, ни один не про права.
