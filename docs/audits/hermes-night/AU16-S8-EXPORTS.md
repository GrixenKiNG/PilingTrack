Версия: `git rev-parse HEAD` рабочей папки = `8e945af60a3ccc2a9680a5d8c2b2e36afbb06fb4` (ветка `hermes/q4-0926`).

## Итог (резюме для владельца, 5 строк)

1. Из системы выгружаются: отчёты (CSV/XLSX), журнал забивки (XLSX), 5 наборов техготовности (CSV), PDF сводный/одиночный, печатная форма журнала инструктажей, плюс печать экранов браузером. Всего 11 точек выгрузки (см. таблицу A).
2. Организация везде фильтруется строгим равенством `tenantId` — «утечки чужого тенанта» в выгрузках не нашёл (ПРОЙДЕНО). Права разведены: отчёты — только ADMIN, журнал забивки — piles.manage, PDF — reports.read_all, техготовность — readiness.read / readiness.audit.export.
3. Два «тяжёлых» места без потолка объёма: выгрузка отчётов CSV/Excel грузит весь период в память без LIMIT (ограничен только 92 днями), и выгрузка техготовности читает всю цепочку аудита и все снимки без LIMIT (важно).
4. Уйти «с чемоданом данных» нельзя: нет ни одного маршрута «выгрузить всё»; отчёты доступны только администратору и окнами по 92 дня; не выгружаются пользователи, объекты, бригады, справочники, техника (кроме реестра), фото, ТО, осмотры, дефекты, инструктажи, происшествия (важно).
5. Мелочи: пустой XLSX отчётов выглядит как успешная выгрузка; кнопка «Справочники» в техготовности выгружает реестр техники, а не справочники; имя файла журнала забивки задаётся на клиенте и расходится с серверным.

Счёт по важности: критично — 0, важно — 4, мелочь — 6. Итого находок — 10.

- Поля: перечитаны рендеры PDF (`src/lib/pdf-generator/*.ts`), заголовки CSV/XLSX (`report-export.service.ts`, `pile-journal-export.ts`, `csv-export.ts`).
