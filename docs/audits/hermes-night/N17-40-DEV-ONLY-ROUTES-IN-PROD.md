## Ответы на вопросы задания

**(1) Маршруты, создающие/меняющие данные без проверки окружения.** Ни одного маршрута, который «работает только вне прода», нет. Все мутации либо под `withMutation` (CSRF + лимит + сессия), либо в перечисленных исключениях с собственной защитой (`route-guards.test.ts:142-171`). Окружение при этом не проверяется вообще — но и «dev-only» мутаций тоже нет. **Проверено (ПРОЙДЕНО).** Отдельно: путь, реально меняющий данные и предназначенный для dev, — сид `prisma/seed.ts`, запускаемый из compose (находки 1–2).

**(2) Окружение проверяется на сервере или только спрятано в UI?** На сервере окружение **не проверяется нигде** (0 совпадений по `src/app/api`). Скрытие в UI как единственная защита тоже не подтверждено: доступ к внутренним данным закрыт на сервере аутентификацией/ролью (`requireAuth`/`assertCan`). То есть разделение «dev/prod» в HTTP-слое отсутствует, но и необходимости в нём нет — нет маршрутов с dev-поведением.

**(3) Маршруты, отдающие внутренние данные без защиты ролью.** Все публичные GET-пробы отдают только статусы/версию/аптайм — это осознанное решение (`health/route.ts:4-10`). Единственные исключения-утечки внутренних деталей: `/api/liveness` (pid/память/версия Node/платформа, находка 3) и `/api/health/deep` (имена планировщиков, находка 4). Внутренние админ-данные (`/api/system/status`) закрыты `requireAuth` + `assertCan('system.read')` (`system/status/route.ts:24-30`); `/api/metrics` — токен скрейпа или сессия (`metrics/route.ts:39-50`). **ПРОЙДЕНО.**

**(4) Поведение при `NODE_ENV=production` и при отсутствии переменной.** В штатном контейнере `NODE_ENV=production` выставляется compose (`docker-compose.yml:72,165`), и тогда: cookie сессии ставится `Secure` (`session-service.ts:286,300`), при пустом `SESSION_SECRET` приложение падает на старте (`instrumentation.ts:46-50`), сид отказывается работать (`seed.ts:36`), тестовый обход лимитера `RATE_LIMIT_BYPASS` игнорируется (`rate-limiter.ts:178-183`). При **отсутствии** `NODE_ENV` все эти защиты ослабляются, но не отключаются полностью: `Secure`-флаг снимается, включается dev-фолбэк секрета (`session-service.ts:74-80`), обход лимитера становится возможен при `RATE_LIMIT_BYPASS=true`, а проверка `SESSION_SECRET` в `instrumentation.ts` не срабатывает. Сценарий реализуется только при запуске контейнера не через штатный compose (ручной `docker run`/`node server.js`). Находка 6.

**(5) Совпадают ли маршруты со сборкой Dockerfile?** **Да.** `next.config.ts:6` — `output: "standalone"`; никакой `outputFileTracingExcludes` или конфиг не вырезает маршруты по имени/окружению (исключаются только `tests/**`, `*.md`, `Dockerfile*`, конфиги — `next.config.ts:50-75`). В образ попадает всё, что есть в `src/app/api`. Побочно в боевой runner-образ кладётся `prisma/` (`Dockerfile:98`), а в migrate-стадию — `prisma/` целиком (`Dockerfile:61-62`), включая `seed.ts`.
