# Может ли ДИСПЕТЧЕР отработать полный день в приложении без тупиков

Аудит по коду ветки `hermes/q4-0926` (worktree D:\PillingR\wt-night). Только чтение, изменений в коде нет.

## Итог

Пройден день диспетчера по коду: утро (дашборд, готовность парка, происшествия), день (мониторинг, отчёты и черновики, назначение людей на объекты, бригады), вечер (сводка дня, незакрытые смены, автозакрытие +5 ч, Telegram).
Найдено 15 находок: критично — 1, важно — 9, мелочь — 5.
Главное: диалог назначения оператора на объект (`admin-sites/user-assignment.tsx`) молча проглатывает любой отказ сервера — «Назначить» нажимается, список не меняется, причины нет; тот же файл при сбое чтения назначенных показывает список как пустой.
Дальше по значению: автозакрытая смена ничем не отличима на экране от закрытой руками (`autoClosedAt` уходит в JSON, но не объявлен в клиентском DTO); незакрытая вчерашняя смена не видна в дефолтном виде «Смен» (фильтр «День» — только сегодняшние), а `HANDOVER_PENDING` не закрывается планировщиком никогда.
Вечерняя картина дня расходится между экранами: сводка по объектам и дашборд считают только сданные отчёты, «Мониторинг» — включая черновики, и на дашборде нужной подписи «включая несданные смены» нет.
В Telegram уходит только аварийное (критические дефекты, происшествия, просрочка ТО, DLQ) — вечерней сводки дня там нет вовсе.
Диспетчер имеет `reports.read_all` и `reports.manage_all`, но не `reports.export`: кнопки выгрузки CSV/Excel на экране «Отчёты» просто исчезают, без объяснения.
