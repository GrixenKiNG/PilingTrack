## Итог

- Найдено **9** находок: **критично — 0**, **важно — 4**, **мелочь — 5**.
- Главное: у шаблона раскладки нет ревизии/ETag и нет проверки версии при сохранении — запись идёт безусловным `upsert`, поэтому одновременное сохранение двух администраторов = «последний затирает первого целиком, оба получают «сохранено»».
- Дефект живёт в общем сервисе `layout-service`, а не только в мониторинге: те же 4 поверхности (`monitoring-equipment-tile`, `equipment-card`, `analytics-dashboard`, `main-dashboard`) страдают одинаково.
- Проект уже умеет решать этот класс: настройки берут advisory-замок (F-R38-11, `settings-service.ts:99`), отчёты — `expectedVersion` (`reports/upsert/route.ts:76`); у раскладки ни того, ни другого.
- Порядок и размеры плитки сервер проверяет по границам (width/height/x/y), но **наложение блоков не проверяется** — принимается любой непротиворечивый набор.
- Другие зрители видят новый шаблон только после полной перезагрузки страницы: клиент читает шаблон один раз при монтировании, шаблон не опрашивается и не рассылается между вкладками.
- Версия/ETag в схеме отсутствует: поле `version` внутри JSON — это версия формата (принимается только `1`), а не токен конкурентности; её легко принять за ревизию.
- Потери данных нет: шаблон — косметическая раскладка дашборда, восстанавливается повторным редактированием; поэтому «критично» не ставится.
- Проверку невозможно воспроизвести без БД/сборки (задача только на чтение) — статус рисков конкурентности «ГИПОТЕЗА/НЕ ПРОВЕРЕНО» там, где это указано.
- Правок в код не внесено; создан только этот файл отчёта.
