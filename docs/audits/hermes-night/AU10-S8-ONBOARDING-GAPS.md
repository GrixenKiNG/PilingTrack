## Итог

Подключение второго клиента сейчас не покрыто кодом почти нигде: путь «создать
организацию» существует только как строка в сиде (`prisma/seed.ts:119`), а не как
функция приложения. Резюме для владельца (5 строк):

1. Создать организацию можно только вручную (сид/сырой SQL); ни API, ни экрана
   для этого нет — `prisma/seed.ts:119` (критично).
2. Роли «администратор клиента» нет: `ADMIN` и `DISPATCHER` — платформенные и
   видят все организации; право `users.manage` есть только у `ADMIN`
   (`src/services/auth/authorization-service.ts:83`) (критично).
3. Приглашения пользователей нет: админ заводит человека и сам вписывает пароль
   (`src/app/api/users/route.ts:40`, `src/lib/validation-schemas.ts:47`);
   отправки писем в проекте нет — «SMTP не подключён»
   (`src/components/piling/to/readiness/settings/notifications-section.tsx:132`)
   (критично).
4. Справочники клиента наполняются только сидом
   (`src/services/dictionaries/tenant-dictionary-initializer.ts:15` вызывается
   лишь из `prisma/seed.ts:267`); импорта данных нет; экспорт — только
   операционные CSV; удаления организации нет; лимиты (`maxUsers` и пр.) не
   проверяются нигде.
5. Итого по коду: блокирующих пробелов — 3 (создание организации, роль
   админа клиента, приглашение), важных — 12, мелких — 2. Всё
   «первоначальное наполнение» сегодня делается руками: `prisma/seed.ts`,
   `scripts/seed-*.ts`, `scripts/seed-sites.sql`.

Число находок по важности: критично — 3, важно — 12, мелочь — 2.

## Не проверено

- **Реальный рантайм мульти-тенантности.** Не запускал приложение с
  `MULTI_TENANT_MODE=multi` и не проверял живьём, что два тенанта реально
  изолированы (RLS + приложение). Вывод сделан по чтению кода
  (`src/proxy.ts:86`, `src/services/tenancy/tenant-context-service.ts:13`).
- **Двух-тенантные интеграционные тесты.** Не проверял, есть ли тест, который
  поднимает две настоящие организации в одной БД: юнит-тесты используют
  мок-тенанты `tenant-a`/`tenant-b`, e2e-фикстур создаёт один временный тенант
  (`e2e/fixtures/role-audit.mjs:10`). Реальное покрытие изоляции — не проверено.
- **Прод-конфигурация.** Не смотрел `.env*`, docker-compose и прод-значения
  `MULTI_TENANT_MODE`/`DEFAULT_TENANT_ID`/`TENANT_DOMAIN` (запрет на секреты и
  на прод) — какой режим реально на бою, не проверено.
- **Пригодность схемы к удалению тенанта.** Число и порядок FK с `Restrict`,
  тянущихся к `Tenant`/`User`, точно не пересчитывал; вывод по нескольким
  найденным (`prisma/schema.prisma:114`, `:1119`, `:1121`) — не полный граф.
- **Экспорт.** Содержимое выгрузок (какие именно поля попадают в CSV) не
  читал построчно; статус «частично» основан на наличии трёх маршрутов экспорта
  и отсутствии маршрута полного выгруза.
- **Возможные внешние онбординг-скрипты.** Проверял `scripts/`,
  `prisma/seed*.ts`, `e2e/`; не исключаю ручных операционных инструкций вне
  репозитория (в запрещённых к чтению `docs/strategy` — сознательно не смотрел).
