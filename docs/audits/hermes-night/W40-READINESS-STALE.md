## Итог

- Находок 12: **критично — 0**, **важно — 6**, **мелочь — 6**. Прод-БД не читалась (AGENTS §1); все числа — только `pilingtrack_test`.
- **Причина найдена и доказана кодом + данными.** Установок с `CurrentReadiness` — 9 (все 9 в БД). Старше 24 часов — 1: `eq-pve-50pr` (PVE 50PR, вердикт `READY`/балл 75, возраст ≈57 дней).
- Корень: ежедневный пересчёт (`DAILY_RECALC`) в `runReadinessScheduler` перебирает только `isActive: true` (`scheduler.ts:258-261`). PVE 50PR деактивирована (`isActive=f`, `Equipment.updatedAt=2026-09-03`), поэтому её готовность не пересчитывается **ни одним** путём, даже когда планировщик работает. Восстановительный `backfill` фильтрует так же (`backfill-service.ts:26,73`).
- Доказательство, что планировщик в этой среде **работает**: 8 активных установок имеют `CurrentReadiness` от `DAILY_RECALC`/`triggerId=2026-10-07` (`calculatedAt=2026-10-06 21:12:43.776`), тогда как `eq-pve-50pr` — от `INSPECTION_COMPLETED` от `2026-08-10`. То есть лаг PVE 50PR — не «планировщик спит», а «установка выпала из выборки планировщика».
- В `npm run dev` суточный планировщик не стартует вообще (только embedded outbox+projection, `embedded-workers.ts:20,26`); `runReadinessScheduler` живёт лишь в `worker:all` (`unified-worker.ts:187-189`). В dev готовность двигают только события.
- UI возраст показывает датой («Оценка: …», «Последнее обновление»), но предупреждения «оценка устарела» нет нигде; снимок PVE 50PR к тому же старый (без `verdict`) и читается как зелёный `READY`.
- Топ-5:
  1. **важно** — `scheduler.ts:258-261`: ежедневный пересчёт обходит `isActive:true` → деактивированные копры застревают на последнем вердикте навсегда.
  2. **важно** — `backfill-service.ts:26,73`: единственный «ремонтный» путь фильтрует так же; вылечить устаревшую строку нечем.
  3. **важно** — `readiness/current/route.ts:20-24`: отдаёт `CurrentReadiness` без проверки свежести и без фильтра `isActive`; устаревший вердикт можно получить по API.
  4. **важно** — `fleet-screen.tsx:210`, `fleet-evidence-panel.tsx:118-119`, `readiness-centre.tsx:795-796,810`: возраст показан, пометки «устарело» нет; оговорка спрятана в раскрывающемся блоке (`fleet-evidence-panel.tsx:167`).
  5. **важно** — `unified-worker.ts:184-189` + `embedded-workers.ts:20`: планировщик есть только в `worker:all`; в `npm run dev` суточного пересчёта нет (подтверждение W12/J7).
