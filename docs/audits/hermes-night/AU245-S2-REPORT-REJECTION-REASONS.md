## Итог

- «Отклонение отчёта» как отдельного действия НЕТ: у сменного отчёта (`Report`) всего два состояния — `draft` и `submitted`, а отправка всегда выполняет `submit` без ветки отказа (`src/modules/reports/domain/report.aggregate.ts:43`, `src/modules/reports/application/commands/report-command.service.ts:280`). Причину отказа отчёта взять неоткуда — её не существует.
- Реальный возврат «отчёта» на доработку идёт через передачу смены (`ShiftHandover`): состояние `REWORK_REQUIRED`, причина обязательна на сервере (3–1000 символов, код 422).
- Главная находка: причина возврата ОБЯЗАТЕЛЬНА, но НЕ видна исполнителю (оператору/механику). Экран исполнителя получает факты из `getOperatorShiftFacts`, где передача выбирается только в состоянии `SUBMITTED` и без поля `reworkReason`; фазы смены не знают состояния `REWORK_REQUIRED` (`src/modules/readiness/application/operator-shift-query.ts:246`, `src/components/piling/operator/shift-phase.ts:111`).
- Причина хранится и видна только в АДМИН-центре готовности (журнал передач) и через API `GET /api/readiness/handovers/:id`; исполнитель этих экранов не открывает.
- Причина отказа в допуске смены (`declineReason`) тоже обязательна и сохраняется, но в UI не отображается НИГДЕ (ни одного рендера этого поля в компонентах).
- Числа: 1 критично, 3 важно, 4 мелочь (+3 контекстных). Прогон тестов домена смен: `shifts.test.ts` — 20 passed / 0 skipped, exit 0.
