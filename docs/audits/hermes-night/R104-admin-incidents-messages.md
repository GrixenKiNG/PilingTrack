## Что видит человек: сценарий за сценарием

Тексты дословно; источник — файл:строка.

Как человек попадает на экран: пункт меню «Нарушения и инциденты» (`module-tab-list.tsx:56`) в модуле «ТБ и допуски» `/admin/safety?view=incidents`; старый адрес `/admin/incidents` оставлен редиректом (`admin/incidents/page.tsx:12`). Экран рисуется только если bootstrap разрешил раздел (`bootstrap-query.ts:238` — нужно и `incidents.read`, и `readiness.read`); роли без прав при прямой ссылке получают общий отказ модуля «Этот раздел недоступен согласно полномочиям, полученным от сервера.» (`tech-readiness-module.tsx:41-44`), а не экран происшествий.

### 1. Открыть список (вкладка «Ждут разбора», `scope=open`)

- **Успех.** Шапка «Происшествия» (`admin-incidents.tsx:131`), подпись «Ждут разбора: N» либо «Неразобранных происшествий нет» (`:133-135`), переключатель «Ждут разбора / Все» (`:139`), список карточек: категория, бейдж тяжести, «Есть пострадавшие», «Разобрано», описание, поля «Когда / Записал / Установка / Объект / Признаки / Снимков» (`:171-215`).
- **403.** `assertCan` бросает ServiceError → `{"error":"Доступ запрещён"}` (`authorization-service.ts:164` через `api-wrapper.ts:108-112`). Экран показывает ровно этот текст красным абзацем (`admin-incidents.tsx:60,155-159`): голое «Доступ запрещён», без объяснения причины и без указания, к кому идти. Достижимо, когда bootstrap и API разошлись (смена режима «Действую как» между загрузкой модуля и запросом, изменение роли в сессии).
- **5xx.** `api-wrapper.ts:131` → «Внутренняя ошибка сервера. Повторите попытку; если повторится — сообщите администратору.» Показывается тем же абзацем — текст хороший.
- **Обрыв сети.** `catch` берёт `error.message` как есть (`admin-incidents.tsx:63`): в Chrome это «Failed to fetch», в Firefox «NetworkError when attempting to fetch resource» — английская строка среди русских.
- **Не-JSON ответ (502/504 HTML от прокси, страница ошибки Next).** `await response.json()` (`:59`) бросает SyntaxError, сообщение которого попадает на экран как есть: «Unexpected token '<', "<!DOCTYPE "… is not valid JSON».
- **Пусто.** «Ничего не ждёт разбора. Это хорошая новость.» (`:166`) либо для «Все» «Происшествий пока не заводили.» (`:167`) — лучшие пустые тексты раздела.
- **401.** `requireAuth` вернул бы «Unauthorized»/«Session is invalid»/«User not found» (`auth.ts:166,175,185`), но маршрут их игнорирует и отдаёт своё «Войдите в систему» (`route.ts:27`). Экран печатает этот абзац, но `authFetch` не участвует → разлогина и `router.replace('/login')` из `api.ts:56-69` и `(app)/layout.tsx` нет. Тупик: сессия в store остаётся, человек не знает, что делать.
- **409** к чтению неприменим.

### 2. Переключить вкладку («Ждут разбора» ⇄ «Все»)

- **Успех:** новая выборка, список и счётчик пересчитываются (`admin-incidents.tsx:80,90-99,143`).
- **Отказ:** тот же красный абзац, что и в п.1; **список при этом не сбрасывается** — `setRows` не вызывается, поэтому на экране остаются строки *предыдущего* отбора под сообщением об ошибке нового (`:95-96`). Человек читает данные одной выборки как результат другой.
- **Возврат на активную вкладку** ничего не делает: `setScope(id)` с тем же `id` не меняет состояние, эффект с зависимостями `[scope, reloadToken]` не перезапускается (`:90-99,143`). Это и есть отсутствие «Повторить».

### 3. Записать разбор (кнопка «Разобрать» → заметка → «Записать разбор»)

- **Кнопка видна** при `incidents.review` по исполняемой роли (`admin-incidents.tsx:73-74`); сам сервер проверит то же право (`route.ts:105`).
- **Предусловие без объяснения.** Кнопка «Записать разбор» гаснет, пока в заметке меньше 10 знаков (`:250`), но ни счётчика, ни подсказки «минимум 10 знаков» нет — человек не понимает, почему она неактивна.
- **Успех:** форма закрывается, поле очищается, список перечитывается — строка меняет бейдж на «Разобрано» (`:115-117`). Отдельного сообщения об успехе нет.
- **400.** Сервер требует `note` длиной 10–4000 (`route.ts:99`), но текст ошибки один: «Опишите вывод разбора — не меньше 10 знаков» (`:111`). Для **слишком длинного** вывода (а `textarea` не имеет `maxLength`, `:238-245`) это сообщение врёт: превышен верхний предел, а сказано про нижний.
- **403 CSRF.** Если запрос ушёл не с того origin (открыто по IP/за прокси), `withMutation` → `withCsrf` вернёт `{"error":"CSRF validation failed: origin mismatch"}` (`csrf-protection.ts:78` через `api-wrapper.ts:182-184`) — английская строка в красный абзац. Лечится обновлением страницы, но об этом не сказано.
- **403 по правам** — голое «Доступ запрещён».
- **409.** «Происшествие не найдено либо уже разобрано» (`route.ts:126-128`) — один текст на два разных случая. Форма остаётся открытой (закрытие только после успеха, `:113-115`), список не перечитывается, строка по-прежнему показывает «Разобрать» → повторное нажатие даёт тот же 409 (круг).
- **5xx** — русский общий текст (`api-wrapper.ts:131`). **Обрыв сети** — «Failed to fetch» (`:119`, сообщение попадает из `catch` через `error.message`). **Не-JSON** — SyntaxError-текст.
- **401** — «Войдите в систему» абзацем; форма остаётся открытой, разлогина нет.
- **Место ошибки.** Абзац ошибки стоит вверху страницы (`:155-159`), а форма — внутри карточки (`:232-263`). В длинном списке сообщение об отказе остаётся за пределами экрана: человек не видит, записался разбор или нет.

### 4. Отменить ввод («Отмена»)

- Форма закрывается, заметка очищается (`admin-incidents.tsx:257`). Введённый текст теряется без подтверждения — для короткой заметки это мелочь, для надиктованного вывода разбора может быть обидно.

### 5. Снять доказательства (фото происшествия)

- Экран показывает **только счётчик**: «Снимков: N» (`admin-incidents.tsx:212-214`), который маршрут считает как длину `evidenceMediaIds` (`route.ts:41,84`). Открыть сами снимки нельзя — ни ссылки, ни предпросмотра. Разбирающий решает по описанию, не видя доказательств. (Уже отмечено как следствие: `R66-media-backup-state.md`, стр. 76.)

### 6. Просмотр истории (вкладка «Все»)

- Бейдж «Разобрано» и блок «Вывод разбора · <дата>» (`admin-incidents.tsx:192-196,223-230`) показывают, кем/когда/чем закончилось, но **кто разобрал** на экран не выводится: `reviewedById` маршрутом не отдаётся вовсе (`route.ts:74-91`).

## Отказы по категориям (сводка «один отказ — разные тексты»)

- **401:** «Войдите в систему» (`route.ts:27,104`) — но `requireAuth` умеет «Unauthorized»/«Session is invalid»/«User not found» (`auth.ts:166,175,185`), и ни один не доходит: маршрут подменяет их своим текстом, а разлогина нет.
- **403:** «Доступ запрещён» (права, `authorization-service.ts:164`) против «CSRF validation failed: …» (безопасность, `csrf-protection.ts:66-115`) — второй английский и не объясняет обновление страницы.
- **Обрыв/прокси:** «Failed to fetch» (браузер) против SyntaxError (не-JSON) — оба технические и английские; в остальном приложении тот же класс закрыт `loadErrorMessage` (`api.ts:111-122`, «Нет соединения с сервером.»).
- **409:** один текст «не найдено либо уже разобрано» (`route.ts:127`) на два разных случая.
