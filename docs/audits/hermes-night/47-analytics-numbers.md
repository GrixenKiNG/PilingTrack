# 47 — Числа на экранах аналитики и дашборда: сходятся ли они с источником данных

Аудит только чтение. Все утверждения ниже проверены по коду, который открывался в этой сессии; ссылки даны как `путь:строка`. Что не проверено — в разделе «Не проверено».

## Итог

- Всего находок: 22. Критично — 6, важно — 12, мелочь — 4.
- Главное: снимок парка (`/api/monitoring/fleet`) читает отчёты **вообще без фильтра по статусу** (`fleet-monitoring.service.ts:193–198`), поэтому черновики попадают в плитки «Сваи», «Бурение», «Простой» и в «Отчёты» на дашборде и на экране аналитики. Аналитика по объектам в тот же момент считает только `status = 'submitted'`.
- Один и тот же показатель «простой» считается по трём разным наборам отчётов: все статусы (парк), только `submitted` (аналитика по объектам), только отчёты с заполненным временем смены (доля простоя в overview).
- План никогда не режется по периоду, а факт режется; при этом из выборки выпадают неактивные объекты без отчётов в периоде — «план %» меняется от смены фильтра периода.
- Экран аналитики в одной полосе KPI смешивает плитки «за сегодня» (из парка) и дельты «к пред. неделе» (из overview за 7 дней).
- «Тренд за месяц» строится из проекции `SiteWeeklyTrend` с жёстким `take: weeks * 10`, а рейтинг объектов рядом — живьём из отчётов; при парке больше 10 объектов недели молча обрезаются.

3. Проекции/воркеры: `src/modules/reports/application/projections/rebuild.ts`; поиск по `ReportAnalytics|SiteWeeklyTrend` (37 попаданий) — прочитаны `projection-worker.ts` и `projection-handlers.ts` только по строкам из поисковой выдачи (полностью не открывались).

6. Сверка «одно число на разных экранах» — сопоставлением SQL/`reduce` каждого источника с потребителем в компоненте.

## Где два экрана могут показать разные числа за один период

1. Дашборд, плитки «Сваи/Бурение/Простой» (`/api/analytics/sites`, только `submitted`) против экрана «Аналитика», плитки тех же величин за сегодня (`/api/monitoring/fleet`, без фильтра статуса) — находки 1, 6, 12.
2. Дашборд против самого себя в пределах 5 минут: Redis-кеш аналитики 300 c против снимка парка 30 c — находка 4.
3. Дашборд, верхняя плитка «Сваи» (прогресс по метрам) против карточки объекта (прогресс по штукам) — находка 9.
4. «План-факт по объектам» на дашборде при разных фильтрах периода — план постоянный, факт и состав объектов переменные — находка 3.
5. Вкладка «Тренды по объектам» (`SiteWeeklyTrend`, только `submitted`) против «Рейтинга объектов» на том же экране (живые отчёты) — находка 14.
6. Вкладка «Тренды» при >10 объектах: обрезанная выборка против живого рейтинга — находка 2.
7. «Простой, ч» на дашборде (все отчёты) против «Доли простоя, %» в аналитике (только смены с известным временем) — находка 10.
