## Итог

- Находок 18: **критично — 0**, **важно — 8**, **мелочь — 10**. Потери данных в сценариях осмотра по коду не подтверждено; проблема — в том, что отказ выдаётся за «данных нет» и за «не найдено», а часть действий ведёт в тупик или в никуда.
- Главный класс: **отказ по правам/сбою показан как «ничего нет»**. Список осмотров на 403 рисует «Осмотров не найдено.» (`inspections-list.tsx:86-87`), карточка на 403/404/500/обрыв — тупик «Осмотр не найден.» (`run-inspection.tsx:296-305`), список шаблонов на 403 — «Шаблонов пока нет.» (`template-list.tsx:81-84`), галерея фото на 403/500 молча пустеет (`inspection-item-photos.tsx:65-68`). Ни один из экранов не называет причину и не даёт «Повторить».
- Ни на `.inspections/**`, ни на `/admin/checklists` нет гварда раскладки уровня страницы: `/inspections` вообще без `requirePageAbility` (в каталоге только три `page.tsx`), раздел чек-листов закрыт `inspection.perform` (`admin/checklists/layout.tsx:4`), тогда как его API требует `maintenance.manage` (`api/checklist-templates/route.ts:48,63`) — уже R18 №10/№5.
- Топ-5:
  1. **403/500/обрыв на списке осмотров = «Осмотров не найдено.»** без «Повторить» (`inspections-list.tsx:48-55,86-87`). Роль без `inspection.perform` (ASSISTANT) или админ в режиме «Действую как» видит пустой раздел и не понимает, что дело в правах.
  2. **Карточка осмотра на любом отказе = «Осмотр не найден.»** — тост «Не удалось загрузить осмотр» и тупик без перезапроса (`run-inspection.tsx:136-137,296-305`). Сетевой сбой и 500 неотличимы от «осмотр удалён/чужой».

## Что видит человек: действие за действием

Тексты дословно; источник — файл:строка.

### 1. Открыть список осмотров (/inspections)

Успех: заголовок «Осмотры», фильтр «Вид осмотра» (Все виды/ЕО/ТО-1/ТО-2/ТО-3/Сезонное), список строк со ссылками на карточку (`inspections-list.tsx:64-120`).

- **403.** Сервер `{"error":"Доступ запрещён"}` (`authorization-service.ts:164`). Экран: тост «Не удалось загрузить осмотры» (`:52`) и ниже — «Осмотров не найдено.» (`:86-87`). Про права ни слова; кнопки «Повторить» нет (только тост, исчезающий через секунды). Достижимо: у `/inspections` нет гварда страницы, раздел открывает любая аутентифицированная роль, а GET требует `inspection.perform` — ASSISTANT и админ в режиме «Действую как OPERATOR/ASSISTANT» получают 403.
- **5xx / обрыв.** Тот же путь: `if (!res.ok) throw new Error()` (`:49`) не различает 403, 500 и обрыв — один тост и «Осмотров не найдено.».
- **Пусто.** «Осмотров не найдено.» (`:87`) — уместно только когда запрос прошёл.
- **401.** `authFetch` делает logout в store (`api.ts:66-68`), раскладка уводит на `/login` (`(app)/layout.tsx:339-343`); сообщения об истечении сессии нет.
- **409** к чтению неприменим.

### 2. Фильтр «Вид осмотра»

- Смена значения перезапускает загрузку (`useEffect`, `:59`); любой отказ снова заменяет весь список тостом «Не удалось загрузить осмотры» — 403/500/обрыв неотличимы (`:42-56`).
- **Пусто после фильтра**: тот же «Осмотров не найдено.».
- Обрезка: `listInspections` берёт `take: 200` (`inspection-query.service.ts:21`) без подписи «показаны первые 200» — при переполнении экран молчит (в журнале забивки такая подпись есть, R93 §9).

### 3. Открыть карточку осмотра (/inspections/[id])

Успех: шапка с установкой, вид/дата/смена/моточасы, бейдж «В процессе»/«Завершён», «Оценка состояния», пошаговый обход по разделам, авто-сохранение черновика при переходе между разделами (`run-inspection.tsx:281-286`).

- **403/404/5xx/обрыв.** `if (!res.ok) throw new Error()` (`:112`) → тост «Не удалось загрузить осмотр» (`:137`) и ниже экран «Осмотр не найден.» с единственной ссылкой «К списку» (`:296-305`) — без «Повторить». Чужой осмотр оператора сервер отдаёт как 404 намеренно (`inspection-query.service.ts:53-55`), но сетевой сбой и 500 выглядят так же.
- **401.** logout + уход на `/login`.
- **409** к чтению неприменим.

### 4. Заполнить пункты / сохранить черновик (PUT /api/inspections/[id])

- Успех: тост «Черновик сохранён» (`:192`); при переходе между шагами — молча (`saveDraft({silent:true})`, `:285`).
- Своя проверка подписи: «Укажите имя для подписи» (`:202`).
- **400** (zod `answersSchema`, `api/inspections/[id]/route.ts:12-22,56-60`): `err.error` = «Некорректные данные» — построчные `details.fieldErrors` не разбираются (`:191`).
- **403 CSRF** (`withMutation` → `withCsrf`, `api-wrapper.ts:183-184`): в тост идёт сырая английская строка `CSRF validation failed: origin mismatch` (`csrf-protection.ts`).
- **404** — английское `Inspection not found` (`inspection-commands.ts:261,263`).
- **409** — русское «Осмотр уже завершён» (`inspection-commands.ts:264,292`) — показывается тостом; это ожидаемый смысл, но человек узнаёт о чужом завершении уже после нажатия.
- **401** — английское `Unauthorized` / `Session is invalid` (`auth.ts:166,175`).
- **5xx** — русское «Внутренняя ошибка сервера. Повторите попытку; …» (`api-wrapper.ts:131`). **Обрыв сети** — браузерное `Failed to fetch` (`:193`).
- **Не-JSON тело** (прокси/шлюз отдаёт HTML): `(await res.json()).error` без `.catch()` (`:191`) бросает `SyntaxError`, в тост попадает английское «Unexpected end of JSON input».

### 5. Завершить осмотр (PUT + POST /complete)

- Успех: тост «Осмотр завершён» (`:225`), возврат в список/к смене.
- **400 «Осмотр не заполнен»**: сервер называет только числа — «Осмотр не заполнен: пунктов без ответа N, без обязательного фото M» (`inspection-commands.ts:352-356`); какие именно пункты — не сказано. При этом `finally { setShowSign(false) }` (`:231`) закрывает панель подписи, и после отказа человек жмёт «Завершить осмотр» заново.
- **Тот же набор английских текстов**, что в п.4, и для PUT, и для POST (`:213`, `:222-223` — здесь `.catch(() => ({}))` есть, поэтому не-JSON не течёт; у PUT `.catch` нет).
- **409** «Осмотр уже завершён» (повтор завершения): сервер идемпотентно вернёт осмотр (`inspection-commands.ts:404-413`), но экран проверяет `res.ok` — при `claimed.count === 0` маршрут всё равно отдаёт 200, так что повтор проходит как успех.
- **401** — logout + уход.

### 6. Начать осмотр (/inspections/new)

- Форма собирает установку/уровень/дату/смену/моточасы, показывает предпросмотр блоков чек-листа и расходники.
- **Отказ чтения установок** (403/5xx/обрыв через `loadJson`): `QueryErrorBanner` с русским текстом и «Повторить» — сделано верно (`:80-85,197-198`, `api.ts:111-121`).
- **Отказ чтения шаблонов**: баннер «Шаблоны осмотра не загрузились» + честный текст «Состав блоков чек-листа неизвестен — шаблоны могут быть, просто они не прочитаны.» (`:101,233-238`) — статус 403/5xx/обрыв не различается, но текст не врёт.
- **Успех**: `router.push('/inspections/{id}')` (`:176`), без промежуточного тоста.
- **400/403/404/401**: `err.error` дословно — «Нет блока «База»…» (400, русское), «Оператору доступен только ежесменный осмотр (ЕО)» / «Вы не назначены на эту установку» (403, русское), `Equipment not found` (404, английское), `tenantId is required` (400, английское), `Unauthorized` (401, английское), CSRF (английское) (`:171-174`; `inspection-commands.ts:43,50,63,69,108-113`). Пустое тело ошибки (например 429) → маска «Ошибка создания осмотра» (`:173`).
- **5xx** — русское (`api-wrapper.ts:131`), обрыв — `Failed to fetch` (`:178`).

### 7. Список шаблонов чек-листов (/admin/checklists)

- Успех: строки шаблонов со ссылкой на редактор и иконкой деактивации (`template-list.tsx:86-115`).
- **403/5xx/обрыв**: тост «Не удалось загрузить шаблоны» (`:42`) и ниже — «Шаблонов пока нет.» (`:82-84`); кнопки «Повторить» нет. Гвард раздела — `inspection.perform` (`admin/checklists/layout.tsx:4`), а API — `maintenance.manage` (`api/checklist-templates/route.ts:48`): OPERATOR проходит раскладку и получает 403, читая «Шаблонов пока нет.» (уже R18 №5/№10).
- **Успех деактивации**: `window.confirm('Деактивировать шаблон?')` (`:54`), затем тост «Шаблон деактивирован» (`:59`). **На отказ** — общий «Не удалось деактивировать шаблон» (`:62`), серверный текст (например `Template not found`) игнорируется (`:58`).

### 8. Редактор шаблона (/admin/checklists/new и /[id])

- Успех: тост «Шаблон создан»/«Шаблон обновлён», переход к списку (`template-editor.tsx:156-157`).
- Своя проверка: «Введите название шаблона», «Заполните заголовок каждого раздела», «Заполните текст каждого пункта» (`:111-117`).
- **Отказ чтения шаблона**: тост «Не удалось загрузить шаблон», `loading` снимается, и под заголовком «Редактировать шаблон» показывается **пустая** форма (`:52-54,81-85,165-171`). Сохранение такой формы стирает шаблон: `updateTemplate` сначала деактивирует старый, затем создаёт новый (`template-commands.ts:64-68`), не в транзакции.
- **400** (zod `createSchema`): «Некорректные данные» без поля (`:152-154`). **404** — `Template not found` (англ.). **401** — `Unauthorized` (англ.). **CSRF** — англ. **5xx** — русское. **Обрыв** — `Failed to fetch` (`:159`).
