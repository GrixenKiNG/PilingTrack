# AU208-S4-SESSION-REFRESH-RACE — продление сессии при параллельных запросах

Революция (git rev-parse HEAD): **aca020a5ae602e18a934d36af1689d6ac1f3f045**
Рабочая ветка: `hermes/q4-0926`. Режим: только чтение приложения; создан один файл отчёта.

## Итог

- «Продление сессии» как функция в коде **отсутствует**: единственная точка выдачи токена — вход (`src/services/auth/auth-service.ts:147`), TTL фиксирован 12 ч (`src/services/auth/session-service.ts:8`), эндпоинт `POST /api/auth/refresh` и таблица `RefreshToken` удалены 24.09.2026 (`prisma/migrations/20260924120000_drop_refresh_token/migration.sql:1-6`). Значит классической гонки «два запроса одновременно продлевают сессию» физически нет — продлевать нечего.
- Поэтому аудит переориентирован на **реальные конкурирующие операции с сессией**, где гонка возможна: одновременные запросы с одним токеном, выход из системы, истечение токена.
- По severity: **критично — 0, важно — 3, мелочь — 4** (всего 7 находок).
- Топ-5:
  1. [важно] Гонка отзыва: параллельный запрос, чья проверка сессии выполняется в момент logout, **заново кладёт отозванный токен в 5-секундный кэш** после того, как logout его очистил (`src/lib/auth.ts:133` vs `:153-156`). Токен остаётся рабочим в этом процессе до 5 с.
  2. [важно] Выход из системы с **уже истёкшим** токеном всегда даёт `503` и не сбрасывает cookie — пользователь не может корректно выйти (`src/app/api/auth/logout/route.ts:19-21` + `src/services/auth/session-service.ts:257`).
  3. [важно] Logout отзывает только текущий `jti`; параллельные сессии на других устройствах/вкладках остаются валидны до 12 ч — «разлогинить везде» нельзя (кроме смены пароля/роли/блокировки) (`src/services/auth/session-service.ts:255-263`, `src/services/users/user-service.ts:236-237`).
  4. [мелочь] Два одновременных входа дают два независимых валидных токена (разные `jti`); браузер сохранит один, второй остаётся живым «сиротой».
  5. [мелочь] Раскладки страниц (`src/lib/page-session.ts:45`, `src/app/page.tsx:18`) проверяют сессию на **каждый** рендер без 5-секундного кэша `lib/auth.ts` — лишний Redis-GET на параллельную нагрузку.
