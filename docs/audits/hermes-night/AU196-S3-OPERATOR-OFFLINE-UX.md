# AU196-S3-OPERATOR-OFFLINE-UX: Экран машиниста без сети

Версия предмета аудита: `git rev-parse HEAD` = `10623ab51dd69d74917c819ab9c73f05176a2f6d`
(ветка `hermes/q4-0926`). Только чтение: код приложения не менялся.

Действующий экран машиниста — маршрут `/operator` → `src/app/(app)/operator/page.tsx:2,24` →
`OperatorMobileApp` (`src/components/piling/operator-mobile/operator-mobile-app.tsx`).
Варианты v2…v10 живут параллельно (`src/app/(app)/operator/v3/page.tsx:6-9`) и по решению
владельца заморожены — они упоминаются отдельной строкой, потому что используют ту же
офлайн-очередь.

## Итог

- Найдено 13 находок: **критично — 0, важно — 4, мелочь — 9**.
- Автономная работа реализована честно и с явным отказом от «решать судьбу смены офлайн»:
  в очередь идут только добавляющие команды с ключом идемпотентности
  (`src/components/piling/operator-mobile/offline-queue.ts:67-69`).
- Топ-1 (важно, данные не теряются, но врут): повтор отложенной **поправки**
  (`src/modules/operator-mobile/application/commands/production-corrections.ts:73-77`) и
  **происшествия** (`src/modules/operator-mobile/application/commands/incidents.ts:58-73`)
  проверяет «смена открыта» РАНЬШЕ, чем идемпотентность. Запись, уже принятая сервером и
  отправленная повторно после закрытия смены, получает 409 → `FAILED` и показывается
  машинисту как «не принята», хотя она в базе есть. `logProduction` от этого защищён
  (`production.ts:118-121` до `requireOpenShift` на 123), соседи — нет.
- Топ-2 (важно, замороженный вариант): в v10 кнопка «Закрыть смену» блокируется по
  `unsent = queued.length`, куда входят и `FAILED` — закрытие смены запирается навсегда,
  тот самый класс, что уже исправлен в действующем экране (`closing-screen.tsx:26-34`).
- Топ-3 (важно, UX): `describeCommand` не знает новой формы простоя «в часах» и в карточке
  введённого печатает «простой —–—» (`offline-queue.ts:116`), хотя команда уже несёт
  `hours` (`api.ts:457-458`).
- Топ-4 (мелочь, но заметно): сводка ждущих записей склеивает подписи без свёртки
  («Выработка, Выработка, Выработка»), хотя причины отказа сервер сворачивает с «(×N)»
  (`offline-queue-banner.tsx:64-71, 89`).
- Резюме для владельца (5 строк): без сети машинист видит постоянную строку статуса
  («Офлайн · На устройстве ждёт отправки: N») и жёлтую плашку; введённое сохраняется на
  телефоне и уходит само по таймеру/событию «online»/возврату на вкладку. При отказе
  сервера запись не удаляется, а краснеет с причиной и тремя выходами (повторить, «что
  введено», удалить). При конфликте после восстановления связи (смена закрыта) запись
  помечается `FAILED` — повтор по кнопке это не лечит. Отдельно: повтор уже принятой
  поправки/происшествия после закрытия смены показывает ложный отказ (см. топ-1).
