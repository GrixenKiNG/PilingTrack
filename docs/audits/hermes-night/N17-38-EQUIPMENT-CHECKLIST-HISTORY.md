## Итог

- Всего находок: 12. По серьёзности — **критично: 0, важно: 2, мелочь: 10**.
- Ответ на главный вопрос «что видит оператор»: **сам оператор эту историю не видит вообще** — ручка требует права `equipment.read`, которого у `OPERATOR` нет; список показывает только карточка установки для ADMIN/DISPATCHER/MECHANIC/SAFETY_ENGINEER. То есть функция обслуживает админскую карточку, а не экран машиниста.
- Топ-5:
  1. **[важно]** Жёсткий предел 50 записей без периода и без «показать ещё»: при 3 чек-листах в смену это ≈16 смен (≈2–3 недели), дальше карточка молча теряет старые записи (`equipment-checklist-history.ts:39`, `route.ts:23`).
  2. **[важно]** Обязательный чек-лист «Готовность площадки» (`SITE_READY`) в историю не попадает вовсе, а подпись блока обещает «Осмотры машиниста по сменам» — пользователь не узнаёт, что часть осмотров скрыта (`equipment-checklist-history.ts:14-18,36`; `operator-checklist-history.tsx:46`).
  3. **[мелочь]** Счётчик `na` мёртв: ответов `NA` не бывает, поле всегда 0 и в интерфейсе не показывается (`equipment-checklist-history.ts:27,66`; `checklist-types.ts:14`).
  4. **[мелочь]** Названия видов в истории расходятся с названиями тех же чек-листов на экране машиниста: «ЕО до смены»/«ЕО после смены» против «ЕО перед работой»/«ЕО после работы» (`equipment-checklist-history.ts:14-18` против `checklist-catalog.ts:263,470`).
  5. **[мелочь]** В строке не видно смены: `shiftId` возвращается, но не отображается — при двух сменах в сутки строки ЕО выглядят неразличимо (`operator-checklist-history.tsx:55-67`).
- Удаления чек-листов в приложении нет: нет ни `delete`, ни `update` по `OperatorChecklistExecution`; связи `onDelete: Restrict`, установку с чек-листами удалить нельзя. «Пропал» чек-лист только как «не создан».

Статусы: **ПРОЙДЕНО** — вывод подтверждён чтением кода; **НЕ ПРОВЕРЕНО** — не выполнялось; **ГИПОТЕЗА** — предположение без подтверждения.
