# AU239-S5-ADMIN-IMPERSONATION-AUDIT: «Действую как»: запись в журнал

Версия на момент аудита: `git rev-parse HEAD` = 4d50c02afbcc8bddda66385ab06bb039e68bdd83 (ветка `hermes/q4-0926`).
Аудит только читающий: код приложения не менялся, создан лишь этот отчёт.

## Итог

- Всего находок: **11**. По важности: критичных — 0, важно — 4, мелочь — 7.
- Главное: **лента /admin (общий журнал, FeedbackEvent) не хранит признак замещения роли вообще** — действие администратора в режиме «Действую как» записывается его настоящим именем, без роли и без пометки о замещении. Обещание самой полосы («записываются в журнал с пометкой о замещении», `src/components/piling/acting-as-banner.tsx:51-52`) для всего приложения, кроме контура техготовности, не выполняется.
- Настоящий пользователь: в обоих журналах сохраняется настоящее имя и настоящий id (`actorId`), поэтому «кто на самом деле нажал» восстановимо по имени. Но **настоящая роль видна только в контуре готовности и только в базе**, в интерфейсе и в CSV вместо неё подставляется исполняемая роль.
- Замещение подписывается ровно в одном месте — доказательный журнал контура готовности (`AuditLog.actingAs`): дефекты, смены, передачи, наряды-допуски, матрица доступов, экспорт и сам факт включения замещения.
- Факт включения замещения пишется **только при загрузке bootstrap раздела техготовности**; включение режима из любого другого раздела не фиксируется нигде. Возврат к своей роли не пишется вообще.

## ПРОЙДЕНО (проверено на корректность)

- Настоящий пользователь фиксируется везде: `actorId` = `user.id` во всех точках записи (`audit-service.ts:1017`, `feedback-event-service.ts:122`, `audit-repository.ts:53-54`). Подмены «кто нажал» на исполняемую роль нет.
- Заголовок `x-acting-as` не даёт подставить произвольную роль: `canActAs` пропускает только ADMIN и только роль из `ACTING_ROLES` (`src/lib/types.ts:40-61`, `src/lib/auth.ts:192-193`).
- Замещение не меняет тенанта: `setRequestTenantId(user.tenantId)` (`src/lib/auth.ts:199`).
- Права считаются по исполняемой роли единообразно (`authorization-service.ts:158-178`, `capabilities.ts:53-70`), в т.ч. без «суммы» прав админа и роли (`capabilities.ts:62-69`).
- В контуре готовности `actingAs` пишется во все проверенные команды: дефекты (`defects/commands.ts:74-75`), смены и передачи (`shifts/commands.ts:74-75`), наряды-допуски (`permits/commands.ts:77-78`), правки матрицы (`access-matrix-service.ts:144`), экспорт (`export/route.ts:145`), сам факт включения (`bootstrap-query.ts:114-130`).
- Запись включения замещения идёт цепочечным писателем (с хешем), поэтому попадает и на экран, и в проверку цепочки (`bootstrap-query.ts:107-130`, `append-audit.ts:34-39`).

## Не проверено

- **Не проверено на живой БД.** Аудит — только чтение кода; фактические строки `FeedbackEvent`/`AuditLog` не читались (нет доступа к базе, работа только в git-worktree). Все выводы — из кода и схемы, не из данных.
- **Не проверено поведение в браузере.** Не запускались приложение и e2e; что именно видит админ в ленте после переключения роли — из кода компонентов, а не из прогона.
- **ГИПОТЕЗА по охвату.** Утверждение «вне контура ТО замещение не подписывается» подтверждено выборочно (отчёты, пользователи, объекты, справочники, настройки, telegram, вход/выход). Полный перечень всех `recordAuditEvent`-вызовов (373 совпадения) построчно не разбирался — не исключено отдельное место, где `actingAs` попадает в `metadata`. Признаков такого не найдено: `rg -n "actingAs" src/services src/modules` не показал вызовов аудита с замещением вне readiness.
- **Не проверено**: не настраивалась отдельная проверка для экрана «Мониторинг»/ORION/вариантов операторского экрана — это замороженные области (AGENTS.md), в аудит намеренно не включались.
- **Не проверено**: влияние смены режима на кэш ответов в реальном прогоне (F9) — вывод из чтения `api-wrapper.ts`, прогоном не подтверждён.
