## Итог

- Находок 22: **критично — 0**, **важно — 8**, **мелочь — 14**. Потери данных из-за текста не найдено; главные проблемы — отказ по правам выглядит как поломка сервера, один настоящий тупик при смене длины и английские строки вместо русских.
- Главный дефект класса: у загрузки реестра **нет разбора статуса вообще** — любой не-ok (403, 500, обрыв) превращается в один и тот же баннер «Не удалось загрузить справочники» без причины (`admin-dictionaries.tsx:132,144-146,452-459`). Администратор в режиме «Действую как OPERATOR» — единственный, кто реально получает здесь 403, потому что `dictionary.manage` есть только у `ADMIN` (`authorization-service.ts:129`), а раскладка страницы проверку по исполняемой роли не делает (`page-session.ts:73` — `actingAs` не возвращается).
- Топ-5:
  1. **Тупик: длину используемой марки нельзя изменить, если экран считает марку неиспользуемой** (`admin-dictionaries.tsx:51-52,272-277,396-399`). Сервер отвечает 409 «Марка используется в N отчётах: изменение длины пересчитает метраж в них. Подтвердите изменение.» (`dictionary-service.ts:316-318`), но диалог подтверждения открывается только по клиентскому счётчику (`reportCount/planCount` из ответа списка), а подтверждение уходит на сервер только из этого диалога. Повторное «Сохранить» даёт тот же 409 бесконечно; текста «подтвердите» в интерфейсе выполнить нечем. Причина расхождения счётчиков задокументирована в R29 №14 (показ и гард считают использование разными функциями).
  2. **403 на загрузке выглядит как поломка сервера** — «Не удалось загрузить справочники» + «Повторить» (`admin-dictionaries.tsx:144-146,455`), повтор будет отказывать всегда.
  3. **Английские строки в русском интерфейсе**: обрыв сети — «Failed to fetch» (`admin-dictionaries.tsx:297,336,364,411,432`), 401 — «Unauthorized» / «Session is invalid» / «User not found» (`auth.ts:166,176,185`), CSRF-403 — «CSRF validation failed: origin mismatch» (`csrf-protection.ts:78`). Все три доходят до тоста через `responseError` (`admin-dictionaries.tsx:76-83`).
  4. **400 отдаёт «Некорректные данные» без причины** — `details.fieldErrors` не читается (`admin-dictionaries.tsx:76-83`, ответ `dictionary/manage/route.ts:97,112,135`), при этом ни у формы, ни у панели нет `maxLength`, а лимиты сервера (название 100 символов, длина 1 000 000 мм) в интерфейсе не показаны (`dictionary-form.tsx:59,70-77`).
  5. **Массовая архивация объясняет отказ только числом** — «Не удалось изменить статус: N» (`admin-dictionaries.tsx:383`): ни причины (403/429/сеть/409), ни того, какие записи не изменились, ни «Отменить» (в отличие от одиночной архивации с «Отменить», `:354-359`).

## Что видит человек: сценарий за сценарием

Тексты дословно; источник — файл:строка.

### 1. Открыть раздел (загрузка реестра)

- Успех: шапка «Справочники» + «Рабочие значения вашей организации для отчётов и планирования» (`admin-dictionaries.tsx:448`), три плитки сводки с числом активных/архивных и подписью «Используются в N объектах» (`:472-480`), вкладки «Сваи / Бурение / Простои» (`:467`), заголовок таблицы «Сваи — активные» и счётчик (`dictionary-table.tsx:79-80`).
- **403.** Сервер отвечает `{"error":"Доступ запрещён"}` (`authorization-service.ts:164` через `api-wrapper.ts:108-112`). Хук не читает ни статус, ни тело: `if (!response.ok) throw new Error('load')` (`admin-dictionaries.tsx:132`), затем `setLoadError(true)` и тост «Ошибка загрузки справочников» (`:144-146`). Экран: баннер «Не удалось загрузить справочники» с одной кнопкой «Повторить» и без пояснения (`:452-459`). Про права — ни слова; повтор отказывает так же. Достижимо: администратор в режиме «Действую как OPERATOR» — раскладка страницы считает права по собственной роли (`page-session.ts:73` не отдаёт `actingAs`), а запрос уходит с `x-acting-as` (`api.ts:20-23`) и получает 403.
- **5xx.** Тот же баннер и тот же тост — 403 и 500 неразличимы. Серверный текст «Внутренняя ошибка сервера. Повторите попытку; если повторится — сообщите администратору.» (`api-wrapper.ts:131`) до человека не доходит.
- **429** (лимит 100 изменений/мин, `api-wrapper.ts:213`) и **503** (предохранитель, `:116`) при чтении неприменимы.
- **Обрыв сети.** `fetch` бросает `TypeError`, но текст тоже не показывается — тот же баннер; отличить «нет связи» от «нет прав» нельзя.
- **Пусто.** `items.length === 0` рисует две пустые надписи сразу: строку таблицы «Сваи: ничего не найдено» (`dictionary-table.tsx:191-193`) и пунктирный блок «Ничего не найдено» / «Попробуйте изменить параметры поиска или фильтра.» (`:290`). При пустом справочнике или фильтре «Активные» совет неверен. На чистой организации справочники заполняются шаблонами (`tenant-dictionary-initializer.ts:20-47`), но проверить, что так и в этой базе, я не мог (см. «Не проверено»).
- **401.** `authFetch` делает logout в store и в `/api/auth/logout` (`api.ts:56-69`), раскладка уводит на `/login` (`(app)/layout.tsx:339-343`). При этом компонент успевает поставить `loadError` и тост «Ошибка загрузки справочников» — сообщения об истёкшей сессии нет.

### 2. Поиск, фильтр статуса, вкладки, плитки сводки

- Успех: список сужается на клиенте (`admin-dictionaries.tsx:202-211`), заголовок таблицы меняется на «Сваи — активные/архив/все» (`:213`, `dictionary-table.tsx:79`).
- Отказов здесь нет: запросов не делается, всё из уже загруженного ответа. Если реестр не загрузился, этих элементов на экране нет вовсе (вкладки и таблица спрятаны за баннером, `:452-500`).
- **Ложное обещание**: поле подписано «Поиск по справочникам» (`:449`), но фильтрует только текущую вкладку — совпадение в «Бурении» вкладка «Сваи» не покажет.
- **Два числа на одном экране**: плитки сводки считают по нефильтрованным данным (`:215-220`), а счётчик в заголовке таблицы — по отфильтрованным (`dictionary-table.tsx:80`).
- Первая опция фильтра подписана «Активные / Архив / Все», хотя выбрана и показывает только активные (`:449`).

### 5. Добавить элемент (форма «Добавить элемент»)

- Успех: тост «Элемент добавлен», форма закрывается, список перечитывается (`admin-dictionaries.tsx:332-334`).
- Своя проверка до запроса: «Сохранить» заблокирована, пока нет названия (для марки сваи — ещё и положительной длины) (`dictionary-form.tsx:35,93`); отметки обязательных полей нет — уже R21 №29.
- **409** «Элемент с таким названием уже существует» (`dictionary-service.ts:78`) — тост, форма остаётся открытой. Сделано верно.
- **400** «Некорректные данные» (`dictionary/manage/route.ts:97`) — без строки о том, какое правило нарушено; лимиты (название ≤ 100, длина ≤ 1 000 000 мм = 1000 м) в форме не подписаны, `maxLength` нет (`dictionary-form.tsx:59,70-77`).

- Занятого состояния нет: кнопка показывает только крутящуюся иконку без текста (`dictionary-form.tsx:93-95`).

### 6. Переименовать (форма и панель)

- У используемого значения поле «Название» в панели заблокировано и повторно проверено перед отправкой («Используемое значение нельзя переименовать», `:254`); сервер отдаёт тот же смысл по-русски: «Используемый элемент нельзя переименовать; архивируйте его и создайте новый» (`dictionary-service.ts:363`).
- Остальные исходы — как в п. 5 (те же тосты).

### 7. Изменить длину марки сваи (диалог «Длина сваи — <имя>» и предупреждение в панели)

- Успех: тост «Длина сохранена» (`:407`); в реестре меняются «Длина, м» и «Обновлено».
- **Подтверждение пересчёта**: если экран считает марку используемой, открывается окно «Пересчитать прошлые отчёты?» с честным текстом «Погонные метры нигде не хранятся: их считают от длины марки при каждом открытии отчёта, аналитики, сводки за период и при печати PDF. Новая длина изменит эти цифры и за прошлые периоды: отчётов — N, планов — M.» и «У марки одна длина: прежнее значение не сохранится…» (`:643-671`). Сделано верно.
- **409 (тупик)**: если клиентский счётчик показал 0, а сервер считает марку используемой, диалог не открывается, запрос уходит без `confirmRecalculate` и получает 409 «Марка используется в N отчётах: изменение длины пересчитает метраж в них. Подтвердите изменение.» (`dictionary-service.ts:316-318`). Тост предлагает подтвердить — подтвердить нечем: повтор даёт тот же 409 (см. находку 2).
- **422** «У используемой марки нельзя убрать длину — метраж отчётов обнулится» (`dictionary-service.ts:313`) — на экране недостижим: пустое поле перехватывается тостом «Длина обязательна для марки сваи» (`:264`).
- **400** «Введите положительную длину в метрах» (`:269,392`) — локальная проверка, до сервера не доходит.
- Обрыв/401/CSRF — как в п. 5. В окне «Длина сваи» кнопка «Сохранить» при занятости только блокируется, текста «Сохранение…» нет (`:638`).

### 8. Архивировать / восстановить

- Одиночно: успех — тост «Архивировано: <имя>» с действием «Отменить» на 10 секунд (`:354-359`), восстановление — «Восстановлено» без отмены (по решению владельца, комментарий `:342-343`). Отмена делает повторный запрос (`:357`).
- Массово: архивация идёт **через подтверждение** «Архивировать N записей?» с честным текстом последствий для операторов (`dictionary-table.tsx:291-302`); восстановление — без подтверждения (`:72`) и без отмены.
- **409/403/429/обрыв при массовой смене** дают один текст «Не удалось изменить статус: N» (`:383`) — ни причины, ни списка записей. Успех — «Архивировано: N» (`:382`).
- Одиночная смена: отказ — серверный текст через `responseError` (`:351`), обрыв — «Failed to fetch» (`:364`). Панельная кнопка архивации — то же самое (`:578`).

### 9. Удалить навсегда

- Кнопка активна только у неиспользуемого значения (`dictionary-table.tsx:162-166`); подтверждение — «Удалить навсегда?» / «Элемент «X» будет удалён без возможности восстановления.» (`:674-683`). Формулировка честная, отмены нет.
- **Успех**: тост «Элемент удалён» (`:428`), список перечитывается.
- **Ошибка**: тост = текст сервера. 409 «Элемент используется и не может быть удалён» (`dictionary-service.ts:389`) — в обычном сценарии недостижим (кнопка заблокирована), но достижим при гонке; 404 «Элемент не найден» (`:385`) — если запись удалили в другой вкладке; обрыв — «Failed to fetch» (`:432`).
- **Гонка по внешнему ключу**: если значение всё-таки используется в строках, которых счётчик не видит, `model.delete` падает P2003, а `PRISMA_STATUS` знает только P2025/P2002 (`api-wrapper.ts:26-29`) → 500 «Внутренняя ошибка сервера. Повторите попытку; если повторится — сообщите администратору.» (`:131`). Причина («используется») не называется. (Английский «Internal server error» из R29 №2 уже заменён русским, но суть не изменилась.)
- В окне удаления нет занятого состояния: два быстрых нажатия «Удалить» отправят два DELETE, второй вернёт 404 и перекроет тост об успехе тостом ошибки (`:674-681`, `:417-434`).

### Повторы одного и того же текста на разные ситуации (сводка)
