## Итог

- Находок 18: **критично — 0**, **важно — 9**, **мелочь — 9**. Потерь данных не найдено; проблема — во лжи о результате действия и в разнобое объяснения отказов.
- Главный дефект: ответ `GET /api/users` кешируется на 30 с per-session и **никем не сбрасывается** при создании/правке/блокировке (`src/app/api/users/route.ts:37`, `src/core/cache/response-cache.ts:199-206`). После успешного действия список перечитывается и показывает **старое** состояние; кешируются и ошибочные ответы, поэтому «Повторить» после 403/5xx отдаёт тот же отказ. Удалённый пользователь может «вернуться» при следующей перезагрузке списка.
- 403 (режим «Действую как OPERATOR» — раскладка пускает по собственной роли) выглядит как поломка сервера: «Не удалось загрузить пользователей» без причины (`use-users-list.ts:64`, `admin-users.tsx:258`).
- Диалог «Виды документов»: сетевой сбой при добавлении/правке оставляет кнопку навсегда в спиннере без сообщения (`user-document-types-dialog.tsx:89-93`, `:129-131`), а удаление типа при обрыве молча падает (`:137-145`).
- Действия, меняющие доступ людям, идут без подтверждения: «Заблокировать» одним кликом (`user-detail.tsx:134-137`), «Требовать для смены»/«Отключить» одним кликом (`user-document-types-dialog.tsx:244-251`). При этом блокировка молча выкидывает человека из системы (`user-service.ts:231-233`).

## Что видит администратор: сценарий за сценарием

Тексты дословно; источник — файл:строка.

### 1. Открыть список

Успех: шапка `Пользователи`, счётчик «N записей» (`admin-users.tsx:271-272`), KPI-полоса (`computeUserKpis`, `user-list-model.ts:98-125`), строка отбора «Показано M из N» (`:323`), таблица.

- **403.** Экран не открывается, если у собственной роли нет `users.manage` (раскладка редиректит, `layout.tsx:4`). Но остаётся путь «Действую как OPERATOR»: раскладка смотрит собственную роль администратора и пускает, а `GET /api/users` идёт с `x-acting-as` и отвечает 403 (`users/route.ts:25` → `authorization-service.ts:164`). Экран: «Не удалось загрузить пользователей» + тело `Ошибка загрузки пользователей`, кнопка «Повторить» (`use-users-list.ts:64`, `admin-users.tsx:253-262`). Про права — ни слова; повтор будет отказывать.
- **5xx / обрыв.** Тот же текст для 5xx; при обрыве тело баннера — браузерное английское `Failed to fetch` (в `catch` берётся `cause.message`, `use-users-list.ts:78`).
- **Пусто.** «Пользователи не найдены» + «Измените фильтр или строку поиска.» (`admin-users.tsx:331`).
- **401.** `authFetch` делает logout в store (`api.ts:56-69`), раскладка уводит на `/login` (`(app)/layout.tsx:339-343`). Сообщения об истечении сессии нет.
- **409** к чтению неприменим.

### 2. Найти (фильтр, быстрые кнопки, поиск)

Только клиентское сужение (`filterOperationalUsers`, `user-list-model.ts:77-96`), запросов нет. Пусто — тот же текст, что в п. 1; здесь он уместен. Фильтр/поиск/выбранный сотрудник живут в адресе (`admin-users.tsx:99-120`) — на сообщения не влияет.

### 3. Создать пользователя

- **Успех.** Тост «Пользователь создан» (`user-dialogs.tsx:99`), диалог закрывается, список перечитывается (`use-users-list.ts:101`). Из-за кеша (находка 1) новый человек может не появиться до ~30 с.
- **Своя проверка.** «Имя обязательно», «Email обязателен»/«Некорректный email», «Укажите пароль»/«Минимум 8 символов» — под полем (`user-dialogs.tsx:77-86`), русские.
- **400** (`createUserSchema`): показывается только `err.error` = «Некорректные данные»; построчный `details` (`users/route.ts:60-63`) не читается (`use-users-list.ts:98-99`). Уже R41 №6.
- **403 CSRF** (`withMutation`→`withCsrf` до обработчика): в тост попадает английское `CSRF validation failed: origin mismatch` (`csrf-protection.ts:78` → `user-dialogs.tsx:101`). Об обновлении страницы не сказано.
- **409** (email занят): «Пользователь с таким email уже существует» (`user-service.ts:189-190`) — русский, диалог остаётся открытым. Поле email не подсвечено.
- **5xx**: «Внутренняя ошибка сервера. Повторите попытку; если повторится — сообщите администратору.» (`api-wrapper.ts:131`). **429**: «Слишком много запросов. Подождите немного и повторите.» (`api-wrapper.ts:204,216`).
- **Обрыв сети**: тост с `Failed to fetch` (`use-users-list.ts:97` не ловит — исключение уходит в `catch` диалога, `user-dialogs.tsx:100-101`). Уже R41 №9.
- **401**: logout + уход на `/login`; диалог исчезает без сообщения.

### 4. Изменить пользователя / сменить роль / сбросить пароль

- **Успех.** Тост «Пользователь обновлён» (`user-dialogs.tsx:236`), диалог закрывается, список перечитывается. Из-за кеша роль/статус на экране могут остаться прежними.
- **Сброс пароля** — то же поле «Новый пароль (оставьте пустым, чтобы не менять)» (`:278-288`). Отдельного ПИН-сброса в разделе нет (ПИН-вход удалён, `users/__tests__/route.test.ts:82`).
- **Побочный эффект не сообщается.** Пароль, смена роли и блокировка увеличивают `sessionVersion` (`user-service.ts:231-233,245`) — человек немедленно разлогинен; админу об этом не говорят.
- **409** (последний администратор): «Это последний администратор организации — у него нельзя снять роль. Сначала назначьте другого администратора» (`user-service.ts:276-283`) — русский, тостом (`user-dialogs.tsx:238`).
- **400** (`updateUserSchema`, zod v4): `err.error` = «Некорректные данные», `details` не читается. **403 CSRF/права**, **5xx**, **обрыв**, **401** — как в п. 3.

- **Подтверждения нет**: кнопка в карточке жмётся сразу (`user-detail.tsx:134-137`), для себя скрыта (`:133`).

- **Обрыв/403/5xx**: тост с текстом (`err.error` либо `Failed to fetch`), экран не меняется.

### 6. Удалить пользователя

- Кнопка видна только при `canHardDelete` (`user-detail.tsx:139`); иначе плашка «У пользователя есть отчёты или закрепления. Доступно только блокирование.» (`:145-149`).

- **409/404/403**. «Нельзя удалить пользователя с отчётами или назначениями — заблокируйте его» (`user-service.ts:347`), «Пользователь не найден» (`:344`), «Доступ запрещён» (`authorization-service.ts:164`) — русские, тостом. **Обрыв** — `Failed to fetch`.

- **Отказ чтения справочника видов** гасится молча: селект «Вид документа» пуст, объяснения нет (`:127`).
- **Создание/правка.** Успех — «Документ добавлен»/«Документ обновлён» (`:182`). 400 «Для документа «X» нужно указать срок действия» (`user-documents.ts:194`), 400 «Дата окончания раньше даты выдачи — проверьте документ» (`:272-275`), 403 «Недостаточно прав для изменения документов работника» (`user-document-access.ts:29`) — русские, тостом. Обрыв — `Failed to fetch`.
- **Удаление.** Успех — «Документ удалён» (`:198`). Отказ — всегда «Удаление не удалось», текст сервера теряется (`:197`); подтверждение закрывается даже при отказе.
