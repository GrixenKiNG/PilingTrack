# AU202-S3-PRINT-FORMS — Печатные формы PilingTrack

Версия кода: `git rev-parse HEAD` = `894818cc1a75ded13f9ee9b1110c0382c3b678a9` (ветка `hermes/q4-0926`).
Тип работы: только чтение. Ни один файл приложения не изменён; создан только этот отчёт.

## Итог

Аудит печатных форм и PDF. Всего найдено 13 замечаний: критично — 0, важно — 6, мелочь — 7.
Формы существуют в трёх видах: серверные PDF (pdfkit, единичный и сводный отчёт), HTML-страница `/print/briefing-journal` (журнал инструктажей), печать рабочих экранов через `window.print()` (отчёты, карточка наряда ТО, аналитика) и выгрузки .xlsx (журнал забивки, отчёты, паспорта свай). Кириллица в PDF обеспечена шрифтами DejaVu (`public/fonts/`, копируются и в Dockerfile, и в Dockerfile.workers) — ПРОЙДЕНО.

Топ-5:
1. `src/app/api/reports/single-pdf/route.ts:119` — имя файла в `Content-Disposition` собирается из ФИО оператора (кириллица) → `Response`/`Headers` бросает `TypeError`, синхронный фолбэк отдаёт 500 вместо файла. Проверено node-экспериментом.
2. `src/lib/pdf-generator/components.ts:94-139` — показатель «Свай забито / Бурение» клипается по ellipsis: строка «N шт. / M м.п.» (195pt) не влезает в колонку 100–141pt; парный двухстрочный режим не срабатывает (unit пустой). Метры не видны на листе.
3. `src/components/piling/equipment-analytics.tsx:150` — «Печать» вызывает `window.print()` без `print-area`, на лист попадает оболочка админки (в отличие от отчётов и карточки ТО, где R134 это уже закрыла).
4. `src/components/piling/briefings/briefing-journal-print.tsx:245,259` — печатный журнал инструктажей печатает только вид записи (Ознакомление/Проверка), теряя вид инструктажа (Вводный/Первичный/Повторный/Внеплановый/Целевой), который есть в данных и на экране.
5. `src/components/piling/briefings/briefing-journal-print.tsx:238-277` — печать не различает подтверждённые и неподтверждённые записи (нет графы «Состояние»/подписей), а примечание под таблицей утверждает, что каждая строка — подтверждённое действие работника.
