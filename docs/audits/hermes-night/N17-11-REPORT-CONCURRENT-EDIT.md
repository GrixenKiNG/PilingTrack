## Итог

Резюме для владельца (5 строк):

1. От перезаписи сменный отчёт защищён целым счётчиком `Report.version` и
   оптимистической проверкой в веб-пути (`report.repository.ts:122-154`), **но
   этот счётчик растёт только на веб-пути** (`report.repository.ts:141`).
2. Запись выработки с телефона (офлайн-очередь), сдача отчёта с телефона и
   автозакрытие смены планировщиком **`Report.version` не увеличивают** — защита
   слепа ко всему, что пришло по мобильному каналу, и к самому факту сдачи.
3. Правка отчёта формой (админ и оператор) работает по принципу «последняя запись
   побеждает»: форма шлёт устаревший снимок и `version`, взятые при открытии, а
   репозиторий **удаляет все строки, которых нет во входящем наборе**
   (`report.repository.ts:161-170`). Сваи/бурение/простой, добавленные другим
   каналом после открытия формы, **исчезают молча**.
4. Каналы блокируются РАЗНЫМИ замками, общего взаимоисключения нет: веб —
   advisory-замок `report:<tenant>:<user>:<site>:<date>`
   (`report-command.service.ts:114-117`), телефон — `FOR UPDATE` по строке смены
   (`shared.ts:63`).
5. Непаспортные строки удаляются без полного следа (`ReportAudit` хранит только
   diff и хэши), а автозакрытие смены планировщиком не пишет строку «сдано» вовсе.

- Всего находок: **14**. Критично — 4, важно — 5, мелочь — 5.
- Топ-5:
  1. (критично) `Report.version` не растёт при записи с телефона — проверка версии
     не видит мобильные правки (К1).
  2. (критично) `Report.version` не растёт при сдаче (телефон/планировщик) — форма,
     открытая до сдачи, сохраняется и после неё (К2).
  3. (критично) `reconcile` удаляет строки, отсутствующие во входящем наборе —
     тихая потеря выработки другого канала (К3).
  4. (критично) форма шлёт устаревшие `version` и `id` строк — последняя запись
     побеждает (К4).
  5. (важно) разные пространства блокировок у веб- и мобильного путей — нет
     взаимоисключения (В1).

## Механика версий и замков (как есть)

- Поле-счётчик: `Report.version Int @default(1)` (`prisma/schema.prisma:1952`),
  `updatedAt`/`submittedAt` — рядом (`:1970,1973`).
- Веб-путь (`/api/reports/upsert`, `/api/reports/admin-upsert`): один writer —
  `repo.save`. Под advisory-замком читает строку в той же транзакции, требует
  `expectedVersion` для существующего (`report.repository.ts:114-116`), сравнивает
  сохранённую версию с присланной (`:122-131`, иначе 409) и атомарно захватывает
  версию через `updateMany where version: existing.version` с `increment: 1`
  (`:138-154`, иначе 409).
- Мобильный путь (`logProduction`, `closeShift`): своя транзакция
  `withReadinessTenantTransaction`; сериализация — `SELECT … FOR UPDATE` по строке
  `Shift` (`shared.ts:63`). `Report.version` не читается и не меняется.
- Планировщик автозакрытия: своя транзакция; переводит отчёт `draft → submitted`
  `updateMany` и кладёт событие `ReportSubmitted` в outbox, версию не трогает
  (`scheduler.ts:215-249`).
- Уникальность и естественный ключ: `@@unique([tenantId, shiftId])`
  (`schema.prisma:1998`) плюс частичный индекс миграции на `(userId, siteId, date)`
  для `shiftId IS NULL` (`:1993-1997`). Поиск фолбэка ограничен `shiftId: null`
  (`report.repository.ts:311-312`).
