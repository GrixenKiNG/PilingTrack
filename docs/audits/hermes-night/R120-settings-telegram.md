# R120-settings-telegram — Настройки и Telegram: что видит человек при сбое

Область: экраны настроек (`/admin/settings`, `/admin/telegram`, раздел «Настройки» контура
техготовности — `to/readiness/settings/**`) и связка с Telegram. Экраны машиниста и ORION — вне
области. Только чтение кода; ни один существующий файл не изменён.

## Итог

- Найдено **13** находок: **0 критично, 7 важно, 6 мелочь**. Новых — 11, повтор прошлых отчётов — 2 (пункты 1 и 6).
- Сверка CX-H01..03 (сообщения о сбое загрузки в разделах настроек): **все три закрыты** и в текущем коде присутствуют (см. «Сверено с прошлым»).
- Топ-5:
  1. Кнопка «Тест» проверяет **первую включённую** конфигурацию, а не ту карточку, у которой нажата (repeat R33#19) — админ видит результат чужого бота.
  2. `chat_id` не проверяется никак (ни форматом, ни тестом при сохранении): опечатка сохраняется с `enabled=true`, и алерты молча не доходят.
  3. `testConnection` показывает **сырой ответ Telegram API** (`{"ok":false,"error_code":401,…}`) и `Not configured` вместо русского текста; у самой проверки нет таймаута — кнопка может «крутиться» бесконечно.
  4. На экране «Интеграции» сбой (в т.ч. 403 у роли без `telegram.manage`) навсегда оставляет карточку в «Проверяем подключение…» и KPI «…» (repeat R18#8).
  5. Ошибки сохранения/удаления/переключения Telegram-канала сведены к «Ошибка сохранения» / «Ошибка удаления»: текст сервера (400 с полями, 404, 409) теряется.

## Не проверено

- **Рантайм не воспроизводился**: сервер/БД/реальный Telegram не поднимались, коды 401/403/429 из
  Telegram и поведение тостов проверены только чтением кода. Точный текст ответа Telegram API
  (`{"ok":false,…}`) приведён по знанию API Bot, а не по зафиксированному ответу.
- **Доступ ролей к разделу «Настройки» контура техготовности** (что Диспетчер/Мастер/Инженер ОТ
  действительно видят вкладку «Интеграции») взят из прошлого отчёта `18-ui-vs-api-permissions.md:115`
  и карты прав; маршрут показа вкладок (`to-module`/`bootstrap-query`) построчно не разбирал.
- **`withCsrf`-ответ** (тело 403 при отсутствии CSRF-токена) не читал — не проверял, что покажет
  `handleTest`/`handleSave` в этом случае.
- Экраны машиниста (operator*) и ORION не открывал — вне области задачи.
- Кнопки/состояния `admin-dlq.tsx` (журнал недоставленных, куда попадают durable-алерты) — вне
  области «Настройки и Telegram», не смотрел.
