# AU167-S5-PERMISSION-NAMING-CONSISTENCY — Права: названия и состав по ролям

Версия репозитория: `baa647e6571c672abf72740343652299b9c8df5c` (ветка `hermes/q4-0926`).
Проверялось по `src/services/auth/authorization-service.ts` (только чтение) и по местам
вызова `can` / `assertCan` / `requirePageAbility` / `useAbility` во всём `src`.
Файлы приложения не изменялись.

## Итог

- Всего прав в матрице: **30** (тип `Ability`, `src/services/auth/authorization-service.ts:23-52`).
- Найдено **24** замечания: **7 важно**, **17 мелочь**, критичных нет.
- Два права не проверяются нигде (`media.upload`, `crews.legacy_manage`) — мёртвые.
- Две пары прав с одинаковым составом ролей (`reports.read_all` = `reports.read_cross_user`;
  `sites.manage` = `sites.assign_users` = `sites.manage_hierarchy`) — имя делит, состав не делит.
- Ряд имён не отражает состав: `system.read` (это «офисный» гейт), `maintenance.manage`
  (30 мест: ТО, ремонты, планы, шаблоны осмотра, топливо, моточасы), `users.documents.read_all`
  (это право на инструктажи и допуски к технике).
- Один и тот же предмет в двух системах назван и роздан по-разному: `inspection.perform` vs
  `readiness.inspection.manage`, `meter.record` vs `readiness.meter.manage`,
  `maintenance.manage` vs `readiness.maintenance.manage`.
- Тест-«снимок» матрицы (`tests/integration/authorization-boundaries.spec.ts`) проверяет только
  4 роли из 7 и 18 прав из 30 — роли MECHANIC/FOREMAN/SAFETY_ENGINEER не проверяются вообще.

Замечания по существу прав (кому выдано, что видит роль) помечены ГИПОТЕЗА — это вопрос к владельцу,
а не доказанный дефект.
