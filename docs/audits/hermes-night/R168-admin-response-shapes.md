# R168 — Строгие ответы списков: ошибка не превращается в пустоту

Задача: чтение административных hooks `reports/equipment/crews/sites` — проследить путь от ответа API к пустому экрану, отличить уже обработанный строгий контракт (HTTP-ошибка → баннер/ошибка) от «мягкого» разбора, где 200 с неожиданной формой, `null`-массив или неверное число/дата молча становятся пустотой. Только чтение, код не менялся.

## Итог

- Находок 31: **критично — 0**, **важно — 15**, **мелочь — 16**.
- Общий корень один: читающие hooks проверяют только `res.ok` (`loadJson` в `src/lib/api.ts:129-133` бросает на не-ok, но **тело не валидирует**). Ответ 200 с телом не той формы, `null`-массив или нестроковая дата проходят дальше и превращаются в `[]` через `|| []` / `Array.isArray(...) ? ... : []`. Итог: «данных нет» вместо «не удалось прочитать».
- Уже сделан строгим (повторять не нужно): HTTP-ветки всех четырёх списков — 401/403/5xx дают текст и «Повторить» (`use-reports-data.ts:263-288`; `use-crews-data.ts:133-137`; `use-sites-overview.ts:92,123-124`; `use-sites-data.ts:52-56`), а также `loadJson`/`LoadFailed` как контракт чтения.
- В репозитории **есть** образец строгой проверки формы: `admin-incidents.tsx:81` (`!Array.isArray(body.data)` → «неожиданный ответ») и `use-users-list.ts:37-47` (`isOperationalUser` + `parseUsersPage`). Четыре проверяемых раздела его не применяют.
- Топ-5:
  1. `use-reports-data.ts:253,346` — `Array.isArray(data.reports) ? data.reports : []`: 200 с неожиданным телом → пустой список без ошибки; экран `admin-reports.tsx:473` пишет «Отчёты не найдены».
  2. `use-sites-overview.ts:98` — `.crews ?? []` под `crewsRes.ok`: 200 с телом без `crews` даёт `crewCount = 0` и «Без бригад» на всех объектах (маскарад числа).
  3. `use-fleet.ts:25` + `admin-equipment.tsx:60` — `setSnapshot(await res.json())` без проверки; `snapshot.equipment ?? []` → «Нет установок» на живой базе.
  4. `admin-equipment.tsx:116` + `equipment-stats-bar.tsx:23` — `snapshot.totals.totalEquipment` без защиты: 200 без `totals` роняет весь экран.
  5. `admin-sites/index.tsx:155-172` — загрузка дерева объекта не проверяет `data.site`: при 200 без `site` эффект перезапускается бесконечно (шторм запросов).

### Уже сделано строго (не требует правок — чтобы не путать с находками)

- `src/lib/api.ts:104-133` — `LoadFailed`/`loadJson`: не-ok ответ чтения всегда исключение. Правильный контракт, но **тело** не проверяет — отсюда весь список выше.
- HTTP-ветки четырёх списков разделяют 401/403/5xx и дают «Повторить»: `use-reports-data.ts:263-288` (и `errorForbidden`), `use-crews-data.ts:133-137`, `use-sites-overview.ts:63-71,92,123-124`, `use-sites-data.ts:52-56`. Повторять эти находки не нужно.
- Образцы строгой проверки формы, которые можно переиспользовать: `admin-incidents.tsx:59-85` (`readErrorMessage` + `!Array.isArray(body.data)`), `use-users-list.ts:25-47` (`isOperationalUser` + `parseUsersPage`), `formatRuDate` (`src/lib/format.ts:56-60`), `shiftDurationHours` (`report-totals.ts:48-57`).
