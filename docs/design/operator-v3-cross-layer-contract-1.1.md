# Оператор v3 — уточнение межслойного договора 1.1

**Статус:** нормативный.  
**Приоритет:** дополняет и исправляет `operator-v3-cross-layer-contract.md`; при расхождении используется этот документ.

## 1. Обязательные поля снимка

Снимок `GET /api/operator/v3/workplace` дополнительно обязан содержать:

- `phases` — все семь фаз с номером, русским названием и состоянием;
- `primaryAction` — одно главное допустимое действие либо `null`;
- `persistentActions` — постоянные действия безопасности и справки.

Поле `actions` остаётся полным перечнем допустимых действий.

## 2. Дополнительные маршруты команд

- `POST /api/operator/v3/commands/create-inspection`;
- `POST /api/operator/v3/commands/save-inspection`;
- `POST /api/operator/v3/commands/complete-inspection`;
- `POST /api/operator/v3/commands/record-meter`;
- `POST /api/operator/v3/commands/upload-evidence`;
- `POST /api/operator/v3/commands/confirm-evidence`;
- `POST /api/operator/v3/commands/verify-repair`;
- `POST /api/operator/v3/commands/close-without-recipient`;
- `POST /api/operator/v3/commands/correct-event`.

## 3. Дополнительные ошибки

| Код | Код ответа | Действие интерфейса |
|---|---:|---|
| `EQUIPMENT_NOT_ASSIGNED` | 403 | показать порядок получения назначения |
| `REQUIRED_ACTION_INCOMPLETE` | 409 | открыть обязательное незавершённое действие |

Переходное сопоставление:

- `AUTH_REQUIRED` → `UNAUTHENTICATED`;
- `ABILITY_REQUIRED` → `FORBIDDEN`;
- `STATE_VERSION_CONFLICT` → `VERSION_CONFLICT`;
- `READINESS_BLOCKED` → `READINESS_DENIED`.

## 4. Семь обязательных сквозных сценариев

1. **Обычная смена:** вход → выбор → получение → проверка → рабочая зона → моточасы → разрешение → начало → работа → завершение → проверка после работ → отчёт → передача → принятие → закрытие.
2. **Замечания без запрета:** замечание → обязательное доказательство → разрешение с замечаниями → осознанный пуск → журнал и передача.
3. **Критический дефект до пуска:** признаки → фотография → запрет → устранение → независимая проверка → новая оценка → разрешение.
4. **Опасное событие во время работы:** событие → инструкция → безопасная остановка → блокировка производства → устранение → повторная оценка → возобновление.
5. **Потеря связи:** локальные записи → перезапуск → восстановление → однократный приём каждой записи → совпадение этапа с сервером.
6. **Противоречие двух устройств:** устаревшая команда отклоняется, обе версии сохраняются, молчаливой перезаписи нет.
7. **Передача без принимающего:** обычный оператор не видит полномочия, ответственный уведомлён, уполномоченный закрывает с причиной, оператор видит итог.

Для каждого действия сохраняются доказательства запроса, единственной записи, повторного чтения, обновления страницы и второго сеанса.
