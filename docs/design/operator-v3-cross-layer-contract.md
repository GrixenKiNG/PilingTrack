# Оператор v3 — единый межслойный договор

**Статус:** нормативный для реализации `/operator/v3`  
**Приоритет:** при расхождении этот документ имеет приоритет над серверным проектом, клиентским проектом и спецификацией интерфейса.

## 1. Чтение рабочего места

`GET /api/operator/v3/workplace`

Ответ содержит:

- `revision` — версия всего снимка;
- `serverTime` — время сервера;
- `operator` — идентификатор, имя, препятствия и замечания по допуску;
- `assignments` — доступные назначения;
- `equipment` — выбранная установка и объект;
- `shift` — смена, версия, фактические и плановые времена;
- `phase` — номер от 1 до 7, русское название, прогресс и пояснение;
- `workMode` — закрытое внутреннее значение рабочего режима;
- `readiness` — решение, актуальность, время расчёта, замечания, препятствия и доказательства;
- `actions` — только допустимые сервером действия;
- `inspections` — проверки до и после работы;
- `workZone` — состояние проверки рабочей зоны;
- `meter` — последние и текущие моточасы;
- `activeInterval` — текущий перерыв, простой или обслуживание;
- `production` — итог выработки и последние записи;
- `defects` — открытые дефекты;
- `incidents` — опасные события и требование остановки;
- `report` — отчёт текущей смены;
- `handover` — входящая и исходящая передача;
- `contacts` — диспетчер, механик и аварийный контакт;
- `sync` — состояние обмена, число локальных команд и срок ограниченного разрешения.

Баллы и проценты готовности в ответе v3 запрещены.

## 2. Закрытые наборы состояний

`workMode`:

| Техническое значение | Русское пользовательское название |
|---|---|
| `NOT_STARTED` | Работа не начата |
| `WORKING` | Производственная работа |
| `BREAK` | Перерыв |
| `DOWNTIME` | Простой |
| `MAINTENANCE` | Обслуживание |
| `STOP_REQUIRED` | Требуется безопасная остановка |
| `STOPPED` | Работа остановлена |
| `FINISHED` | Работы завершены |

`readiness.decision`:

| Техническое значение | Русское пользовательское название |
|---|---|
| `UNKNOWN` | Недостаточно данных |
| `ALLOWED` | Работа разрешена |
| `ALLOWED_WITH_NOTES` | Работа разрешена с замечаниями |
| `DENIED` | Работа запрещена |

`readiness.freshness`:

| Техническое значение | Русское пользовательское название |
|---|---|
| `COLLECTING` | Собираются данные |
| `CALCULATING` | Выполняется проверка готовности |
| `CURRENT` | Оценка актуальна |
| `STALE` | Данные устарели |
| `RECHECK_REQUIRED` | Требуется повторная проверка |
| `FAILED` | Не удалось проверить готовность |

`sync.state`:

| Техническое значение | Русское пользовательское название |
|---|---|
| `SYNCED` | Все данные переданы |
| `PENDING` | Есть данные для отправки |
| `SENDING` | Выполняется отправка данных |
| `OFFLINE` | Работа без связи |
| `CONFLICT` | Обнаружено противоречие данных |
| `INTERVENTION_REQUIRED` | Требуется вмешательство ответственного сотрудника |
| `AUTHORIZATION_EXPIRED` | Разрешение работы без связи истекло |

Пользователь видит только русские подписи из таблиц выше. Техническое значение не может использоваться как запасной пользовательский текст.

## 3. Договор действия

Каждый элемент `actions` содержит:

- `id` — устойчивый вид действия;
- `label` — русская подпись;
- `kind` — `COMMAND`, `SCREEN` или `NAVIGATION`;
- `method` и `route` для команды;
- `expectedVersion` для критического изменения;
- `offlinePolicy` — `FORBIDDEN`, `CAPTURE_ONLY` или `AUTHORIZED`;
- `requiresEvidence` — обязательные доказательства;
- `confirmation` — русский текст подтверждения при необходимости.

Клиент не конструирует адрес команды и не показывает действие, отсутствующее в `actions`.

## 4. Нормативные маршруты v3

Чтение:

- `GET /api/operator/v3/workplace`;
- `GET /api/operator/v3/events`;
- `GET /api/operator/v3/offline-authorization`.

Команды:

- `POST /api/operator/v3/commands/accept-assignment`;

- `POST /api/operator/v3/commands/complete-preparation`;

- `POST /api/operator/v3/commands/record-production`;
- `POST /api/operator/v3/commands/start-break`;
- `POST /api/operator/v3/commands/start-downtime`;
- `POST /api/operator/v3/commands/finish-interval`;
- `POST /api/operator/v3/commands/report-defect`;
- `POST /api/operator/v3/commands/report-incident`;
- `POST /api/operator/v3/commands/confirm-safe-stop`;
- `POST /api/operator/v3/commands/start-maintenance`;
- `POST /api/operator/v3/commands/finish-maintenance`;

Существующие маршруты могут вызываться внутри переходного адаптера, но клиент v3 использует только этот реестр.

## 5. Командная оболочка

Команда содержит `commandId`, `deviceId`, `deviceSequence`, `occurredAt`, `expectedVersion` и `payload`.

Заголовок `idempotency-key` равен `commandId`. Критическая команда без `expectedVersion` отклоняется.

Успешная квитанция едина и для первого выполнения, и для повтора:

```json
{
  "result": "COMPLETED",
  "replayed": false,
  "commandId": "...",
  "newVersion": 12,
  "workplace": {}
}
```

При повторе меняется только `replayed` на `true`; код ответа и деловой результат остаются прежними. Отдельного результата «уже выполнено» нет.

## 6. Ошибки

| Код | Код ответа | Действие интерфейса |
|---|---:|---|
| `UNAUTHENTICATED` | 401 | предложить войти снова |
| `FORBIDDEN` | 403 | показать русскую причину и убрать действие |
| `NOT_FOUND` | 404 | перечитать рабочее место |
| `ACTIVE_SHIFT_CONFLICT` | 409 | показать конфликтующую смену |
| `VERSION_CONFLICT` | 409 | перечитать снимок и не повторять автоматически |
| `IDEMPOTENCY_KEY_REUSED` | 409 | остановить очередь и запросить вмешательство |
| `COMMAND_IN_PROGRESS` | 409 | повторить тот же ключ после задержки |
| `SYNC_CONFLICT` | 409 | сохранить обе версии и показать состояние вмешательства |
| `ENTITY_CLOSED` | 409 | перечитать снимок |
| `INVALID_TRANSITION` | 409 | показать русскую причину и перечитать снимок |
| `EVIDENCE_STALE` | 422 | открыть требуемую повторную проверку |
| `ATTACHMENT_REQUIRED` | 422 | вернуть фокус к обязательному вложению |
| `VALIDATION_ERROR` | 422 | показать русские ошибки полей |
| `OFFLINE_AUTHORIZATION_REQUIRED` | 423 | запретить действие |
| `OFFLINE_AUTHORIZATION_EXPIRED` | 423 | потребовать безопасную остановку |
| `READINESS_DENIED` | 423 | показать препятствия |
| `INTERNAL_ERROR` | 500 | показать безопасное русское сообщение и номер обращения |

Внешнее сообщение всегда русское и не содержит путь файла, запрос базы или текст сторонней библиотеки.

## 7. Работа без связи и поздний факт

Без подписанного разрешения клиент не показывает производственное действие и не разрешает продолжать эксплуатацию.

Если оператор фиксирует уже произошедший факт после потери разрешения, запись сохраняется локально как `CAPTURE_ONLY`, помечается «Требует проверки» и не меняет этап, готовность или право продолжать работу. После отправки сервер создаёт позднее событие и ретроспективную оценку, но не переписывает исходное решение.

## 8. Общий выпускной шлюз

Обязательны семь браузерных сценариев под настоящими ролями:

1. назначение → получение → проверки → готовность → пуск;
2. разрешённая работа → производственная запись → повтор команды без дубля;
3. простой как интервал → завершение → отражение в отчёте;
4. дефект → серверная классификация → безопасная остановка;
5. ремонт другим полномочным сотрудником → проверка → новая оценка → возобновление;
6. завершение → проверка после работ → отчёт → передача → закрытие;
7. потеря связи → разрешённые локальные действия → восстановление → согласование без дублей и переписывания истории.

Для каждого делового действия доказательство включает запрос, одну запись, повторное чтение, сохранение после обновления страницы и результат во втором сеансе. Уведомление, локальный флаг, сборка или снимок одного экрана доказательством не являются.
