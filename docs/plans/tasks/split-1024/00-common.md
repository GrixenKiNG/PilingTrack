## Цель и граница

Разрезать четыре файла длиннее 500 строк по ответственности. **Поведение не меняется ни на одну строку.** Это перенос кода, а не переписывание: ни новых функций, ни «улучшений», ни переименований, ни смены порядка вызовов, ни новых зависимостей, ни новых проверок.

## Метод: чистый перенос по шагам

1. **Снять базовую линию ДО правок** и записать числа: `npx tsc --noEmit`, `npm run lint`, тесты файла и соседей (команды в задании), `npm run test:unit` (passed/skipped/failed), `npx playwright test --list` (число тестов). Перед `tsc` удалить `.next/dev/types`. Каждую команду запускать отдельно и записывать настоящий код возврата, без `| tail`.
2. **GitNexus до переноса:** `impact` на каждый переносимый символ (CLI: `node .gitnexus/run.cjs impact "<имя>" --direction upstream --repo .`). `UNKNOWN` — не «безопасно»: подтвердить поиском по тексту (`rg`) всех импортов, включая динамические. Индекс часто устаревает — при сомнении `node .gitnexus/run.cjs analyze --index-only`.
3. **Один шаг — один коммит.** Шаг = перенос одной группы символов в один новый файл. После каждого шага: `tsc`, `lint`, тест файла — зелёные, затем коммит. Сообщение коммита по-русски: что куда перенесено.
4. **Старые пути импорта остаются рабочими.** Всё, что импортировали снаружи из исходного файла, продолжает импортироваться оттуда же (переэкспорт `export {…} from './новый'` в исходном файле). Внешних импортёров в этом задании не переписывать.
5. **Что можно менять в строках кода:** только ключевое слово `export` (добавить, когда символ стал виден другому файлу) и строки `import`/`export … from`. Тела функций, JSX, комментарии, порядок объявлений внутри перенесённого блока — копировать дословно. Комментарии не «чистить» и не переводить.
6. **Что запрещено:** менять имена символов, сигнатуры, значения по умолчанию, порядок хуков и эффектов, зависимости `useEffect`/`useMemo`/`useCallback`, тексты на экране, классы CSS, `data-testid`, `aria-*`, ключи команд, запросы к базе (поля `select`/`where`, порядок `Promise.all`), логирование. Обёртки «для красоты», объединение дублирующихся кусков, вынос «общего» между файлами — нельзя. Дублирование не трогать, а назвать в отчёте.
7. **Если разрезать без правки логики нельзя** (кусок замыкает много локальных переменных, и для выноса пришлось бы вводить параметры) — **не резать**. Остановиться на достигнутом, записать в отчёт «не разрезано, потому что …» и предложить, что бы потребовалось. Цель «каждый файл ≤ 500 строк» вторична по отношению к «поведение не меняется».

## Доказательство чистого переноса (обязательно, воспроизводит Claude)

После каждого шага и в конце:

```bash
node docs/plans/tasks/split-1024/check-pure-move.cjs <хеш_базы> <путь/исходного/файла> <исходный_файл_после> <новый_файл_1> <новый_файл_2> ...
```

Скрипт сравнивает строки кода до и после как множество, игнорируя `import` и `export`. Код возврата 0 — чистый перенос. Код 1 — выводит, какие строки пропали и появились; каждая такая строка должна быть названа в отчёте и объяснена. В задании 1–3 допустимых различий нет вообще (чистый перенос верхнего уровня). В задании 4 допустимы только оговорённые в нём.

Дополнительно: `git diff --color-moved=dimmed-zebra <хеш_базы>` — приложить в отчёте число не перемещённых (не серых) добавленных строк.

## Проверки «готово» (все зелёные, как в `AGENTS.md` §6)

Каждую команду отдельно, с кодом возврата:

```bash
rm -rf .next/dev/types
npx tsc --noEmit
npm run lint
npm run test:unit
npx playwright test --list
npm run build
```

Критерии:
- `tsc` и `lint` — 0 ошибок и 0 предупреждений (базовая линия проекта — ноль предупреждений ESLint).
- `test:unit` — passed не меньше базовой линии, failed = 0, число skipped не выросло. Назвать три числа.
- `playwright --list` — число тестов не упало.
- `npm run build` — зелёный. Если он падает из-за отсутствия env/БД — так и написать, не придумывать env; тогда `tsc` + `lint` + unit остаются обязательными, а сборку проверит Claude.
- Тесты **не переписывать**, чтобы они проходили. Упавший тест значит, что перенос изменил поведение — откатить шаг. Новых тестовых файлов не заводить (`AGENTS.md` §5).
- `detect_changes` GitNexus (`node .gitnexus/run.cjs detect-changes --scope all --repo .`) перед каждым коммитом; `partial`/`truncated` — не чистая проверка, повторить.
